# 基盤ライブラリ

基盤ライブラリは、仕様をテストへ落とし込み、HTTP、ブラウザ、CLI、端末の境界を検証するための出発点です。新しいテストを書くときは、最初に「どの境界の振る舞いを証明したいか」を決めてください。テストランナーや実行環境で選ぶのではなく、確認したい契約で選ぶと、同じテストを不必要に重ねずに済みます。

## 最初に選ぶもの

HTTP の request と response を確認するなら [api](./api/)、ブラウザ上の利用者操作なら [e2e](./e2e/)、コンポーネント単位なら [ui](./ui/) または [component](./component/) から始めます。ウォレット接続を含む dApp の操作は [dapp](./dapp/) を使います。CLI の標準出力、終了コード、ファイル操作を確認したい場合は [cli-test](./cli-test/) が対象です。

仕様がまだテスト可能な単位へ分かれていない場合は [kaname](./kaname/) で観点を分割し、共通の fixture と実行モデルが必要なら [core](./core/) を参照してください。状態遷移の数学的な性質を検査する場合は [lean](./lean/) を使います。

## 読み進め方

選んだライブラリの概要で、再現する範囲と実サービスへ委ねる範囲を確認します。次に Quickstart のコードをそのままテストへ置き、期待値を一度通してください。その後、使い方で失敗経路と状態の扱いを追加します。API の引数、戻り値、例外の正確な契約はリファレンスで確認します。kiwa 全体の設計意図は [kiwa の考え方](../../guides/architecture) を参照してください。
