## What "measured" means now

Before this baseline, the numbers this file reported were misleading in two ways.

- `test:cov` for 21 packages had shrunk to a hand-written list of `.vitest-dist/src/<file>.js` includes. Anything not on the list was outside the fraction, so a package could show `100%` while a 466-line file (`packages/a11y/src/layer-harness.ts`, before this change) was never counted. `observability` measured 6 of 30 source files; `dapp` measured 7 of 25.
- 9 packages had no `test:cov` script at all. There were no numbers, so there was nothing to look at. `payment`, `desktop`, `mobile`, `security-devsecops` all fall into this group.

After this change, every package's `test:cov` matches `.vitest-dist/src/**/*.js`, excluding `.vitest-dist/tests/**`. The percentages are what the tests actually cover.

## Two ways to close a gap

Some gaps close by writing new tests; some close by removing dead code. Neither is a shortcut for the other.

The `ui` result is the extreme case. `ui/src` has ten files. Every test file drives one component; five components have no tests at all. Adding tests, not adjusting the include, closes it.

The `qwikcity` result is the other end: three source files, three test files, every branch reached, every function called. Adding another component to `qwikcity` without adding its tests would put it back on this list.

## Follow-ups

Each row below 100.00 becomes its own follow-up. The order below is coverage-ascending; the reason is that a 34% package takes many more tests to close than a 99.5% package, and the small deltas are easier to schedule against a busy week.

1. `ui` (34.15) — the largest single gap in the repository.
2. `cli`, `dapp`, `cache`, `e2e`, `perf-harness`, `queue` (<80%).
3. `orm`, `api`, `cli-test`, `realtime`, `agent`, `release-invariants`, `streaming`, `mcp`, `auth`, `quality-metrics`, `component`, `ai-llm`, `search` (80–97%).
4. Everything else 97–99% — small deltas per file; several packages need only a handful of tests.
5. `nuxt`, `solidjs`, `solidstart`, `sveltekit` — 100% line but not 100% branch or function. One test per uncovered arm.
