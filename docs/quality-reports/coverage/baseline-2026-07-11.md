# Coverage baseline — 2026-07-11

Real coverage numbers across every `packages/*` after three changes to how coverage is measured.

- The 21 packages whose `test:cov` narrowed the include to a hand-written list of specific files now use the glob `.vitest-dist/src/**/*.js`. What the file used to show was `100%` line coverage of a shrinking include list. `orm` slipped through the first pass; codex-review on the PR caught it and it was fixed in the same PR.
- The 9 packages that had no `test:cov` script (`agent`, `component`, `desktop`, `lean`, `mcp`, `mobile`, `payment`, `search`, `security-devsecops`) got one, matching the pattern the rest of the repo already used, and picked up `@vitest/coverage-v8` as a devDependency.
- Every `test:cov` now excludes `**/types.js`. Type-only `.ts` files emit an empty stub after `tsc`, which v8 reads as 0% lines / 0% functions — meaningless noise that pushed a real gap up the priority list.

## What "measured" means now

Before this baseline, the numbers this file reported were misleading in two ways.

- `test:cov` for 21 packages had shrunk to a hand-written list of `.vitest-dist/src/<file>.js` includes. Anything not on the list was outside the fraction, so a package could show `100%` while a 466-line file (`packages/a11y/src/layer-harness.ts`, before this change) was never counted. `observability` measured 6 of 30 source files; `dapp` measured 7 of 25. `orm` measured a wide slice through a `semantics/**/*.js` glob but still hand-listed the three root files, missing anything new added later at the root.
- 9 packages had no `test:cov` script at all. There were no numbers, so there was nothing to look at. `payment`, `desktop`, `mobile`, `security-devsecops` all fall into this group.

After this change, every package's `test:cov` matches `.vitest-dist/src/**/*.js`, excludes `.vitest-dist/tests/**` and excludes `**/types.js`. The percentages are what the tests actually cover.

## Two ways to close a gap

Some gaps close by writing new tests; some close by removing dead code. Neither is a shortcut for the other.

The `ui` result is the extreme case. `ui/src` has ten files. Every test file drives one component; five components have no tests at all. Adding tests, not adjusting the include, closes it.

The `qwikcity` result is the other end: three source files, three test files, every branch reached, every function called. Adding another component to `qwikcity` without adding its tests would put it back on this list.

## Follow-ups

Each row below the target becomes its own follow-up. The order below is coverage-ascending; the reason is that a 34% package takes many more tests to close than a 99.5% package, and the small deltas are easier to schedule against a busy week.

1. `ui` (34.27) — the largest single gap in the repository.
2. `cli`, `dapp`, `cache`, `e2e`, `perf-harness`, `queue` (<80%).
3. `orm`, `api`, `cli-test`, `agent`, `realtime`, `mcp`, `streaming`, `quality-metrics`, `auth`, `ai-llm`, `search`, `component` (80–97%).
4. Everything else 97–99% — small deltas per file; several packages need only a handful of tests.
5. The `100% line but < 100% branch or function` group — one test per uncovered arm each.
