# kiwa libraries

kiwa is a family of test libraries selected by application boundary. Each package has its own documentation, grounded in its README, exports, and tests. The guides do not document inferred APIs or fictional examples.

> [日本語](/libraries/)

## How to read this site

Each package is documented in four forms.

| Form | Purpose | Contents |
| --- | --- | --- |
| Overview | **Explanation** | Problem, adoption decision, design diagram, and related libraries |
| Quickstart | **Tutorial** | A runnable path from installation to the first successful test |
| Guide | **How-to** | Goal-oriented instructions such as connection, mock/live choice, and cleanup |
| Reference | **Reference** | Public API, types, and links to implementation or generated API documentation |

## Start with these libraries

The English entry point covers five packages that are the starting point for Web and dApp testing. Each link is the entry point for an individual package.

- [@kiwa-lab/core](./foundation/core/) — specification parsing and shared test environments.
- [@kiwa-lab/dapp](./foundation/dapp/) — dApp E2E with Anvil and Playwright.
- [@kiwa-lab/api](./foundation/api/) — mock, live, and hybrid testing for HTTP handlers.
- [@kiwa-lab/ui](./foundation/ui/) — component tests across UI frameworks.
- [@kiwa-lab/e2e](./foundation/e2e/) — browser E2E for general Web applications.

## Full catalogue

The Japanese catalogue documents all 74 kiwa libraries, including service, framework, AI, quality, language adapter, and native language packages. Use the [Japanese library catalogue](/libraries/) when you need a package outside this English entry point.
