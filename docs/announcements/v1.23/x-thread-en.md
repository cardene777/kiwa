1/ kiwa v1.23 is out — Payment 深化 milestone. After v1.14's payment webhook mock landed the 3 provider baseline (Stripe + Paddle + Lemon Squeezy signature verify + 4 fixture events), v1.23 layers **9 axes of advanced billing semantics** on top — dunning + retry + 3DS v2 + SCA + PSD2 mandate + subscription lifecycle + invoice lifecycle + VAT/GST/sales-tax + chargeback dispute. Provider-neutral state machines + strict transition guards. 100 new semantics tests.

2/ Why 9 axes? Real billing has 3 failure modes a webhook-only mock can't catch — state-machine drift (a subscription's real lifecycle is a 5-state graph with guards, not `active`/`canceled`), retry cadence (real dunning = 4 attempts over ~1 week + grace period), cross-provider fidelity (Stripe defers proration; Paddle charges immediately; Lemon Squeezy hosts checkout while Paddle inlines it). Each axis is a pure module under `@kiwa/payment/semantics/*` that emits a strongly typed `AxisStep` sequence.

3/ v1.23-1 `@kiwa/payment` v0.3 lands the 9 semantics files (`dunning.ts` / `retry.ts` / `three-ds.ts` / `sca.ts` / `psd2.ts` / `subscription-lifecycle.ts` / `invoice.ts` / `tax.ts` / `chargeback.ts`) + 3-provider neutral event routing table (34 neutral events × 3 provider = 102 entries) + fidelity harness `collectFidelityCoverage()` 3 × 9 = 27 rows for the release gate. 118/118 tests pass (base 18 + new 100).
