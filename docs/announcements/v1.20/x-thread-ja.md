1/ kiwa v1.20 released。 Streaming 深化 milestone です。 v1.19 (Framework 深化 横軸、 SolidJS Signal + Deno Fresh Islands + HonoJS Cloudflare Workers) の後、 v1.20 は event-driven backbone (Kafka (kafkajs-shaped producer / consumer / admin) + Redpanda (Kafka API 互換 broker + schema registry) + NATS (core pub/sub + JetStream + KV / Object store)) を 1 統一 mock として同時 land しました。 5 semantics (producer / consumer / exactly-once / DLQ / schema-registry) を 1 API surface で扱えます。

2/ `@kiwa-lab/streaming` v0.1.0 — 3 provider 統一 testing mock。 `createKafkaMock({ defaultPartitionCount })` は kafkajs-shaped の broker + producer + consumer + admin (deterministic djb2 key-hash partitioner、 `partitionAssigner: 'range' | 'round-robin'`)、 `createRedpandaMock({ schemaRegistry: true })` は Kafka API 互換 broker + colocated `SchemaRegistry`、 `createNatsMock()` は core pub/sub + `*` (single-token) / `>` (multi-token) subject routing + `nats.jetstream()` persistent stream + `js.kv` + `js.objectStore`。 104 behavior test。

3/ producer + consumer semantics — Kafka の `producer.send` は hash(key) mod partitionCount で routing、 全 write は `{ topic, partition, offset }` を record、 `sendBatch(records[])` は topic 越しに flatten。 `consumer.run({ eachMessage, autoCommit })` は assign された各 partition を walk、 `commitOffsets(offsets[])` で explicit commit、 `getCommittedOffset(groupId, topic, partition)` で durable marker 参照。 rebalance は member join/leave 時に deterministic に再計算。

4/ exactly-once semantics — `createTransactionalProducer(kafka, { transactionalId })` は multi-record atomic commit + abort、 `createIdempotentProducer(kafka, { producerId })` は per-partition sequence dedup (retry-safe)、 `createReadCommittedFilter(consumer)` は downstream read から uncommitted / aborted transaction を filter。 3 helper で exactly-once pillar を broker なしで完結。

5/ DLQ + schema registry — `createDeadLetterQueue({ maxRetries, backoffExponent })` は retry policy + poison message quarantine + inspect + reprocess flow を任意の consumer に重ねる。 `createSchemaRegistry()` は `registerAvro` / `registerProtobuf` / `registerJson` + 3 compatibility mode (`BACKWARD` / `FORWARD` / `FULL`) + schema evolution + fail-fast publish gating。 Kafka + Redpanda + NATS が同一 mock surface を共有。

6/ dogfood app 3 種 — `dogfood-kafka-event-pipeline` (Kafka producer + consumer group + exactly-once transactional producer + DLQ × fidelity harness 5 scenario) + `dogfood-redpanda-schema-registry` (Redpanda + 3 Avro schema (v1→v2 additive / v2→v3 breaking / v3→v4 default drop) × BACKWARD / FORWARD / FULL + fail-fast + Kafka API round-trip × 5 scenario) + `dogfood-nats-jetstream` (NATS core pub/sub + wildcards + JetStream persistent + KV + Object store × 5 scenario)。 全 3 app が 7 軸 release gate PASS。
