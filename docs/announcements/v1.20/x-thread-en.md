1/ kiwa v1.20 is out — Streaming 深化 milestone. After v1.19's Framework 深化 horizontal (SolidJS Signal + Deno Fresh Islands + HonoJS Cloudflare Workers), v1.20 lands **the event-driven backbone** every SaaS + data team already ships: Kafka (kafkajs-shaped producer / consumer / admin) + Redpanda (Kafka API 互換 + schema registry) + NATS (core pub/sub + JetStream + KV / Object store). One unified mock, five semantics, zero brokers.

2/ `@kiwa/streaming` v0.1.0 — 3 provider unified testing mock. `createKafkaMock({ defaultPartitionCount })` returns broker + producer + consumer + admin (kafkajs-shaped, deterministic djb2 key-hash partitioner, `partitionAssigner: 'range' | 'round-robin'`). `createRedpandaMock({ schemaRegistry: true })` layers a colocated `SchemaRegistry` on a Kafka-shaped broker. `createNatsMock()` gives core pub/sub with `*` (single-token) + `>` (multi-token) subject routing + `nats.jetstream()` persistent streams + `js.kv` + `js.objectStore`. 104 behavior tests.

3/ Producer + consumer semantics — Kafka producer.send routes on hash(key) mod partitionCount, records the partition + offset for every write, `sendBatch` flattens across topics. `consumer.run({ eachMessage, autoCommit })` walks each assigned partition, `commitOffsets(offsets[])` records explicit offsets, `getCommittedOffset(groupId, topic, partition)` surfaces the durable marker. Rebalance recomputes assignments deterministically when a member joins/leaves.

4/ Exactly-once semantics — `createTransactionalProducer(kafka, { transactionalId })` gives atomic multi-record commit + abort, `createIdempotentProducer(kafka, { producerId })` gives per-partition sequence dedup (retry-safe), `createReadCommittedFilter(consumer)` filters uncommitted / aborted transactions from downstream reads. Three helpers cover the exactly-once pillars end-to-end without a broker.

5/ DLQ + schema registry — `createDeadLetterQueue({ maxRetries, backoffExponent })` layers retry policy + poison message quarantine + inspect + reprocess flow on any consumer. `createSchemaRegistry()` gives `registerAvro` / `registerProtobuf` / `registerJson` + three compatibility modes (`BACKWARD` / `FORWARD` / `FULL`) + schema evolution + fail-fast publish gating. Kafka + Redpanda + NATS all share the same mock surface.

6/ dogfood apps — `dogfood-kafka-event-pipeline` (Kafka producer + consumer group + exactly-once transactional producer + DLQ fidelity harness, 5 scenario) + `dogfood-redpanda-schema-registry` (Redpanda + 3 Avro schemas × BACKWARD / FORWARD / FULL + fail-fast + Kafka API round-trip, 5 scenario) + `dogfood-nats-jetstream` (NATS core pub/sub + wildcards + JetStream + KV + Object store, 5 scenario). All 3 hit 7-axis release gate PASS.
