2/ The bug that recurred 4 times — `pnpm -F {name} build` (build filter) and `pnpm publish --filter {name}` (publish filter) are 2 separate halves inside `scripts.release`. A contributor adds a new package to one half. The release runs green — the build produces the artefact, the publish command exits 0 because the packages it was told about succeeded. The registry never receives the new package. v1.14 payment / v1.25 perf-harness / v1.27 quality-metrics / v1.28 realtime each hit it independently.

Walks `packages/*/package.json`, filters by `@kiwa/*` scope + `private: false`, checks each publishable package appears in **both** halves. Fail-fast **before** the milestone finisher. Landed 6 previously-missing packages (agent / ai-llm / component / mcp / search / streaming) in the same PR.

4/ v1.29-2 PostToolUse hook + `/issue-plan` checklist SSOT (Issue #987) — `hooks/post-tool-use/release-script-filter-guard.sh` proactive prevention. When Write / Edit tools touch `packages/*/package.json`, the hook scans the root `package.json` release script for the package's filter presence and warns (does not hard-deny) if either half is missing. `/issue-plan` skill body embeds a checklist for new package additions so the invariant is called out in Issue body before implementation.

5/ v1.29-3 release-invariants v0.1 + docs + publish (Issue #988) — new npm package `@kiwa/release-invariants` with 3 pure invariant checkers + a 1-shot aggregator. `checkReleaseScriptFilter` (both halves per package), `checkProvenanceFlagAbsence` (v1.14 removed `--provenance` from `pnpm publish`, must not creep back), `checkGateScriptPackageCoverage` (`test:mutation` must cover every publishable package), and `buildReleaseInvariantsSummary` (1-shot summary with `ok: boolean`). 8 behavior test PASS.

6/ Why a new package (not just internal tests)? The 3 invariants are pure functions with no kiwa-specific dependencies. Any pnpm monorepo can call `buildReleaseInvariantsSummary({ releaseScript, mutationGateScript, publishable })` from a test runner or a plain node script. The SSOT ships as an npm package so downstream users can adopt the pattern without copying kiwa's internal code.
