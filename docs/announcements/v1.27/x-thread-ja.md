2/ なぜ 4 tier? 単一 universal floor には 3 失敗 mode がある — threshold drift (Core layer package は SaaS mock より自然と高 kill-rate、 1 番号で両方を記述できない)、 kill-rate 計算式 drift (Stryker は 4 個の異なる score を表示、 team が silent に flattering な方を選ぶ)、 regression detection drift (baseline を毎 run 再構築すると regression が hide される)。 4 rule SSOT (`docs/concepts/mutation-testing-ssot.md`) = kill rate 計算式 = `killed / (killed + survived + timeout + error)` に pin + 4 tier floor は code の shape で pin (Core 80 / Framework 70 / SaaS 65 / Test type 60) + baseline JSON persist at `.mutation-baseline/{package}.json` + tier-aware 12-axis gate は package 越し・ milestone 越し・ fork 越しで mutation suite 比較可能にする最小 set。
