2/ Why 4 tiers? A single universal floor has 3 failure modes — threshold drift (`Core` packages naturally test higher than SaaS mocks, one number cannot describe both), kill-rate formula drift (Stryker exposes 4 different numbers, teams silently pick the one that flatters), regression detection drift (rebuilding the baseline hides regressions). The 4-rule SSOT (`docs/concepts/mutation-testing-ssot.md`) — kill-rate formula pinned at `killed / (killed + survived + timeout + error)` / 4-tier floor pinned by code shape (Core 80 / Framework 70 / SaaS 65 / Test type 60) / baseline JSON persisted at `.mutation-baseline/{package}.json` / tier-aware 12-axis gate — is the smallest set that makes kiwa mutation suites comparable across packages, milestones, and forks.
