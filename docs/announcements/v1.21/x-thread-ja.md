1/ kiwa v1.21 released。 Auth 深化 milestone です。 v1.20 (Streaming 深化、 Kafka + Redpanda + NATS を 1 統一 mock) の後、 v1.21 は 2026 の SaaS + 認証基盤 team が実運用で必要な **web-auth 主戦場 4 protocol (WebAuthn L3 (Chrome Virtual Authenticator) + Passkey (platform + roaming + sync fabric) + OAuth 2.1 (RFC 9700 + PKCE mandatory + DPoP sender-constrained token) + OIDC (id_token 検証 + Discovery + Dynamic Client Registration + Federation)) を 1 統一 mock として同時 land** しました。 `@kiwa-test/auth` v0.3 (6 provider adapter: NextAuth v5 + Lucia v3 + Better Auth + Clerk + Auth0 + Supabase Auth) の上に protocol 深化 layer を追加、 browser + Docker + 実 Keycloak / Auth0 tenant 不要で 4 protocol の testing 固有難所を SSOT 化。

2/ `@kiwa-test/auth` v0.4.0 — 4 protocol 統一 testing mock。 `createWebAuthnEnv()` は Chrome Virtual Authenticator 型 credential store + `navigator.credentials` mock (`create()` = attestation `none` / `packed` / `fido-u2f` × authenticator selection criteria `userVerification` / `residentKey` / `authenticatorAttachment` + `get()` = assertion + sign counter monotonicity + user-verified flag)、 `createPasskeyEnv()` は platform authenticator vs roaming authenticator boundary + `credProps.rk` + sync fabric mock (iCloud Keychain / Google Password Manager)。 WebAuthn 21 test + Passkey 33 test。

3/ OAuth 2.1 (RFC 9700) — `createOAuth21Env()` は mock Authorization Server + Resource Server 対。 PKCE S256 code_verifier / code_challenge (RFC 7636 で mandatory)、 DPoP proof JWT header + payload verify (RFC 9449 sender-constrained token、 `htu` / `htm` / `jti` / `iat` binding、 60s clock-skew 窓)、 refresh token rotation with reuse detection (leaked-token detection で refresh chain 全体 revoke cascade)、 revocation endpoint (RFC 7009、 derived access + refresh token に cascade)。 45 test。 `plain` code_challenge_method + `implicit` grant + `password` grant は `unsupported_response_type` で reject — RFC 9700 hard gate。

4/ OIDC — `createOIDCEnv()` は Discovery (`/.well-known/openid-configuration`) + JWKS endpoint + JWKS rotation (`kid` header + `jose` verify wrapper、 old token は grace 中 verify、 new token は rotated key で verify)、 Dynamic Client Registration (RFC 7591、 4 auth method (`none` / `client_secret_basic` / `client_secret_post` / `private_key_jwt`) + software_statement JWS)、 id_token 検証 (iss / aud / exp / iat / nonce / at_hash / c_hash + RS256 + ES256 signature)、 Federation trust chain (OIDC Federation 1.0 draft — trust anchor + intermediate + statement chain verify)。 35 test。

5/ dogfood app 3 種 — `dogfood-webauthn-passkey-app` (Next.js 15 App Router、 /register attestation + /signin assertion + /manage residentKey=required、 real driver は Chrome Virtual Authenticator (page.context().addVirtualAuthenticator)、 mock driver は `@kiwa-test/auth`、 4 pattern fidelity: userVerification × residentKey × authenticatorAttachment × sync fabric transition) + `dogfood-oauth21-provider` (Hono + Cloudflare Workers 自作 AS、 5 endpoint: /authorize + /token + /revoke + /userinfo + /.well-known/oauth-authorization-server、 real driver = oauth2-mock-server、 4 pattern fidelity: PKCE S256 + DPoP proof + refresh rotation + revocation cascade) + `dogfood-oidc-federation` (Nuxt 3 RP + Deno 自作 OP、 Discovery + DCR + JWKS rotation + id_token 検証 + Federation trust chain、 real driver = mock Keycloak-shaped OP、 4 pattern fidelity: Discovery + DCR + JWKS rotation + Federation)。 全 3 app が 7 軸 release gate PASS。

6/ testing 固有難所 SSOT (concept doc `auth-protocol-testing.md`) — 4 protocol × 4 testing 固有難所 SSOT。 Virtual Authenticator (Chrome CDP `WebAuthn.addVirtualAuthenticator` vs `@kiwa-test/auth` mock — 同じ credential store 形状、 同じ sign counter monotonicity 保証) / PKCE + DPoP (S256 base64url no-padding + SHA-256 digest / DPoP `htu` normalizer + `htm` case-insensitive + `jti` replay-detection window + `iat` clock-skew tolerance) / id_token 検証 (JOSE 互換 RS256 + ES256 verify + full-claim verify with clock skew + `at_hash` / `c_hash` は `alg` から hash-algo 導出) / Discovery + Federation (well-known cache-control respect + JWKS rotation with kid rollover + Federation statement chain intermediate substitution attack detection)。
