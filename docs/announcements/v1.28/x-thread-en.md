2/ Why 8 axes? Wrapping WebRTC / WebTransport / HTTP/3 in one "realtime" abstraction hides 3 protocol-specific shapes — WebRTC's 4-step SDP offer/answer + ICE trickle, WebTransport's HTTP/3 CONNECT + uni/bi stream flag, HTTP/3's `PUSH_PROMISE` server-initiated frame gated by `SETTINGS_ENABLE_PUSH`. The 8-axis SSOT (`docs/concepts/webrtc-webtransport-testing.md`) names the shape each protocol enforces so a fidelity regression on `webrtc-data-channel` reliable mode surfaces as a single cell change on the 24-row grid — not a percentage that could shift for any of 24 reasons.
