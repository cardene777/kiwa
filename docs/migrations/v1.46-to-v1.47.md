# Migration guide — v1.46 → v1.47

v1.47 is **additive** — existing APIs stay。 v1.47 adds **security-devsecops v0.2 adapter 統合** (実 CLI 呼出隠蔽 + skill 4 種 adapter 経由化 Phase 2 完成) 単軸 milestone。

## 4 things v1.47 adds

- `@kiwa/security-devsecops` v0.2 — 6 axis (SAST + SCA + Secret + IaC + DAST + Container) の **adapter interface** (SastAdapter / ScaAdapter / SecretAdapter / IacAdapter / DastAdapter / ContainerAdapter) 追加、 6 axis × mock/real adapter pair (12 adapter 実装)、 backward compat 維持で v0.1 semantics 直接使用継続。
- **real adapter env-gate** — `KIWA_SECURITY_MODE=real` + `KIWA_SEMGREP_URL` / `KIWA_TRIVY_URL` / `KIWA_GITLEAKS_URL` / `KIWA_TFSEC_URL` / `KIWA_ZAP_URL` / `KIWA_GRYPE_URL` の 7 env で real 呼出 opt-in、 default mock で常時実行可能。
- **fidelity harness** — `examples/dogfood-security-devsecops-adapter-app/` に mock vs real の 完了状態 + event count 一致検証 harness 提供、 v0.3 で real adapter が実 CLI spawn 実装に置換されても継続使用可能。
- **skill 4 種 × adapter 経由経路 SSOT 公式化** — `docs/concepts/security-devsecops-library-integration.md` § Phase 2 完成 SSOT で security-audit / supply-chain / specialty / threat-model の 4 skill が adapter 経由経路を採用する map + code sample。 **25 milestone 連続 snippet validation streak** (v1.23-v1.47) 達成。

## What breaks (nothing)

- v0.1 直接 semantics 使用は v0.2 でも継続可能、 adapter は新規 optional path
- perf-harness v0.3 / quality-metrics v0.4 (v1.46 追加分) — untouched
- 他 39 package (v1.46 時点) — untouched

## Upgrade steps

```bash
pnpm add -D @kiwa/security-devsecops@^0.2
```

adapter 経路の opt-in は 3 pattern。

### Pattern 1 — mock adapter (default、 常時 test 可能)

```ts
import {
  sastMockAdapter,
  scaMockAdapter,
  type AdapterInvocation,
} from '@kiwa/security-devsecops';

const inv: AdapterInvocation = { scanId: '1', target: '/repo', mode: 'mock' };
const sastResult = await sastMockAdapter.scan(inv);
const scaResult = await scaMockAdapter.scan(inv);
```

### Pattern 2 — real adapter (env-gate opt-in)

```ts
import { sastRealAdapter, type AdapterInvocation } from '@kiwa/security-devsecops';

// env 未設定時は throw、 設定時のみ pass
process.env.KIWA_SECURITY_MODE = 'real';
process.env.KIWA_SEMGREP_URL = 'http://semgrep-endpoint';

const inv: AdapterInvocation = { scanId: '1', target: '/repo', mode: 'real' };
const result = await sastRealAdapter.scan(inv);
```

### Pattern 3 — v0.1 semantics 継続 (backward compat)

```ts
// v0.1 経路は変更なし、 semantics 直接使用可能
import { startSastScan, detectSastFinding, completeSastScan } from '@kiwa/security-devsecops';

const session = startSastScan({ scanId: '1', target: '/repo' });
detectSastFinding(session, { ruleId: 'x', filePath: 'src/x.ts', line: 1, severity: 'high', message: 'x' });
completeSastScan(session);
```

## adapter interface と semantics の使い分け

- **adapter 経由** = skill / dev-flow / dogfood app で 6 axis workflow を横断的に扱う、 mock/real 切替が env で可能
- **semantics 直接** = 個別 finding を細かく driving したい場合、 custom logic を挟みたい場合
