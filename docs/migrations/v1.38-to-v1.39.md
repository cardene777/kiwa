Use it in your own test.

```ts
import { describe, expect, it } from 'vitest';
import {
  completeHandshake,
  evaluatePosture,
  startMtlsSession,
  startZeroTrustSession,
} from '@kiwa-test/security';

describe('my service — security posture regression', () => {
  it('completes a TLS 1.3 handshake with a named cipher', () => {
    const s = startMtlsSession({ target: 'istio', sessionId: 's' });
    const step = completeHandshake(s, {
      peerCn: 'api.example.com',
      cipherSuite: 'TLS_AES_256_GCM_SHA384',
      tlsVersion: '1.3',
    });
    expect(step.neutralEvent).toBe('mtls.handshake_completed');
  });

  it('flags a device without EDR as failed posture', () => {
    const s = startZeroTrustSession({ target: 'opa', sessionId: 's' });
    const step = evaluatePosture(s, {
      osUpToDate: true,
      diskEncrypted: true,
      edrRunning: false,
      mdmEnrolled: true,
    });
    expect(step.metadata.passed).toBe(false);
  });
});
```

### `SECURITY_ADV_AXIS_TO_EVENTS` + `collectAdvFidelityCoverage` — 4 provider × 8 axis advanced grid

The advanced fidelity harness describes which provider covers which advanced axis and what neutral event + provider dialect each axis emits.

```ts
import {
  collectAdvFidelityCoverage,
  SECURITY_ADV_AXIS_TO_EVENTS,
} from '@kiwa-test/security';

const coverage = collectAdvFidelityCoverage();
console.log(coverage.rows.length); // 32 (4 provider × 8 axis)

const istioMtls = coverage.rows.find(
  (r) => r.provider === 'istio' && r.axis === 'mtls',
);
console.log(istioMtls?.neutralEvents);
// [ 'mtls.handshake_completed', 'mtls.cert_pinned', 'mtls.ocsp_verified', 'mtls.ct_log_checked' ]
```

Every one of the 32 rows names a provider + axis pair plus the list of neutral events + the per-provider dialect. Tests iterating the grid pick the pair they cover and run the fidelity check on it — the harness returns a per-scenario accuracy score that ties the real driver output back to the mock output.

The v0.2 advanced grid is orthogonal to the v0.1 base grid — the v0.1 `SECURITY_FIDELITY_GRID` covers 4 provider (`helmet` / `express-rate-limit` / `casbin` / `coraza`) × 8 base axis = 32 combinations, and the v0.2 `SECURITY_ADV_FIDELITY_GRID` covers 4 provider (`istio` / `opa` / `siem-splunk` / `vault`) × 8 advanced axis = 32 combinations. Total = 64 combination coverage across the two grids.

### `KIWA_MODE=real` — env-gated real driver run for the advanced grid

The mock path stays the default. When `KIWA_MODE=real` is set, the harness assertions also try to run against the real driver, gated by the required env for that provider.

- **istio** → `KIWA_MODE` + `KIWA_ISTIO_URL` (Istio pilot / envoy sidecar; `KIWA_ISTIO_TOKEN` optional)
- **opa** → `KIWA_MODE` + `KIWA_OPA_URL` (OPA data API; `KIWA_OPA_TOKEN` optional)
- **siem-splunk** → `KIWA_MODE` + `KIWA_SPLUNK_HEC_URL` + `KIWA_SPLUNK_HEC_TOKEN` (Splunk HEC ingest endpoint)
- **vault** → `KIWA_MODE` + `KIWA_VAULT_URL` + `KIWA_VAULT_TOKEN` (HashiCorp Vault KV / transit engines)

Absent env means silently fall back to mock mode. This is the same env-gate contract the v1.31 streaming real-driver concept doc, the v1.32 database real-driver concept doc, the v1.33 payment real-driver concept doc, the v1.34 frontend real-driver concept doc, the v1.35 observability real-driver concept doc, the v1.36 search real-driver concept doc, the v1.37 security v0.1 base real-driver concept doc, and the v1.38 ai-llm real-driver concept doc all use — v1.39 layers the advanced provider set (Istio + OPA + Splunk + Vault) on the same pattern.

## No release-gate axis change

v1.39 does not add a 14th release-gate axis. The 8 v0.2 security axes gate the security package's own tests (via `pnpm --filter @kiwa-test/security test`) but do not surface as a per-package `quality-metrics` axis. The reason is that the advanced fidelity harness is provider-shape-specific — a package that does not export to Istio / OPA / Splunk / Vault has nothing to assert on. When a future milestone adds a `security.advanced.fidelity` axis that describes "which advanced security providers this package's tests hit," it will slot into the 13-axis release gate as the 14th; v1.39 keeps things simple.
