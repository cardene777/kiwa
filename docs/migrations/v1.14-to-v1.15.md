# Migration guide — v1.14 → v1.15

v1.15 is **additive** — every `@kiwa-test/*` package that existed in v1.14 keeps its public API. Existing tests keep passing.

The 3 things v1.15 adds are:

- `@kiwa-test/ai-llm` v0.2 (existing package, new multimodal input mock — image + audio — across all 4 SDKs, plus Whisper transcription mock)
- `@kiwa-test/mcp` v0.1 (new package, Model Context Protocol server + client mock, JSON-RPC 2.0 handshake + tool registration + 5 fixture tools)
- `@kiwa-test/agent` v0.1 (new package, LangGraph-style state machine + OpenAI Assistants v2 orchestration mock)

Plus 2 new dogfood apps (`dogfood-multimodal-chat` + `dogfood-mcp-tool-agent`) that measure the mocks against real Anthropic + real MCP endpoints.

## What breaks (nothing)

Nothing. The v1.15 changes are pure additions.

- `@kiwa-test/ai-llm` v0.1 API (`createAnthropicMock` / `createOpenAIMock` / `createVercelAiMock` / `createLangchainMock` / `runFidelityCheck` / `buildAiLlmReport`) — unchanged. Adding `parts` / `content: MessagePart[]` is opt-in; text-only tests do not need to change.
- `@kiwa-test/quality-metrics` — unchanged. 11-axis release gate still triggers on `@kiwa-test/ai-*` provider prefix. Both `@kiwa-test/mcp` and `@kiwa-test/agent` roll into the 7-axis common branch (they are not token-priced generative surfaces on their own).
- `evaluateReleaseGate` — same 11-axis contract as v1.14, same `isAiLlmProvider` prefix dispatch.
- Everything else (auth / queue / cache / realtime / payment / search / observability / polyglot Rust + Go / dApp / framework adapters / docs skills) — untouched.

## What's new (opt in)

### `@kiwa-test/ai-llm` v0.2 — multimodal (image + audio) + Whisper

Bump the existing dependency:

```bash
pnpm add -D @kiwa-test/ai-llm@^0.2
```

Add image content to any of the 4 SDK mocks — the `content: MessagePart[]` array is a superset of the v0.1 `content: string` shape.

```ts
import { createAnthropicMock } from '@kiwa-test/ai-llm';

const client = createAnthropicMock({
  imageTokenCost: 1500,
  responses: {
    'What is in this image?': { content: 'a maple leaf' },
  },
});

const res = await client.messages.create({
  model: 'claude-3-5-sonnet',
  max_tokens: 200,
  messages: [
    {
      role: 'user',
      content: [
        {
          type: 'image',
          source: {
            type: 'base64',
            media_type: 'image/jpeg',
            data: '...base64...',
          },
        },
        { type: 'text', text: 'What is in this image?' },
      ],
    },
  ],
});
```

New config knobs (all optional; safe defaults keep v0.1 tests passing).

- `imageTokenCost` — default `1500`; multiplies by 0.5 / 0.8 / 1.0 for detail = `low` / `auto` / `high`
- `audioTokenCost` — default `500`; scales per 30 s of audio duration
- `transcriptions` — Whisper reply dict, keyed via `toTranscriptionKey(source)`
- `defaultTranscription` — Whisper fallback when the dict misses

The mock's `_kiwa.costUsd` accounting picks up multimodal tokens automatically, so release-gate assertions do not need a schema change.

### `@kiwa-test/mcp` v0.1 — Model Context Protocol server + client mock

New dependency:

```bash
pnpm add -D @kiwa-test/mcp
```

Boot an in-process server, register tools, drive a client through the JSON-RPC 2.0 handshake + tool call chain.

```ts
import {
  connectClientToServer,
  McpServer,
  registerAllFixtureTools,
} from '@kiwa-test/mcp';

const server = new McpServer({ name: 'demo', version: '1.0.0' });
registerAllFixtureTools(server);

const { client } = await connectClientToServer(server);
const tools = await client.listTools();
// [{ name: 'echo' }, { name: 'calc' }, { name: 'weather' }, { name: 'search' }, { name: 'db-query' }]

const result = await client.callTool('calc', { op: 'add', a: 2, b: 3 });
// result.content = [{ type: 'text', text: '5' }]
```

v0.1 covers the 4 ops needed for tool-use loops (`initialize` / `notifications/initialized` / `tools/list` / `tools/call`) and the 8 error codes MCP-aware clients care about. Resources / prompts / sampling / logging land in v0.2.

### `@kiwa-test/agent` v0.1 — LangGraph + Assistants v2

New dependency:

```bash
pnpm add -D @kiwa-test/agent
```

LangGraph-style state machine.

```ts
import { END, START, StateGraph } from '@kiwa-test/agent';

const graph = new StateGraph<{ reply: string | null }>()
  .addNode('answer', () => ({ reply: 'hi' }))
  .addEdge(START, 'answer')
  .addEdge('answer', END)
  .compile();

const final = await graph.invoke({ reply: null });
// final.reply === 'hi'
```

OpenAI Assistants v2 client.

```ts
import { AssistantsClient, toolCall } from '@kiwa-test/agent';

const client = new AssistantsClient({ idSeed: 'demo' });
const assistant = client.createAssistant({
  name: 'echo',
  instructions: 'echo user text',
  handler: async () => ({ kind: 'message', content: 'echoed' }),
});
const thread = client.createThread({ messages: [{ role: 'user', content: 'hi' }] });
const run = client.createRun({ threadId: thread.id, assistantId: assistant.id });
const step = await client.poll(run.id);
// step.status === 'completed'
```

Compile validation is fail-fast (6 checks) and runs on `.compile()`, so bad graph shapes surface before execution.

## Sanity command sequence

```bash
# 1. install / upgrade
pnpm add -D @kiwa-test/ai-llm@^0.2 @kiwa-test/mcp @kiwa-test/agent

# 2. rerun existing tests — nothing should break
pnpm test

# 3. adopt any new module you want. Nothing is forced.
```

## When to reach for each new package

- **`@kiwa-test/ai-llm` v0.2 multimodal** — the app takes images or audio as user input. Vision OCR, screenshot triage, receipt parsing, Whisper transcription. The 4 SDKs share the same `MessagePart[]` shape.
- **`@kiwa-test/mcp`** — the app exposes tools through a process-boundary protocol so multiple client-side agents can reuse them. Language-server-like servers, database gateways, hardware bridges.
- **`@kiwa-test/agent`** — the app orchestrates multi-turn tool loops or stateful conversations. LangGraph for declarative dataflow; Assistants v2 for stateful multi-turn.
