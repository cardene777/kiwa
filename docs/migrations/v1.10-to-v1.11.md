# v1.10 → v1.11 migration

## Scope

v1.11 (issue [#680](https://github.com/cardene777/kiwa/issues/680)) shifts kiwa's focus from "add more providers" to "measure release quality with numbers":

- `@kiwa-test/quality-metrics` v0.1 — unified 5-axis harness (coverage / test count / fidelity / perf p95 / mutation kill)
- Dogfood app pattern — `examples/dogfood-{supabase-saas,rabbitmq-worker,foundry}-app/` for real-vs-mock behavioural fidelity measurement
- Docs augmentation — `docs/tutorials/` + `docs/migrations/` + `docs/api/` + a `/docs-generate` skill
- GitHub Pages publication of the generated docs site (v1.11-6)

**No breaking changes** — every v1.10 test file compiles + passes unchanged.

## Adopt @kiwa-test/quality-metrics (recommended)

Add the harness to your test suite so each provider's `pnpm test:cov` also emits a report:

```bash
pnpm add -D @kiwa-test/quality-metrics
```

Then in a small `scripts/emit-quality-report.ts`:

```ts
import { writeFileSync } from 'node:fs';
import {
  assembleReport,
  coverageFromV8Summary,
  emitJson,
  emitMarkdown,
  evaluateReleaseGate,
  fidelityFromMethodCounts,
  mutationFromCounts,
  perfFromSamples,
  testCountFromCategories,
} from '@kiwa-test/quality-metrics';

const report = assembleReport({
  provider: '@kiwa-test/auth',
  version: '0.3.0',
  coverage: coverageFromV8Summary(await import('../coverage/coverage-summary.json').then((m) => m.total)),
  testCount: testCountFromCategories({ behavior: 236, integration: 8, e2e: 0 }),
  fidelity: fidelityFromMethodCounts({ mockCoveredMethods: 42, realTotalMethods: 60 }),
  perf: perfFromSamples([]),
  mutation: mutationFromCounts({ mutations: 0, killed: 0 }),
});

const verdict = evaluateReleaseGate(report);
writeFileSync('docs/quality-reports/auth-0.3.0.md', emitMarkdown({ report, verdict }));
writeFileSync('docs/quality-reports/auth-0.3.0.json', emitJson(report));
```

Wire it after `pnpm test:cov` in your provider's `package.json`.

## Follow the dogfood app pattern (optional)

If you maintain a kiwa provider, mirror the v1.11-2 / v1.11-3 / v1.11-4 layout under `examples/dogfood-<provider>-app/`:

```
examples/dogfood-<provider>-app/
├── src/
│   ├── adapters/
│   │   ├── interface.ts    (provider-neutral trace-recording shape)
│   │   ├── mock.ts         (kiwa mock adapter)
│   │   └── real.ts         (real provider with graceful skip)
│   └── flows/
│       ├── <domain>-flows.ts   (7 flows exercising the provider)
│       └── fidelity.ts     (trace diff + quality-metrics call)
└── tests/
    ├── e2e-mock-mode.test.ts     (8 tests)
    ├── fidelity-report.test.ts  (3 tests)
    └── emit-fidelity-report.test.ts  (1 test writing quality-report/)
```

Both adapters export the same interface + record trace events. The fidelity harness diffs the traces and emits `quality-report/fidelity-latest.md` + `.json`. The pattern lands cleanly in both TypeScript (v1.11-2, v1.11-3) and Rust (v1.11-4).

## Consume the docs site (optional)

v1.11-6 publishes the full docs at `https://cardene777.github.io/kiwa/`. To rebuild locally:

```bash
# after v1.11-5 + v1.11-6 land
pnpm docs:build
open docs/.vitepress/dist/index.html
```

Or run the reusable local skill:

```bash
claude /docs-generate            # regenerate typedoc + cargo doc + forge doc
claude /docs-publish             # rebuild + push to gh-pages branch (v1.11-6)
```
