# Migration guide — v1.17 → v1.18

v1.18 is **additive** — every `@kiwa-lab/*` package and `kiwa-test-rs` public API that existed in v1.17 keeps its surface. Existing tests keep passing.

The 4 things v1.18 adds are.

- `kiwa-test-rs` v0.5 (Blockchain 深化 — `kiwa::contract::reth` new module + `kiwa::contract::foundry::invariant` submodule + `kiwa::contract::alloy::helpers` submodule)
- 3 dogfood apps (`dogfood-reth-node-test` + `dogfood-foundry-invariant-fuzz` + `dogfood-dapp-e2e-reorg`) that measure the mock against real Reth / Foundry / anvil-fork surfaces
- 3 tutorials, 1 concept doc, 1 migration guide (this file) covering the 4 axes end-to-end (chain state / EL client integration / fuzz shrinker / reorg semantics)
- `@kiwa-lab/dapp` reorg helpers — `snapshotChain(client)` + `revertChain(client, snapshotId)` — reused by the reorg dogfood app and the Playwright tutorial

## What breaks (nothing)

Nothing. The v1.18 changes are pure additions.

- `kiwa-test-rs` v0.4 exports (`kiwa::contract::foundry::Anvil` + `kiwa::contract::foundry::FoundryEnv` + `kiwa::contract::alloy::SolAbi` + `kiwa::contract::alloy::Signer` + `kiwa::contract::alloy::keccak256`) — unchanged.
- `kiwa-test-rs` v0.4 file layout — `foundry.rs` moves to `foundry/mod.rs` and `alloy.rs` moves to `alloy/mod.rs`, but every public re-export path stays the same. Callers using `use kiwa::contract::foundry::FoundryEnv;` do not touch a line.
- `@kiwa-lab/dapp` v0.x (wallet injection + `dappE2eTest` fixture) — unchanged. The v1.18 reorg helpers ride the same package version and are named exports on the existing entry point.
- `@kiwa-lab/observability` v2.0 (dashboard + alert + trace + correlation) + `@kiwa-lab/component` v0.1 + `@kiwa-lab/realtime` / `@kiwa-lab/ai-llm` / `@kiwa-lab/mcp` / `@kiwa-lab/agent` / `@kiwa-lab/perf-harness` / `@kiwa-lab/quality-metrics` — unchanged.
- `evaluateReleaseGate` — same 11-axis contract as v1.17. Blockchain surfaces (`kiwa-test-rs` + `dogfood-*-reorg`) roll into the common 7-axis branch (coverage / test count / fidelity / perf p95 / mutation). The AI-LLM 4 axes (cost / latency / token / accuracy) do not apply to chain-state / EL client surfaces — there is no token pricing to measure.
- Everything else (auth / queue / cache / realtime / payment / search / polyglot Go / dApp framework adapters / docs skills) — untouched.

## What's new (opt in)

### `kiwa-test-rs` v0.5 — 3 new axes over the v0.4 contract layer

The v0.4 `kiwa::contract::foundry` + `kiwa::contract::alloy` modules stay the same. v0.5 adds three depths on top.

#### `kiwa::contract::reth` — a second Rust dev chain

Feature `contract-reth` (default OFF). Spawns `reth node --dev` as a subprocess, wraps it in a `Drop`-based handle, and ships a JSON-RPC `debug_setHead` reorg driver + 7-row anvil ↔ reth fidelity matrix.

```rust
use std::time::Duration;
use kiwa::contract::reth::{RethBinary, RethNode, reth_reorg, fidelity_matrix};

let bin = RethBinary::detect();
if !bin.available {
    return; // graceful skip — same shape as FoundryEnv::detect
}

let node = RethNode::spawn_dev(8551)?;
node.wait_ready(Duration::from_secs(3))?;

let reorg = reth_reorg(node.endpoint(), 3)?;
assert!(reorg.rpc_ok);

let matrix = fidelity_matrix();
// 7 FidelityCase rows: 4 expected_agreement=true + 3 divergence-by-design
```

`RethNode` terminates the child process on `Drop` so a panic in downstream assertions cannot leak a running reth process. The reorg helper is a hand-rolled HTTP client that does not pull `reqwest` into the runtime dep tree.

#### `kiwa::contract::foundry::invariant` — 10 000-run invariant + fuzz driver

v0.4's `foundry.rs` becomes `foundry/mod.rs` + `foundry/invariant.rs`. Same `FoundryEnv` contract, same `Anvil` handle — the new submodule adds three entries.

- `invariant_run(env, project_root, opts)` — renders `forge test --match-contract Invariant*`, forwards `runs` + `seed` through `FOUNDRY_INVARIANT_RUNS` / `FOUNDRY_INVARIANT_SEED` env vars (deterministic across parallel invocations, no `foundry.toml` mutation), and parses the `[FAIL. Reason: …]` shrink summary Foundry emits when a counter-example lands.
- `parse_invariant_shrink(stdout)` — pure text parser exposed so tests can exercise the shrink shape without spawning `forge`.
- `forge_script(env, project_root, script_path, rpc_url, broadcast, extra_args)` — thin wrapper around `forge script <path> --rpc-url <rpc>` with `--broadcast` opt-in. Default is dry-run so integration tests simulate deployments without touching a chain.

```rust
use kiwa::contract::foundry::{FoundryEnv, InvariantOutcome, invariant::{InvariantOptions, invariant_run}};

let env = FoundryEnv::detect();
let report = invariant_run(
    &env,
    &project_root,
    &InvariantOptions {
        runs: 10_000,
        seed: Some(0xdead_beef),
        match_contract: Some("InvariantERC20".to_string()),
        ..Default::default()
    },
)?;

if report.skipped {
    return; // forge not on PATH
}
assert_eq!(report.outcome, InvariantOutcome::Passed);
```

#### `kiwa::contract::alloy::helpers` — 3 ergonomic wrappers

v0.4's `alloy.rs` becomes `alloy/mod.rs` + `alloy/helpers.rs`. Same `SolAbi` + `Signer` + `keccak256` re-exports — the new submodule adds three primitives that render production-shaped payloads.

- `build_eip712_typed_data(domain, primary_type, fields)` — EIP-712 v4 (`domainSeparator + typeHash + hashStruct`) digest + `eth_signTypedData_v4`-compatible JSON envelope. Only primitive scalar types (`address` / `uint*` / `bytes*` / `string` / `bytes` / `bool`) in v0.5; nested-struct support lands in v0.6.
- `encode_multicall3(calls: &[Multicall3Call])` — canonical `aggregate3((address,bool,bytes)[])` calldata batch encoder for the `0xcA11bde05977b3631167028862bE2a173976CA11` Multicall3 contract.
- `encode_permit2_witness_transfer(permit)` — Uniswap Permit2 `permitWitnessTransferFrom` calldata + EIP-712 witness digest so signers can drop a signature in without touching the ABI wire format.

All three helpers piggyback on the v0.4 `keccak256` implementation. No `sha3` / `alloy-primitives` dependency added.

### `@kiwa-lab/dapp` — reorg helpers

Two named exports on the existing entry point, no version bump for the fixture surface.

```ts
import { snapshotChain, revertChain } from '@kiwa-lab/dapp';
import { createPublicClient, http } from 'viem';

const client = createPublicClient({ transport: http('http://127.0.0.1:8557') });
const snapshotId = await snapshotChain(client);
// … mine tx, mine block, mine more tx …
const reverted = await revertChain(client, snapshotId);
// reverted === true when anvil accepted the id, false on stale/unknown id
```

`snapshotChain(client)` returns the `evm_snapshot` id typed as a `Hex`. `revertChain(client, id)` returns anvil's boolean response, so `expect(reverted).toBe(true)` catches stale ids instead of letting the test silently continue.

### Dogfood apps (3 new, all opt in)

Three examples ship under `examples/`, each producing a real vs mock fidelity report that feeds the 7-axis release gate.

- `dogfood-reth-node-test` — `MockRethAdapter` (in-process `MockChainState`) + `RealRethAdapter` (spawns `reth node --dev` when `KIWA_RETH_LIVE=1`). 3 scenarios (`erc20_transfer` / `reorg_3block` / `event_history`) driven through a shared 6-op adapter shape. Real adapter records `RETH_ENV_MISSING` when `reth` is absent so fidelity divergence stays observable.
- `dogfood-foundry-invariant-fuzz` — 3 Solidity contracts (`ERC20` + `Vault` + `Router`) × 8 invariants driven through `kiwa::contract::foundry::invariant`. 10 000-run budget with fixed seed, coverage feed into the release gate. Real adapter opts in through `KIWA_FORGE_LIVE=1`.
- `dogfood-dapp-e2e-reorg` — Next.js 15 + wagmi + viem UI + Playwright + `@kiwa-lab/dapp`. 4 reorg scenarios (pending / balance rollback / event history / nonce gap) driven under anvil fork mainnet. Real adapter opts in through `TESTNET_RPC_URL` (Sepolia driver ships as a `REORG_LIVE_NOT_IMPLEMENTED` stub in v0.1; v0.2 wires it up).

Every dogfood app writes its fidelity report to `quality-report/fidelity-latest.md` (git-ignored) and to `docs/quality-reports/blockchain/<name>.md` (git-tracked snapshot promoted per release).

## Release gate

The 11-axis contract is unchanged. Blockchain surfaces (`kiwa-test-rs` + `dogfood-*-reorg`) keep the 7-axis common branch (coverage 3 / fidelity / perf p95 / mutation / behavior tests). The AI-LLM 4 axes (cost / latency / token / accuracy) route only through providers whose name starts with `@kiwa-lab/ai-` (see `isAiLlmProvider` in `packages/quality-metrics/src/types.ts`) — chain-state / EL client surfaces are excluded because there is no token pricing to measure.

The blockchain thresholds match the common 7-axis defaults documented in v1.17 — line coverage ≥ 85%, branch ≥ 80%, function ≥ 90%, fidelity ratio ≥ 70%, perf p95 ≤ 100 ms for `debug_setHead` / `invariant_run` / `snapshotChain` round-trip, mutation kill rate ≥ 60%, behavior test count ≥ 10.

## Upgrade checklist

- [ ] Bump `kiwa-test-rs` in `Cargo.toml` — `kiwa-test-rs = { version = "0.5", features = [...] }`
- [ ] Turn on `contract-reth` when the caller wants a second Rust dev chain (`features = ["contract-reth"]`); default OFF keeps binary size lean for callers that only need `contract-foundry` or `contract-alloy`
- [ ] Replace ad-hoc `Command::new("forge").arg("test").arg("--match-contract").arg("Invariant*")` shell-outs with `invariant_run(&env, &project_root, &opts)` so the harness parses the shrink summary and short-circuits when `forge` is missing
- [ ] Pass `InvariantOptions::seed = Some(u64)` for release-gate suites (deterministic replay). Leave `None` only when hunting fresh state-explorer paths on a scratch branch
- [ ] Wire `snapshotChain` / `revertChain` around any Playwright scenario that mutates chain state, so a follow-up test does not observe leaked state from the previous one
- [ ] Add `TESTNET_RPC_URL` in CI when you want the `dogfood-dapp-e2e-reorg` fidelity report to run the live driver instead of the `REORG_REAL_ENV_MISSING` skip path; add `KIWA_RETH_LIVE=1` + `reth` binary for the reth dogfood; add `KIWA_FORGE_LIVE=1` + `foundryup` for the invariant dogfood

## Migrating from v0.4 `contract::foundry`

Tests that used `kiwa::contract::foundry::FoundryEnv` + `Anvil` + `forge_test` (v0.4 surface) do not need to change. v0.5 is additive — the v0.4 API surface is untouched and public re-export paths stay the same after the `foundry.rs` → `foundry/mod.rs` internal split.

To adopt v0.5 in an existing v0.4 test, extend the invariant / shrink path.

```rust
// v1.17 (v0.4 forge_test unit surface)
use kiwa::contract::foundry::{FoundryEnv, forge_test};

let env = FoundryEnv::detect();
let unit_report = forge_test(&env, &project_root)?;
if !unit_report.skipped {
    assert!(unit_report.success);
}

// v1.18 (v0.4 unit path + v0.5 invariant path on the same env)
use kiwa::contract::foundry::{
    FoundryEnv, InvariantOutcome, forge_test,
    invariant::{InvariantOptions, invariant_run},
};

let env = FoundryEnv::detect();
let unit_report = forge_test(&env, &project_root)?;
let invariant_report = invariant_run(
    &env,
    &project_root,
    &InvariantOptions { runs: 10_000, seed: Some(0xdead_beef), ..Default::default() },
)?;

if !unit_report.skipped && !invariant_report.skipped {
    assert!(unit_report.success);
    assert_eq!(invariant_report.outcome, InvariantOutcome::Passed);
}
```

The invariant runner is a pure superset of the unit runner. It writes no config file, forwards its seed through env vars, and returns a structured report — the test grows one function call and gains 10 000 runs of state-explorer coverage.
