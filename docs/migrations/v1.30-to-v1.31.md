## What's new (opt in)

### `@kiwa-test/streaming` v0.3 — 8 advanced-semantics axes

Install (or bump) the package.

```bash
pnpm add -D @kiwa-test/streaming@^0.3
```

Import the axis you need.

```ts
import {
  createKafkaRawProtocol,
  createKafkaConsumerGroup,
  createRedpandaSchemaEvolution,
  createRedpandaTransactions,
  createNatsJetStreamDurable,
  createNatsKvObject,
  createExactlyOnceSemantics,
  createConsumerLagTelemetry,
  createFidelityHarness,
} from '@kiwa-test/streaming';
```

Use it in your own test.

```ts
import { describe, expect, it } from 'vitest';
import { createKafkaRawProtocol } from '@kiwa-test/streaming';

describe('my producer — KIP-98 fencing', () => {
  it('rejects an older-epoch identity after fenceProducer', () => {
    const raw = createKafkaRawProtocol();
    const first = raw.initProducerId();
    const fenced = raw.fenceProducer(first.producerId);
    expect(raw.isValidEpoch(first)).toBe(false);
    expect(raw.isValidEpoch(fenced)).toBe(true);
  });
});
```

The full API surface — `initProducerId` / `fenceProducer` / `isValidEpoch` / `transitionTransaction` / `openFetchSession` / `bumpFetchSession` / `addToIsr` / `removeFromIsr` / `advanceHighWatermark` — is spelled out in tutorial 58. The 3 other Kafka-shaped axes (`consumer-group` / `transactions` / `exactly-once`) follow the same "explicit state, explicit clock" pattern.

### `createFidelityHarness()` — 3 provider × 8 axis = 24 cell grid

The fidelity harness describes which provider covers which axis, and whether the mock has parity with the real driver.

```ts
import { createFidelityHarness } from '@kiwa-test/streaming';

const harness = createFidelityHarness();
console.log(harness.totalCells()); // 24

const kafkaCells = harness.cellsFor('kafka');
// kafka-raw-protocol / kafka-consumer-group / exactly-once / consumer-lag-telemetry all `implemented`.
// redpanda-schema-evolution / redpanda-transactions all `implemented` (Kafka API compat).
// nats-jetstream-durable / nats-kv-object all `not-applicable` on kafka.

const missing = harness.axesFor('nats', 'not-applicable');
// ['kafka-raw-protocol', 'kafka-consumer-group', 'redpanda-schema-evolution', 'redpanda-transactions']
```

The 3 statuses are — `implemented` (the axis has a working mock + real-driver check), `not-applicable` (a real-world mismatch, e.g., NATS has no Kafka wire protocol), `planned` (marked for a future milestone). Tests iterate the grid and assert every cell is `implemented` or explicitly `not-applicable` — a `planned` cell is a "not yet done" flag your test suite can fail on.

### `KIWA_MODE=real` — env-gated real driver run

The mock path stays the default. When `KIWA_MODE=real` is set, the harness assertions also try to run against the real driver, gated by the required env for that axis.

```ts
import { isRealDriverMode, requiredKeyFor } from '@kiwa-test/streaming';

if (isRealDriverMode()) {
  const key = requiredKeyFor('kafka-raw-protocol');
  if (key && process.env[key]) {
    // Spin up testcontainers Kafka + run the same assertion against the real broker.
  }
}
```

Required keys — `KAFKA_KEY` for Kafka axes, `REDPANDA_KEY` for Redpanda axes, `NATS_KEY` for NATS axes. Absent env ⇒ skip the real-driver assertion (mock path stays green). This is the same env-gate contract the v1.22 real-driver testing tutorial (auth adapters + Keycloak testcontainers) uses.

## No release-gate axis change

v1.31 does not add a 14th release-gate axis. The 8 streaming axes gate the streaming package's own tests (via `pnpm --filter @kiwa-test/streaming test`) but do not surface as a per-package `quality-metrics` axis. The reason is that the fidelity harness is provider-shape-specific — a package that does not use Kafka / Redpanda / NATS has nothing to assert on. When a future milestone adds a `provider.fidelity` axis that describes "which streaming providers this package's tests hit," it will slot into the 13-axis release gate as the 14th; v1.31 keeps things simple.
