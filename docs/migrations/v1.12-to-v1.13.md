# v1.12 → v1.13 migration

## Scope

v1.13 (issue [#709](https://github.com/cardene777/kiwa/issues/709)) extends kiwa to cover **realtime providers** and lands the first four realtime mocks:

- `@kiwa-lab/realtime` v0.1 — new package with unified mocks for Supabase Realtime + Ably + Pusher + Socket.io / SSE, plus a real-vs-mock fidelity harness scoped to 5 realtime scenarios (chat broadcast, presence join/leave, postgres CDC, room subscribe race, reconnect with pending)
- `@kiwa-lab/perf-harness` v0.1 — new package with a 5-target perf benchmark helper (p50 / p95 / p99 + regression detection) that feeds the release gate's `perf.p95Ms` axis
- 3 dogfood apps under `examples/dogfood-{supabase-realtime-chat,ably-collab-cursor,socketio-notification}/`
- Docs augmentation — 3 tutorials + this migration guide + a new [`docs/concepts/realtime-testing.md`](../concepts/realtime-testing) SSOT

**No release-gate axis change.** v1.13 does not add axes to `evaluateReleaseGate`. Realtime providers land on the 7-axis common branch; the `provider` prefix `@kiwa-lab/realtime` **does not** activate the AI-LLM branch. The 5 realtime axes (order / timing / drop / reconnect / backpressure) are properties of the event trace, aggregated by `runRealtimeFidelityCheck` and mapped to the existing `fidelity.ratio` and `perf.p95Ms` axes via `buildRealtimeReport`.

## Update TypeScript deps

Bump `@kiwa-lab/quality-metrics` (already on v0.2 from v1.12; no bump required) and add `@kiwa-lab/realtime` when you want to test a realtime provider:

```diff
 {
   "devDependencies": {
     "@kiwa-lab/quality-metrics": "0.2.0",
     "@kiwa-lab/ai-llm": "0.1.0",
+    "@kiwa-lab/realtime": "0.1.0"
   }
 }
```

Then `pnpm install`.

## What changed in the release gate (non-breaking)

The gate's provider dispatch is unchanged. The `isAiLlmProvider` predicate ([`packages/quality-metrics/src/types.ts`](https://github.com/cardene777/kiwa/blob/main/packages/quality-metrics/src/types.ts)) still selects the 11-axis branch only for `@kiwa-lab/ai-*`. Realtime reports carry a `provider` string like `@kiwa-lab/realtime/supabase-realtime-chat` — that prefix does **not** match `@kiwa-lab/ai-`, so `verdict.axesEvaluated` stays at 7.

Downstream implication — every v1.12 report continues to pass unchanged. Adopting `@kiwa-lab/realtime` for a new provider adds a *new* 7-axis report, not a modification to an existing one.

## Adopt @kiwa-lab/realtime (only if you are testing a realtime provider)

Install the harness and use one of the four mocks that matches your SDK.

```bash
pnpm add -D @kiwa-lab/realtime
```

### Supabase Realtime chat

```ts
import { createSupabaseRealtimeMock } from '@kiwa-lab/realtime';

const supabase = createSupabaseRealtimeMock({
  artificialLatencyMs: 3,
  provider: 'supabase-mock',
});
const channel = supabase.channel('room:demo');
await channel
  .on('broadcast', { event: 'chat' }, (payload) => {
    console.log(payload.payload); // { userId, text, timestamp }
  })
  .subscribe();
await channel.track({ userId: 'alice' });
await channel.send({ type: 'broadcast', event: 'chat', payload: { text: 'hi' } });
```

### Ably shared cursor

```ts
import { createAblyMock } from '@kiwa-lab/realtime';

const ably = createAblyMock({ clientId: 'alice' });
const channel = ably.channels.get('board-1');
await channel.subscribe('cursor', (msg) => console.log(msg.data));
await channel.publish('cursor', { x: 100, y: 200 });
const history = await channel.history({ limit: 10 }); // rewind
```

### Pusher presence

```ts
import { createPusherMock } from '@kiwa-lab/realtime';

const pusher = createPusherMock({ userId: 'me' });
const channel = pusher.subscribeChannel('presence-room-1');
channel.bind('pusher:subscription_succeeded', (members) => {
  console.log('now in room, count:', members.count);
});
```

### Socket.io notification

```ts
import { createSocketioMock } from '@kiwa-lab/realtime';

const io = createSocketioMock({ backpressureLimit: 8 });
const socket = io.io('/notify');
await socket.join('alerts:alice');
socket.on('notify', (payload) => console.log(payload));

// server-side push
io.of('/notify').to('alerts:alice').emit('notify', { body: 'PR #123 ready' });
```

See the [Supabase Realtime chat tutorial](../tutorials/09-supabase-realtime-chat), the [Ably collab cursor tutorial](../tutorials/10-ably-collab-cursor), and the [Socket.io notification tutorial](../tutorials/11-socketio-notification) for full walkthroughs.

## Fidelity harness — realtime shape

`runRealtimeFidelityCheck` produces a report shaped like:

```ts
{
  records: [
    {
      scenarioId: 'chat-message-broadcast',
      real: CollectedEvent[],       // driver returned real events
      mock: CollectedEvent[],       // driver returned mock events
      eventCountDiff: number,       // real.length - mock.length
      kindOrderMatch: number,       // 0-1 Jaccard on kind sequence
      payloadMatch: number,         // 0-1 payload/event-name similarity
      accuracyScore: number,        // (kindOrderMatch + payloadMatch) / 2
      totalDurationDiffMs: number,
    },
    // ...
  ],
  summary: {
    scenarios: number,
    avgAccuracyScore: number,
    avgEventCountDiff: number,
    avgKindOrderMatch: number,
    avgPayloadMatch: number,
    avgTotalDurationDiffMs: number,
    accuracyMethod: 'sequence-jaccard',
  },
}
```

The 5 realtime axes (order / timing / drop / reconnect / backpressure) surface via:

- **Order** — `record.kindOrderMatch` — Jaccard similarity on the `kind` sequence (`presence` / `broadcast` / `postgres_changes` / `connection`)
- **Timing** — `record.totalDurationDiffMs` — cumulative drift in scenario wall-clock
- **Drop** — mock adapter's `metrics().eventsDropped` — passed through to the fidelity summary
- **Reconnect** — mock adapter's `metrics().reconnectCount` — same
- **Backpressure** — per-scenario `pendingByRoom.queuedCount` snapshots — surfaced by dogfood-specific `getPending()` methods, not directly by the harness

**Fidelity is not "mock == real"**. It is "mock stays close enough to real on 5 axes that a v1.14 test written against the mock still tells you something about production behaviour". The default `avgAccuracyScore ≥ 0.80` floor is the same "meaningfully similar" bar the AI-LLM concept doc landed on.

### Shortcut — `buildRealtimeReport` from `runRealtimeFidelityCheck`

If you already run `runRealtimeFidelityCheck`, `buildRealtimeReport` fills a `QualityReport` from the fidelity result + mock metrics without hand-wiring `perf` / `fidelity` samples:

```ts
import { buildRealtimeReport, runRealtimeFidelityCheck } from '@kiwa-lab/realtime';
import { evaluateReleaseGate, emitMarkdown } from '@kiwa-lab/quality-metrics';

const fidelity = await runRealtimeFidelityCheck({
  realDriver,
  mockDriver,
  scenarios: [
    'chat-message-broadcast',
    'presence-join-leave',
    'reconnect-with-pending',
  ],
});

const report = buildRealtimeReport({
  provider: '@kiwa-lab/realtime/supabase-realtime-chat',
  version: '0.1.0',
  fidelity,
  mockMetrics: supabase.getMetrics(),
  testCount: { behavior: 48, integration: 0, e2e: 0 },
});
const verdict = evaluateReleaseGate(report);
console.log(emitMarkdown({ report, verdict }));
// verdict.axesEvaluated === 7 — realtime lands on the common branch
```

## Adopt @kiwa-lab/perf-harness (optional, shared with v1.13-1)

The perf harness is not scoped to realtime — any provider can use it to fill the `perf.p95Ms` axis with real percentile samples. Install alongside the realtime harness when you want p50/p95/p99 tracking:

```bash
pnpm add -D @kiwa-lab/perf-harness
```

Realtime perf typically measures **socket round-trip latency** (subscribe → first event received) rather than one-shot API latency:

```ts
import { buildMeasureResult, measure } from '@kiwa-lab/perf-harness';

// Option A — build a percentile summary from mock metrics (samples already collected)
const samples = supabase.getMetrics().publishLatencyMs; // ms per publish → subscribe
const result = buildMeasureResult('supabase-publish', samples.length, 0, samples);
console.log(result.p50, result.p95, result.p99);

// Option B — drive the harness end-to-end (warmup + measurement loop)
const measured = await measure({
  name: 'supabase-publish',
  iterations: 100,
  warmup: 10,
  fn: async () => {
    await channel.send({ type: 'broadcast', event: 'chat', payload: { text: 'ping' } });
  },
});
console.log(measured.p95); // ms
```

## Default thresholds — realtime (unchanged from v1.11 gate)

Realtime lands on the common 7-axis branch, so the thresholds are unchanged from v1.11:

| axis | threshold | comparison | rationale |
|---|---|---|---|
| `coverage.line` | 85% | ≥ | Common branch |
| `coverage.branch` | 80% | ≥ | Common branch |
| `coverage.function` | 90% | ≥ | Common branch |
| `fidelity.ratio` | 70% | ≥ | Method-count coverage of the mock vs the real SDK surface |
| `perf.p95Ms` | 100 ms | ≤ | Socket round-trip target for the mock (matches SLA for user-perceived push latency) |
| `mutation.killRate` | 60% | ≥ | Common branch |
| `testCount.behavior` | 10 | ≥ | Common branch |

The `perf.p95Ms ≤ 100 ms` bar is deliberately tight — real Supabase Realtime / Ably / Pusher / Socket.io targets sub-100 ms end-to-end push latency on healthy networks, and the mock's `artificialLatencyMs` default of `3-5` ms leaves plenty of headroom. Blowing 100 ms in mock mode usually indicates a test infrastructure issue (CI runner under load, `await` misuse) rather than a real regression.

Overrides live in `evaluateReleaseGate(report, { perfP95Ms: 250, ... })`. Any override must be justified in the provider PR body (per `docs/quality/release-gate.md` § overrides の運用).

## Follow the realtime dogfood pattern (optional)

If you maintain a realtime provider, mirror the v1.13 dogfood layout:

```
examples/dogfood-<provider>-app/
├── src/
│   ├── adapters/
│   │   ├── interface.ts    (provider-neutral flow contract + TraceEvent)
│   │   ├── mock.ts         (kiwa mock adapter — throttle / debounce / backpressure)
│   │   └── real.ts         (real provider with graceful skip when env / SDK missing)
│   └── flows/
│       ├── <domain>-flows.ts   (3-5 flows exercising the realtime primitives)
│       └── fidelity.ts     (trace diff + buildRealtimeReport call)
└── tests/
    ├── e2e-mock-mode.test.ts        (mock-mode end-to-end tests, exact assertions)
    ├── fidelity-report.test.ts      (harness contract tests)
    └── emit-fidelity-report.test.ts (writes quality-report/fidelity-latest.md)
```

The three v1.13 dogfood apps demonstrate the pattern for chat + presence + typing debounce (`dogfood-supabase-realtime-chat`), collab cursor + throttle + history rewind (`dogfood-ably-collab-cursor`), and notification + reconnect + backpressure (`dogfood-socketio-notification`).
