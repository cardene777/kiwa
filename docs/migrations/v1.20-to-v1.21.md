# Migration guide — v1.20 → v1.21

v1.21 is **additive** — every `@kiwa-lab/*` package and `kiwa-test-rs` public API that existed in v1.20 keeps its surface. Existing tests keep passing.

The 4 things v1.21 adds are.

- `@kiwa-lab/auth` v0.2 (4 auth protocol adapters — `setupWebAuthnEnv` + `setupPasskeyEnv` + `setupOAuth21Env` + `setupOidcEnv` — landing WebAuthn L3 virtual authenticator, Passkey sync fabric, OAuth 2.1 mock AS with PKCE + DPoP + refresh rotation + revocation, and OIDC mock OP with Discovery + DCR + `id_token` + JWKS rotation + Federation trust chain)
- 3 dogfood apps (`dogfood-webauthn-passkey-app` + `dogfood-oauth21-provider` + `dogfood-oidc-federation`) that measure the mocks against real browser + Keycloak surfaces
- 3 tutorials, 1 concept doc, 1 migration guide (this file) covering the 4 protocols end-to-end (virtual authenticator + Passkey / PKCE + DPoP + refresh + revocation / Discovery + DCR + `id_token` / Federation trust chain)
- 4 protocol adapters layered so `setupOidcEnv` reuses the `setupOAuth21Env` authorization + token endpoints verbatim and layers the OIDC surface on top — a single fidelity harness covers both

## What breaks (nothing)

Nothing. The v1.21 changes are pure additions.

- `@kiwa-lab/streaming` v0.1 (`createKafkaMock` + `createRedpandaMock` + `createNatsMock` + `createTransactionalProducer` + `createIdempotentProducer` + `createDeadLetterQueue` + `createSchemaRegistry` + JetStream + KV + Object stores) — unchanged.
- `@kiwa-lab/solidjs` + `@kiwa-lab/fresh` + `@kiwa-lab/hono` v0.1 (Framework 深化 landing) — unchanged.
- `kiwa-test-rs` v0.5 exports (`contract::reth` + `contract::foundry::invariant` + `contract::alloy::helpers`) — unchanged.
- `@kiwa-lab/dapp` reorg helpers (`snapshotChain` / `revertChain`) — unchanged.
- `@kiwa-lab/observability` v2.0 (dashboard + alert + trace + correlation) — unchanged.
- `@kiwa-lab/component` v0.1 + `@kiwa-lab/realtime` + `@kiwa-lab/ai-llm` + `@kiwa-lab/mcp` + `@kiwa-lab/agent` + `@kiwa-lab/perf-harness` + `@kiwa-lab/quality-metrics` — unchanged.
- `evaluateReleaseGate` — same 11-axis contract as v1.17 / v1.18 / v1.19 / v1.20. Auth protocol surfaces (`webauthn` / `passkey` / `oauth21` / `oidc`) roll into the common 7-axis branch (coverage / test count / fidelity / perf p95 / mutation). The AI-LLM 4 axes (cost / latency / token / accuracy) do not apply.
- Every prior `@kiwa-lab/auth` surface (NextAuth / Lucia / Better Auth / Clerk / Auth0 / Supabase Auth core + advanced) — unchanged. v1.21 adds four new setup entry points; v1.10-2 through v1.20 setup entry points keep their signatures.
- Everything else (queue / cache / realtime / payment / search / polyglot Go / dApp framework adapters / docs skills) — untouched.

## What's new (opt in)

### `@kiwa-lab/auth` v1.21 — 4 protocol adapters (WebAuthn L3 + Passkey + OAuth 2.1 + OIDC)

Auth protocol testing diverges from bearer-token session tests on four axes — virtual authenticator taxonomy, PKCE + DPoP proof mechanics, `id_token` claim / hash / nonce guards, and Federation trust-chain resolution. `@kiwa-lab/auth` v1.21 delivers four adapters that let a test drive all four without booting a real browser, security key, Keycloak deployment, or Federation trust anchor.

```ts
import {
  setupWebAuthnEnv,
  setupPasskeyEnv,
  setupOAuth21Env,
  setupOidcEnv,
  createOidcTrustAnchor,
  createOidcEntityStatement,
  resolveOidcTrustChain,
  mintSoftwareStatement,
} from '@kiwa-lab/auth';

// WebAuthn L3 — virtual authenticator + credentialCreation + credentialAssertion.
const webauthn = await setupWebAuthnEnv({
  authenticators: [
    { attachment: 'platform', transport: 'internal', hasResidentKey: true, hasUserVerification: true },
  ],
});
const created = await webauthn.credentialCreation({
  rp: { id: 'example.test', name: 'Example RP' },
  user: { id: 'user-1', name: 'alice', displayName: 'Alice' },
  challenge: 'c-create',
  attestation: 'direct',
});
const assertion = await webauthn.credentialAssertion({
  rpId: 'example.test',
  challenge: 'c-get',
});
expect(assertion.signCount).toBe(1);

// Passkey — sync fabric backup + restore across iCloud Keychain / Google Password Manager.
const passkey = await setupPasskeyEnv({
  devices: [
    { deviceId: 'macbook-old', platform: { biometric: 'touch-id' } },
    { deviceId: 'macbook-new', platform: { biometric: 'touch-id' } },
  ],
});
const cred = await passkey.createPasskey('macbook-old', 'user-1', {
  rp: { id: 'example.test', name: 'Example RP' },
  user: { id: 'user-1', name: 'alice', displayName: 'Alice' },
  challenge: 'c-create',
});
passkey.backupCredential(cred.credentialId, 'icloud-keychain');
passkey.removeDevice('macbook-old');
const restored = passkey.restoreCredential('macbook-new', 'user-1', cred.credentialId, 'icloud-keychain');
expect(restored.originDeviceId).toBe('macbook-old');

// OAuth 2.1 — PKCE + DPoP + refresh rotation + revocation.
const oauth = await setupOAuth21Env({
  issuer: 'https://as.example.test',
  clients: [
    {
      clientId: 'client-A',
      redirectUris: ['https://app.example.test/cb'],
      scopes: ['openid'],
      clientType: 'public',
    },
  ],
  users: [{ subject: 'user-1', scopes: ['openid'] }],
});
const { codeVerifier, codeChallenge } = oauth.createPkceChallenge();
const authRes = oauth.server.authorize(
  {
    responseType: 'code',
    clientId: 'client-A',
    redirectUri: 'https://app.example.test/cb',
    state: 's-1',
    scope: 'openid',
    codeChallenge,
    codeChallengeMethod: 'S256',
  },
  'user-1',
);
const dpop = oauth.createDpopProof({
  htm: 'POST',
  htu: 'https://as.example.test/token',
});
const token = oauth.server.token({
  grantType: 'authorization_code',
  code: authRes.code,
  redirectUri: 'https://app.example.test/cb',
  clientId: 'client-A',
  codeVerifier,
  dpop,
});
expect(token.tokenType).toBe('DPoP');
const rotated = oauth.refreshToken(token.refreshToken, 'client-A', dpop);
expect(rotated.refreshToken).not.toBe(token.refreshToken);

// OIDC — Discovery + DCR + id_token verify + Federation trust chain.
const oidc = await setupOidcEnv({
  issuer: 'https://op.example.test',
  clients: [
    {
      clientId: 'preset-client',
      redirectUris: ['https://rp.example.test/cb'],
      scopes: ['openid'],
      clientType: 'public',
    },
  ],
  users: [{ subject: 'user-1', scopes: ['openid'] }],
  softwareStatementIssuer: 'trust-anchor-alpha',
});
const meta = oidc.discovery.fetch();
expect(meta.issuer).toBe('https://op.example.test');
const client = oidc.registerClient({
  redirect_uris: ['https://rp2.example.test/cb'],
  token_endpoint_auth_method: 'none',
});
const idToken = oidc.signIdToken({
  sub: 'user-1',
  aud: client.client_id,
  nonce: 'n1',
});
const result = oidc.verifyIdToken(idToken.jwt, {
  expectedIssuer: 'https://op.example.test',
  expectedAudience: client.client_id,
  expectedNonce: 'n1',
});
expect(result.valid).toBe(true);

// OIDC Federation trust chain (OIDF 1.0 §7).
const anchor = createOidcTrustAnchor({ entity_id: 'https://anchor.example.test' });
const intermediate = createOidcEntityStatement({
  iss: 'https://anchor.example.test',
  sub: 'https://intermediate.example.test',
});
const leaf = createOidcEntityStatement({
  iss: 'https://intermediate.example.test',
  sub: 'https://leaf.example.test',
});
const chain = resolveOidcTrustChain({ leaf, intermediates: [intermediate], anchor });
expect(chain.valid).toBe(true);
```

Every adapter carries a deterministic counter reset (`__resetWebAuthnCounters` / `__resetPasskeyCounters` / `__resetOAuth21Counters` / `__resetOidcCounters`) so tests that mint credentials / tokens / JWKS keys stay reproducible across runs.

The OIDC adapter layers on the OAuth 2.1 adapter — `setupOidcEnv` reuses the `setupOAuth21Env` `/authorize` + `/token` endpoints verbatim (including PKCE + DPoP + refresh rotation semantics) and adds the OIDC surface (Discovery + DCR + `id_token` sign / verify + JWKS rotation + Federation) on top. That means the same fidelity harness covers both layers.

### JWKS rotation with retention window (RFC 7517)

The OIDC adapter maintains a JWKS document under `env.jwks`. Rotation lifecycle mirrors production OPs — a rotate retires the current kid, mints a new one, and keeps the retired kid inside the JWKS for a `jwksRetentionSec` window so tokens signed by the retired kid still verify.

```ts
const env = await setupOidcEnv({
  issuer: 'https://op.example.test',
  clients: [
    {
      clientId: 'preset-client',
      redirectUris: ['https://rp.example.test/cb'],
      scopes: ['openid'],
      clientType: 'public',
    },
  ],
  users: [{ subject: 'user-1', scopes: ['openid'] }],
  jwksRetentionSec: 3600,
});
const client = env.registerClient({
  redirect_uris: ['https://rp.example.test/cb'],
  token_endpoint_auth_method: 'none',
});
const token = env.signIdToken({ sub: 'user-1', aud: client.client_id, nonce: 'n1' });

// Rotate — the previous kid retires but stays inside JWKS.
env.jwks.rotate();
expect(env.jwks.fetch().keys.map((k) => k.kid)).toEqual(['k002', 'k001']);

// Verify still succeeds via the retired kid.
const result = env.verifyIdToken(token.jwt, {
  expectedIssuer: 'https://op.example.test',
  expectedAudience: client.client_id,
  expectedNonce: 'n1',
});
expect(result.valid).toBe(true);
```

`env.jwks.rotate()` returns the new active key material (`{ kid, alg, ... }`). The retired kid drops out of the JWKS document after `jwksRetentionSec` elapses — subsequent verifies of tokens signed by the retired kid throw `/kid not in JWKS/`.

### Dogfood apps (3 new, all opt in)

Three examples ship under `examples/`, each producing a real vs mock fidelity report that feeds the 7-axis release gate.

- `dogfood-webauthn-passkey-app` — Next.js 15 RP that exercises WebAuthn credential creation + attestation, credential assertion + userVerification (4 patterns), residentKey-based discoverable credentials, and `/manage` (list + delete). Layer 1 pure logic tests (`setupWebAuthnEnv` / `credentialCreation` / `credentialAssertion`), Layer 2 fidelity harness (mock vs SimpleWebAuthn-shaped RP + Chrome Virtual Authenticator, opt in through `KIWA_WEBAUTHN_REAL_READY=1`), Layer 3 Playwright full-flow e2e (register → list → signin → delete → signin).
- `dogfood-oauth21-provider` — self-hosted AS that exercises PKCE authorization code exchange, DPoP-bound access tokens, rotating refresh with reuse detection, revocation cascade, and introspection. Layer 1 pure logic tests, Layer 2 fidelity harness (mock vs Keycloak, opt in through `KIWA_MODE=real` + `KEYCLOAK_URL`), Layer 3 7-axis release-gate report at `quality-reports/auth/oauth21-provider.md`.
- `dogfood-oidc-federation` — Deno + Hono OP that exercises Discovery, RFC 7591 DCR (3 auth methods + `software_statement` JWS + `redirect_uris` validation), `id_token` verify (JWS signature + claims + nonce + `at_hash` / `c_hash`), JWKS rotation e2e, and OpenID Federation 1.0 §7 trust-chain resolution. Nuxt 3 RP under `rp/`. Layer 1 pure logic tests, Layer 2 fidelity harness (mock vs Keycloak, deferred to v1.22), Layer 3 16-axis release-gate report at `docs/quality-reports/auth/oidc-federation.md`.

Every dogfood app writes its fidelity report to `quality-reports/auth/<name>.md` (git-tracked snapshot promoted per release). `KIWA_MODE=mock` always runs; `KIWA_MODE=real` runs only when the real-driver bootstrap gate (`KIWA_WEBAUTHN_REAL_READY=1` / `OAUTH21_BOOTSTRAP=1` / `OIDC_BOOTSTRAP=1`) is set.

## Release gate

The 11-axis contract is unchanged. Auth protocol surfaces (`webauthn` / `passkey` / `oauth21` / `oidc`) keep the 7-axis common branch (coverage 3 / fidelity / perf p95 / mutation / behavior tests). The AI-LLM 4 axes (cost / latency / token / accuracy) route only through providers whose name starts with `@kiwa-lab/ai-` (see `isAiLlmProvider` in `packages/quality-metrics/src/types.ts`) — auth surfaces are excluded because there is no token pricing to measure.

The auth thresholds match the common 7-axis defaults documented in v1.17 — line coverage ≥ 85%, branch ≥ 80%, function ≥ 90%, fidelity ratio ≥ 70%, perf p95 ≤ 100 ms for `credentialCreation` / `credentialAssertion` / `authorize` / `token` / `signIdToken` / `verifyIdToken` / `resolveOidcTrustChain`, mutation kill rate ≥ 60%, behavior test count ≥ 10.

## Upgrade checklist

- [ ] Add `@kiwa-lab/auth@0.2` when the caller wants WebAuthn / Passkey / OAuth 2.1 / OIDC coverage (`pnpm add -D @kiwa-lab/auth@0.2`); v1.20 tests keep passing regardless
- [ ] Replace ad-hoc Chrome DevTools Protocol Virtual Authenticator harnesses (usually a Playwright fixture that mounts + unmounts an authenticator per test) with `setupWebAuthnEnv({ authenticators: [...] })` — the attachment / transport / residentKey / userVerification pairs refuse invalid combinations at setup time
- [ ] Replace ad-hoc PKCE + DPoP stubs (usually a `class MockAuthServer { authorize() {} token() {} }` pattern plus manual code / access token counters) with `setupOAuth21Env({ issuer, clients, users })` — the mock refuses `code_challenge_method=plain` + `response_type=token` + dropped grants at runtime
- [ ] Replace ad-hoc `id_token` sign / verify (usually a `jsonwebtoken.sign` call plus a claim-by-claim assertion loop) with `env.signIdToken({ sub, aud, nonce, accessToken, code })` + `env.verifyIdToken(jwt, expected)` — each mismatch surfaces a specific `reason` string
- [ ] Wire `resolveOidcTrustChain({ leaf, intermediates, anchor, now? })` into any Federation client that must validate a chain — the walker refuses broken links, expired intermediates, cycles, and chains that never reach the anchor

## Migrating from v0.x custom auth harnesses

Tests that maintain a hand-rolled OAuth 2.1 or OIDC harness (usually a `class MockAuthServer` pattern plus manual state) can migrate incrementally.

```ts
// Before (hand-rolled OAuth stub)
const codes = new Map<string, { user: string; clientId: string }>();
const mockAs = {
  authorize: (req: { clientId: string; state: string; codeChallenge: string }, user: string) => {
    const code = `code-${codes.size + 1}`;
    codes.set(code, { user, clientId: req.clientId });
    return { code, state: req.state };
  },
  token: (req: { code: string; codeVerifier: string }) => {
    const entry = codes.get(req.code);
    if (!entry) throw new Error('unknown code');
    codes.delete(req.code);
    return { accessToken: `at-${req.code}`, refreshToken: `rt-${req.code}` };
  },
};
const authRes = mockAs.authorize({ clientId: 'c1', state: 's1', codeChallenge: 'x' }, 'user-1');
const token = mockAs.token({ code: authRes.code, codeVerifier: 'x' });

// After (v1.21 with @kiwa-lab/auth)
import { setupOAuth21Env } from '@kiwa-lab/auth';

const env = await setupOAuth21Env({
  issuer: 'https://as.example.test',
  clients: [
    {
      clientId: 'c1',
      redirectUris: ['https://app.example.test/cb'],
      scopes: ['openid'],
      clientType: 'public',
    },
  ],
  users: [{ subject: 'user-1', scopes: ['openid'] }],
});
const { codeVerifier, codeChallenge } = env.createPkceChallenge();
const authRes = env.server.authorize(
  {
    responseType: 'code',
    clientId: 'c1',
    redirectUri: 'https://app.example.test/cb',
    state: 's1',
    scope: 'openid',
    codeChallenge,
    codeChallengeMethod: 'S256',
  },
  'user-1',
);
const token = env.server.token({
  grantType: 'authorization_code',
  code: authRes.code,
  redirectUri: 'https://app.example.test/cb',
  clientId: 'c1',
  codeVerifier,
});
```

The v1.21 helper enforces the OAuth 2.1 refusal set — `response_type=token` / `code_challenge_method=plain` / dropped grants (`password` / `client_credentials` / `implicit`) / replay of already-consumed codes / mismatched `code_verifier` / cross-client revocation. The hand-rolled stub does not, which is why it silently allows the RFC-forbidden combinations.

The same pattern applies to WebAuthn (replace ad-hoc Chrome Virtual Authenticator harnesses with `setupWebAuthnEnv` for attachment + transport + residentKey + UV combinations), Passkey (replace ad-hoc `iCloudKeychainMock` stubs with `setupPasskeyEnv` for sync fabric backup + restore), and OIDC (replace hand-rolled `jsonwebtoken.sign` / `.verify` with `env.signIdToken` / `env.verifyIdToken` for claim + hash + nonce guards, plus `resolveOidcTrustChain` for Federation walker).
