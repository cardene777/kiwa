# Migration guide — v1.19 → v1.20

v1.20 is **additive** — every `@kiwa-lab/*` package and `kiwa-test-rs` public API that existed in v1.19 keeps its surface. Existing tests keep passing.

The 4 things v1.20 adds are.

- `@kiwa-lab/streaming` v0.1 (unified Kafka + Redpanda + NATS mock — `createKafkaMock` + `createRedpandaMock` + `createNatsMock` + `createTransactionalProducer` + `createIdempotentProducer` + `createDeadLetterQueue` + `createSchemaRegistry` + JetStream + KV + Object stores)
- 3 dogfood apps (`dogfood-kafka-event-pipeline` + `dogfood-redpanda-schema-registry` + `dogfood-nats-jetstream`) that measure the mock against real broker surfaces
- 3 tutorials, 1 concept doc, 1 migration guide (this file) covering the 5 semantics end-to-end (producer / consumer / exactly-once / DLQ / schema-registry)
- Colocated KV + Object stores that ride on the same NATS JetStream substrate — `nats.kv('bucket')` and `nats.objectStore('bucket')` share the persistence layer

## What breaks (nothing)

Nothing. The v1.20 changes are pure additions.

- `@kiwa-lab/solidjs` + `@kiwa-lab/fresh` + `@kiwa-lab/hono` v0.1 (Framework 深化 landing) — unchanged.
- `kiwa-test-rs` v0.5 exports (`contract::reth` + `contract::foundry::invariant` + `contract::alloy::helpers`) — unchanged.
- `@kiwa-lab/dapp` reorg helpers (`snapshotChain` / `revertChain`) — unchanged.
- `@kiwa-lab/observability` v2.0 (dashboard + alert + trace + correlation) — unchanged.
- `@kiwa-lab/component` v0.1 + `@kiwa-lab/realtime` + `@kiwa-lab/ai-llm` + `@kiwa-lab/mcp` + `@kiwa-lab/agent` + `@kiwa-lab/perf-harness` + `@kiwa-lab/quality-metrics` — unchanged.
- `evaluateReleaseGate` — same 11-axis contract as v1.17 / v1.18 / v1.19. Streaming surfaces (`streaming`) roll into the common 7-axis branch (coverage / test count / fidelity / perf p95 / mutation). The AI-LLM 4 axes (cost / latency / token / accuracy) do not apply.
- Everything else (auth / queue / cache / realtime / payment / search / polyglot Go / dApp framework adapters / docs skills) — untouched.

## What's new (opt in)

### `@kiwa-lab/streaming` v0.1 — Kafka + Redpanda + NATS unified mock (5 semantics)

Streaming diverges from HTTP request/response on five axes — producer partitioning, consumer group rebalance, exactly-once atomicity, DLQ retry + quarantine, and schema evolution. `@kiwa-lab/streaming` v0.1 delivers a unified mock stack that lets a test drive all five without booting a real broker.

```ts
import {
  createKafkaMock,
  createTransactionalProducer,
  createIdempotentProducer,
  createDeadLetterQueue,
  createRedpandaMock,
  createNatsMock,
  createSchemaRegistry,
} from '@kiwa-lab/streaming';

// Kafka producer + consumer roundtrip.
const kafka = createKafkaMock({ defaultPartitionCount: 4 });
const producer = kafka.producer();
await producer.connect();
await producer.send({ topic: 'orders', messages: [{ key: 'user-1', value: { total: 42 } }] });

const consumer = kafka.consumer({ groupId: 'workers', partitionAssigner: 'round-robin' });
await consumer.connect();
await consumer.subscribe({ topics: ['orders'], fromBeginning: true });
await consumer.run({ eachMessage: async (m) => { /* handle */ } });
expect(kafka.getCommittedOffset('workers', 'orders', 0)).toBeGreaterThanOrEqual(0);

// Exactly-once via transactional producer.
const tx = createTransactionalProducer({ kafka, transactionalId: 'tx-1' });
await tx.connect();
await tx.initTransactions();
await tx.beginTransaction();
await tx.send({ topic: 'orders', messages: [{ value: 'a' }] });
await tx.commitTransaction();
expect(tx.currentState()).toBe('committed');

// Idempotent producer dedups on sequence.
const idem = createIdempotentProducer({ kafka });
await idem.connect();
await idem.send({ topic: 't', messages: [{ value: 'x' }] }, 42);
const dup = await idem.send({ topic: 't', messages: [{ value: 'x-dup' }] }, 42);
expect(dup).toEqual([]);

// DLQ quarantine after maxAttempts.
const dlq = createDeadLetterQueue<{ id: number }>({
  topic: 'orders',
  handler: async () => { throw new Error('poison'); },
  retryPolicy: { maxAttempts: 3 },
});
const result = await dlq.handle({
  topic: 'orders', partition: 0, offset: 0, timestamp: 0,
  key: null, value: { id: 42 }, headers: {},
});
expect(result).toBe('quarantined');
expect(dlq.deadLetterTopic).toBe('orders.dlq');

// Redpanda = Kafka mock + colocated schema registry.
const rp = createRedpandaMock();
const entry = await rp.schemaRegistry.register({
  subject: 'orders-value',
  kind: 'avro',
  schema: '{"type":"record","name":"O","fields":[{"name":"id","default":0}]}',
});
expect(entry.version).toBe(1);

// NATS core pub/sub + JetStream persistent stream.
const nats = createNatsMock();
const js = nats.jetstream();
await js.addStream({ name: 'ORDERS', subjects: ['orders.>'] });
await js.publish('orders.created', { id: 1 });
const nc = await js.consumer('ORDERS', { durable: 'processor' });
const batch = await nc.fetch(10);
expect(batch).toHaveLength(1);
```

Every helper carries a brand symbol (`KAFKA_MOCK_SYMBOL` / `REDPANDA_MOCK_SYMBOL` / `NATS_MOCK_SYMBOL` / `DLQ_SYMBOL` / `SCHEMA_REGISTRY_SYMBOL` / `TRANSACTIONAL_PRODUCER_SYMBOL` / `IDEMPOTENT_PRODUCER_SYMBOL`) so `isKafkaMock(m)` / `isRedpandaMock(m)` / `isNatsMock(m)` / `isDeadLetterQueue(d)` / `isSchemaRegistry(r)` type-guards catch a fake object at test compile time.

The Kafka + Redpanda mocks share the same producer / consumer / admin surface, so `createRedpandaMock()` satisfies `isKafkaMock(m) === true`. That means a Kafka-only test suite runs against a Redpanda instance by swapping the factory — no other changes.

### Colocated schema registry (Redpanda)

Redpanda ships an in-process schema registry — no Confluent sidecar container. `@kiwa-lab/streaming` mirrors that shape.

```ts
const rp = createRedpandaMock({ schemaRegistry: { defaultCompatibility: 'FULL' } });

// Register a versioned schema.
await rp.schemaRegistry.register({
  subject: 'orders-value',
  kind: 'avro',
  schema: '{"type":"record","name":"Order","fields":[{"name":"id","default":0}]}',
});

// Fail-fast publish — check compat BEFORE writing.
const check = rp.schemaRegistry.checkCompatibility({
  subject: 'orders-value',
  kind: 'avro',
  schema: '{"type":"record","name":"Order","fields":[{"name":"id","default":0},{"name":"amount"}]}',
});
// `amount` has no default → FULL / BACKWARD compat fails.
expect(check.compatible).toBe(false);
expect(check.reasons.length).toBeGreaterThan(0);
```

`checkCompatibility` is synchronous (no round-trip to the broker) and returns `{ compatible, mode, reasons }`. The pattern `if (!check.compatible) throw new Error(check.reasons.join(', '))` gates every publish against schema drift — the test asserts on the gate without a real registry.

Three compatibility modes are supported.

- **BACKWARD** (default) — new schema can read old data. Safe to add optional fields with defaults, safe to remove required fields with defaults.
- **FORWARD** — old schema can read new data. Safe to add required fields, safe to remove optional fields.
- **FULL** — both BACKWARD and FORWARD. Strictest mode; every evolution passes both checks.

### JetStream + KV + Object stores (NATS)

NATS JetStream is the persistence layer for streams, KV, and Object storage. All three ride on the same substrate.

```ts
const nats = createNatsMock();

// JetStream persistent stream.
const js = nats.jetstream();
await js.addStream({ name: 'ORDERS', subjects: ['orders.>'], maxMsgs: 1000 });
await js.publish('orders.created', { id: 1 });
const consumer = await js.consumer('ORDERS', { durable: 'processor', filterSubject: 'orders.created' });
const batch = await consumer.fetch(10);
for (const m of batch) consumer.ack(m);
expect(consumer.info().ackFloor).toBeGreaterThan(0);

// KV store — put / get / delete / keys / revision.
const kv = nats.kv('sessions');
const rev = await kv.put('user-1', { name: 'alice' });
expect(rev).toBe(1);
const entry = await kv.get<{ name: string }>('user-1');
expect(entry?.value.name).toBe('alice');
expect(entry?.revision).toBe(1);

// Object store — byte roundtrip.
const store = nats.objectStore('files');
await store.put('greeting.txt', 'hello');
const obj = await store.get('greeting.txt');
expect(obj?.info.size).toBe(5);
```

Subject wildcards `*` (single token) and `>` (trailing multi-token) match the real NATS routing rules. `compileSubject('orders.>.created')` throws at compile time because `>` must be the last token — the assertion is `expect(() => compileSubject(bad)).toThrow(/last token/)`.

### Dogfood apps (3 new, all opt in)

Three examples ship under `examples/`, each producing a real vs mock fidelity report that feeds the 7-axis release gate.

- `dogfood-kafka-event-pipeline` — Kafka producer + consumer group + transactional producer + DLQ. Layer 1 pure logic tests (`createKafkaMock` / `createTransactionalProducer` / `createDeadLetterQueue`), Layer 2 integration tests through the mock, Layer 3 fidelity harness that compares mock traces against a real `docker compose up -d kafka` run (opt in through `KIWA_KAFKA_LIVE=1`).
- `dogfood-redpanda-schema-registry` — Redpanda + Avro schema evolution + BACKWARD / FORWARD / FULL compatibility checks. Layer 1 registry roundtrip tests, Layer 2 fail-fast publish gate, Layer 3 fidelity harness that compares mock traces against a real `docker compose up -d redpanda` run.
- `dogfood-nats-jetstream` — NATS JetStream persistent + KV Store + Object Store + subject-based routing. Layer 1 pub/sub + JetStream fetch tests, Layer 2 KV / Object roundtrip assertions, Layer 3 fidelity harness that compares mock traces against a real `nats-server -js` run (opt in through `KIWA_NATS_LIVE=1`).

Every dogfood app writes its fidelity report to `quality-report/fidelity-latest.md` (git-ignored) and to `docs/quality-reports/streaming/<name>.md` (git-tracked snapshot promoted per release).

## Release gate

The 11-axis contract is unchanged. Streaming surfaces (`streaming`) keep the 7-axis common branch (coverage 3 / fidelity / perf p95 / mutation / behavior tests). The AI-LLM 4 axes (cost / latency / token / accuracy) route only through providers whose name starts with `@kiwa-lab/ai-` (see `isAiLlmProvider` in `packages/quality-metrics/src/types.ts`) — streaming surfaces are excluded because there is no token pricing to measure.

The streaming thresholds match the common 7-axis defaults documented in v1.17 — line coverage ≥ 85%, branch ≥ 80%, function ≥ 90%, fidelity ratio ≥ 70%, perf p95 ≤ 100 ms for producer send / consumer fetch / registry register roundtrip, mutation kill rate ≥ 60%, behavior test count ≥ 10.

## Upgrade checklist

- [ ] Add `@kiwa-lab/streaming@0.1` when the caller wants Kafka / Redpanda / NATS coverage (`pnpm add -D @kiwa-lab/streaming@0.1`); v1.19 tests keep passing regardless
- [ ] Replace ad-hoc kafkajs stubs (usually `class MockProducer { send() {} }`) with `createKafkaMock().producer()` — the brand-symbol guard catches structural drift at compile time
- [ ] Replace ad-hoc Redis / S3 mocks used for KV / Object storage with `nats.kv('bucket')` / `nats.objectStore('bucket')` when the target stack is NATS — the same connection handles pub/sub, persistence, KV, and objects
- [ ] Wire `createDeadLetterQueue({ topic, handler, retryPolicy, onDeadLetter })` into any consumer that catches poison messages — the `quarantined()` array + `onDeadLetter` callback surface both the count and each failed record
- [ ] Wire `checkCompatibility({ subject, kind, schema })` before every producer send when the target stack uses a schema registry — the fail-fast gate catches BACKWARD / FORWARD / FULL violations before the write reaches the broker

## Migrating from v0.x custom Kafka / NATS harnesses

Tests that maintain a hand-rolled kafkajs harness (usually a `class MockProducer { send() { records.push(...) } }` pattern plus a manual offset counter) can migrate incrementally.

```ts
// Before (hand-rolled kafkajs stub)
const records: unknown[] = [];
const mockProducer = {
  send: async (record: { topic: string; messages: { value: unknown }[] }) => {
    for (const m of record.messages) records.push({ topic: record.topic, value: m.value });
    return record.messages.map((_, i) => ({ topic: record.topic, offset: i }));
  },
};
await mockProducer.send({ topic: 'orders', messages: [{ value: 'x' }] });
expect(records).toHaveLength(1);

// After (v1.20 with @kiwa-lab/streaming)
import { createKafkaMock } from '@kiwa-lab/streaming';

const kafka = createKafkaMock();
const producer = kafka.producer();
await producer.connect();
await producer.send({ topic: 'orders', messages: [{ value: 'x' }] });
expect(kafka.getTopicMessages('orders')).toHaveLength(1);
```

The v1.20 helper carries brand symbols so `isKafkaMock(m)` / `isTransactionalProducer(p)` / `isDeadLetterQueue(d)` type-guards catch a mislabeled mock at compile time. The broker surface (`kafka.getTopicMessages` / `kafka.getCommittedOffset` / `kafka.reset`) is what makes multi-partition + multi-consumer assertions machine-checkable — no manual offset arithmetic.

The same pattern applies to NATS (replace ad-hoc `nats.pub()` mocks with `createNatsMock()` for wildcard subscription + JetStream + KV / Object roundtrip) and Redpanda (replace ad-hoc schema-registry stubs with `createRedpandaMock().schemaRegistry` for BACKWARD / FORWARD / FULL compat gates).
