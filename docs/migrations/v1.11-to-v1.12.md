# v1.11 → v1.12 migration

## Scope

v1.12 (issue [#694](https://github.com/cardene777/kiwa/issues/694)) extends the quality gate to cover AI-LLM providers and lands the first four SDK mocks:

- `@kiwa-test/quality-metrics` v0.2 — release gate expanded from 7 to 11 axes (cost / latency / token / accuracy added)
- `@kiwa-test/ai-llm` v0.1 — new package with unified mocks for Anthropic Messages API + OpenAI Chat Completions + Vercel AI SDK + LangChain, plus a real-vs-mock fidelity harness
- 3 dogfood apps under `examples/dogfood-{anthropic-chatbot,openai-tool-agent,vercel-ai-rag}/`
- Docs augmentation — 3 tutorials + this migration guide + a new [`docs/concepts/ai-llm-testing.md`](../concepts/ai-llm-testing) SSOT

**Non-AI providers are unchanged.** The `evaluateReleaseGate` branch that enforces the 4 AI-LLM axes only fires when `provider.startsWith('@kiwa-test/ai-')`. Every v1.11 report continues to pass on the 7 common axes without modification.

## Update TypeScript deps

Bump `@kiwa-test/quality-metrics` and add `@kiwa-test/ai-llm` when you want to test an AI-LLM provider:

```diff
 {
   "devDependencies": {
-    "@kiwa-test/quality-metrics": "0.1.0"
+    "@kiwa-test/quality-metrics": "0.2.0",
+    "@kiwa-test/ai-llm": "0.1.0"
   }
 }
```

Then `pnpm install`.

## What changed in the release gate (breaking? non-breaking?)

**Non-breaking for non-AI providers.** The gate's provider dispatch is a single `if` around `isAiLlmProvider(report.provider)` (see [`packages/quality-metrics/src/gate.ts`](https://github.com/cardene777/kiwa/blob/main/packages/quality-metrics/src/gate.ts) L83). Non-AI reports never enter the AI-LLM branch, so their `verdict.axesEvaluated` stays at 7 and the output shape is identical to v1.11.

**Breaking for AI-LLM providers.** Any provider whose package name starts with `@kiwa-test/ai-` must now supply the four new metrics (`cost`, `latency`, `token`, `accuracy`) — omitting them fails validation with a per-axis blocker. This is the intentional bar for the new SSOT — an AI-LLM provider that cannot report its own cost / latency / token / accuracy can't claim to be "release quality" under the v1.12 rules.

Non-breaking side of the same change — `isAiLlmProvider` is exported from `@kiwa-test/quality-metrics` so downstream consumers (dogfood apps, custom scripts) use the same 1-line predicate (`provider.startsWith('@kiwa-test/ai-')`) rather than reimplementing it.

## Adopt @kiwa-test/ai-llm (only if you are testing an AI-LLM provider)

Install the harness and use one of the four mocks that matches your SDK.

```bash
pnpm add -D @kiwa-test/ai-llm
```

### Non-AI report — no change (v1.11 → v1.12)

Existing 7-axis reports continue to work unchanged. The gate returns `verdict.axesEvaluated === 7`.

```ts
import {
  assembleReport,
  coverageFromV8Summary,
  evaluateReleaseGate,
  fidelityFromMethodCounts,
  mutationFromCounts,
  perfFromSamples,
  testCountFromCategories,
} from '@kiwa-test/quality-metrics';

const report = assembleReport({
  provider: '@kiwa-test/auth', // non-AI prefix → 7-axis branch
  version: '0.3.0',
  coverage: coverageFromV8Summary(covSummary.total),
  testCount: testCountFromCategories({ behavior: 236, integration: 8, e2e: 0 }),
  fidelity: fidelityFromMethodCounts({ mockCoveredMethods: 42, realTotalMethods: 60 }),
  perf: perfFromSamples([]),
  mutation: mutationFromCounts({ mutations: 200, killed: 130 }),
});
const verdict = evaluateReleaseGate(report);
// verdict.axesEvaluated === 7 — behaviour identical to v1.11
```

### AI-LLM report — 11-axis diff (v1.11 → v1.12)

AI-LLM providers must add `cost` / `latency` / `token` / `accuracy` to the `assembleReport` call. Missing fields raise a per-axis blocker.

```diff
 import {
+  accuracyFromSamples,
   assembleReport,
+  costFromSamples,
   coverageFromV8Summary,
   evaluateReleaseGate,
   fidelityFromMethodCounts,
+  latencyFromSamples,
   mutationFromCounts,
   perfFromSamples,
   testCountFromCategories,
+  tokenFromSamples,
 } from '@kiwa-test/quality-metrics';

 const report = assembleReport({
-  provider: '@kiwa-test/auth',
+  provider: '@kiwa-test/ai-llm', // AI-LLM prefix → 11-axis branch
-  version: '0.3.0',
+  version: '0.1.0',
   coverage: coverageFromV8Summary(covSummary.total),
   testCount: testCountFromCategories({ behavior: 30, integration: 8, e2e: 3 }),
   fidelity: fidelityFromMethodCounts({ mockCoveredMethods: 42, realTotalMethods: 60 }),
   perf: perfFromSamples(latencyMs),
   mutation: mutationFromCounts({ mutations: 200, killed: 130 }),
+  cost: costFromSamples(costSamplesUsd),
+  latency: latencyFromSamples(endToEndLatencyMs),
+  token: tokenFromSamples({ promptTokens, completionTokens }),
+  accuracy: accuracyFromSamples({ samples: cosineSims, method: 'cosine' }),
 });
 const verdict = evaluateReleaseGate(report);
+// verdict.axesEvaluated === 11 — new AI-LLM branch enforced
```

### Shortcut — `buildAiLlmReport` from `runFidelityCheck`

If you use `runFidelityCheck` (the harness that diffs real vs mock across a prompt set), `buildAiLlmReport` fills the 4 AI-LLM axes from the fidelity result without hand-wiring `cost` / `latency` / `token` / `accuracy` samples:

```ts
import { buildAiLlmReport, createAnthropicMock, runFidelityCheck } from '@kiwa-test/ai-llm';
import { evaluateReleaseGate, emitMarkdown } from '@kiwa-test/quality-metrics';

const mock = createAnthropicMock({
  responses: { 'ping': { content: 'pong' } },
});
const fidelity = await runFidelityCheck({
  mock,
  real: async (input) => realAnthropicCompletion(input),
  prompts: [{ messages: [{ role: 'user', content: 'ping' }] }],
});

const report = buildAiLlmReport({
  provider: '@kiwa-test/ai-llm',
  version: '0.1.0',
  fidelity,
  testCount: { behavior: 20, integration: 5, e2e: 3 },
  coverageV8Summary: c8Summary.total,
  mutation: { mutations: 200, killed: 160 },
  perfSamplesMs: benchSamples,
});
const verdict = evaluateReleaseGate(report);
console.log(emitMarkdown({ report, verdict }));
```

## Default thresholds — AI-LLM 4 axes

| axis | threshold | comparison | rationale |
|---|---|---|---|
| `cost.perRequestUsd` | $0.10 | ≤ | Claude Haiku / gpt-4o-mini price band; guards against cost blow-ups in bulk calls |
| `latency.p95Ms` | 3000 ms | ≤ | Streaming LLM "user-facing 3-second bar" |
| `token.totalTokens` | 4000 | ≤ | 4k-context model default; detects context bloat |
| `accuracy.score` | 0.80 | ≥ | Embedding cosine similarity 0.80 = "semantically close" bar |

Overrides live in `evaluateReleaseGate(report, { costPerRequestUsd: 0.5, ... })`. Any override must be justified in the provider PR body (per `docs/quality/release-gate.md` § overrides の運用).

## Adopt the AI-LLM mocks (optional, per SDK)

Pick the mock that matches your provider SDK. Every mock exposes the same `AiLlmMock` shape (`getMetrics()`, `reset()`) and returns responses shaped like the real SDK.

```ts
// Anthropic Messages API
import { createAnthropicMock } from '@kiwa-test/ai-llm';
const claude = createAnthropicMock({
  responses: { 'What is kiwa?': { content: 'kiwa is a testing harness.' } },
});
```

```ts
// OpenAI Chat Completions
import { createOpenAIMock } from '@kiwa-test/ai-llm';
const oai = createOpenAIMock({
  responses: { 'ping': { content: 'pong' } },
});
```

```ts
// Vercel AI SDK
import { createVercelAiMock } from '@kiwa-test/ai-llm';
const vai = createVercelAiMock({
  responses: { 'greet': { content: 'hello world', chunks: ['hello ', 'world'] } },
});
```

```ts
// LangChain
import { createLangchainMock } from '@kiwa-test/ai-llm';
const lc = createLangchainMock({
  responses: { 'summarize kiwa': { content: 'kiwa provides mocks for testing.' } },

```

## Follow the AI-LLM dogfood pattern (optional)

If you maintain an AI-LLM provider, mirror the v1.12 dogfood layout:

```
examples/dogfood-<provider>-app/
├── src/
│   ├── adapters/
│   │   ├── interface.ts    (provider-neutral flow contract + TraceEvent)
│   │   ├── mock.ts         (kiwa mock adapter with per-turn / per-question banks)
│   │   └── real.ts         (real provider with graceful skip when env missing)
│   └── flows/
│       ├── <domain>-flows.ts   (3-5 flows exercising the provider)
│       └── fidelity.ts     (trace diff + buildAiLlmReport call)
└── tests/
    ├── e2e-mock-mode.test.ts        (mock-mode end-to-end tests)
    ├── fidelity-report.test.ts      (harness contract tests)
    └── emit-fidelity-report.test.ts (writes quality-report/fidelity-latest.md)
```

The three v1.12 dogfood apps demonstrate the pattern for streaming + tool_use (`dogfood-anthropic-chatbot`), function calling + parallel tool calls (`dogfood-openai-tool-agent`), and RAG (`dogfood-vercel-ai-rag`).

## Verification

```bash
pnpm test                                    # every v1.11 test still passes (7-axis reports unchanged)
pnpm -F @kiwa-test/quality-metrics test      # gate harness self-tests (7 + 11 axis branches)
pnpm -F @kiwa-test/ai-llm test               # 4 SDK mocks + fidelity harness self-tests
pnpm --filter dogfood-anthropic-chatbot test  # AI-LLM dogfood 1
pnpm --filter dogfood-openai-tool-agent test  # AI-LLM dogfood 2
pnpm --filter dogfood-vercel-ai-rag test      # AI-LLM dogfood 3
```
