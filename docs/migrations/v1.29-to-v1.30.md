# Migration guide — v1.29 → v1.30

v1.30 is **additive** — every `@kiwa-lab/*` package public API that existed in v1.29 keeps its surface. Existing tests keep passing without touching a single line. The v1.30 changes are pure additions on the a11y horizontal sweep axis (axe-core WCAG 2.1 AA + 4-tier threshold + 3-layer harness + 13th release-gate axis).

The 5 things v1.30 adds are.

- `@kiwa-lab/a11y` v1.1 — 3-layer harness (`runLayerHarness` / `bucketViolations` / `unionByRule` / `computeTotals` / `isHarnessOk` / `summariseHarness`) layered on top of the v1.0 `runAxe` + `reportViolations` + `expectNoViolations` primitives. jsdom + Playwright + SSR-hydration violations are unioned by rule id with provenance, so an SSR-only rule and a hydration-only rule surface separately in the baseline JSON.
- `@kiwa-lab/quality-metrics` v0.4 — 4-tier a11y threshold SSOT (`DEFAULT_A11Y_TIER_THRESHOLDS` + `resolveA11yTier` + `assertA11yTier` + `A11yMetric` + `A11yTier` types + opt-in 13-axis `evaluateReleaseGate({ a11yTier })` third-argument context field), backward-compat with every v1.11-1.29 consumer. The 12-axis path from v1.27 (`{ mutationTier }`) still works — v1.30 adds a new axis, not a replacement.
- 34 package `.axe-config.mjs` + `.a11y-baseline/{pkg}.json` + `test:a11y` script (v1.30-1 through v1.30-3) — every `@kiwa-lab/*` package plus `release-invariants` now ships an axe-core config, a persisted baseline, and a workspace `test:a11y` script hooked into `pnpm -r --filter '@kiwa-lab/*' test:a11y`. The 4-tier SSOT (`docs/quality/a11y-thresholds.md`) pins each package to Core / Framework / SaaS / Test type with a documented reason.
- 2 new tutorials (56 a11y baseline walkthrough + 57 a11y baseline migration methodology) + 1 concept doc SSOT (`a11y-testing-ssot.md` — WCAG 2.1 AA + 4-tier threshold + baseline persistence + regression detection + 3-layer harness + jsdom vs Playwright vs SSR-hydration nuances) + 1 migration guide (this file) + 1 snippet validation test (`packages/a11y/tests/docs-tutorial-v1.30.test.ts`) — 8-milestone snippet validation streak (v1.23 → v1.30). All wired through the sidebar (`docs/.vitepress/config.mts`).
- 1 new release-gate axis (`a11y.tier`, 13th in the 12-axis lineup after v1.27) + `scripts/check-a11y-gates.mjs` (34-row `A11Y_PACKAGE_TIER` map + reads each package's `.a11y-baseline/{pkg}.json`) + dogfood 3 app integration (v1.28-2/3/4 realtime dogfood apps now surface their a11y baseline through the same 13-axis path).

## What's new (opt in)

### `@kiwa-lab/a11y` v1.1 — 3-layer harness

Install the package.

```bash
pnpm add -D @kiwa-lab/a11y@^1.1 axe-core jsdom
```

Import the harness.

```ts
import {
  runLayerHarness,
  computeTotals,
  isHarnessOk,
  summariseHarness,
  type HarnessReport,
  type HarnessFixtures,
} from '@kiwa-lab/a11y';
```

Use it in your own audit.

```ts
import { describe, expect, it } from 'vitest';
import { runLayerHarness } from '@kiwa-lab/a11y';

describe('my component — 3-layer a11y', () => {
  it('all 3 layers pass', async () => {
    document.body.innerHTML = '<div id="host"><button>click</button></div>';
    const host = document.getElementById('host')!;

    const report = await runLayerHarness('my-component', {
      jsdom: {
        context: host,
        runOptions: {
          runOnly: { type: 'tag', values: ['wcag2a', 'wcag2aa', 'wcag21a', 'wcag21aa'] },
        },
      },
    });

    expect(report.ok).toBe(true);
    expect(report.totals.critical).toBe(0);
  });
});
```

The 3 layers are pure — jsdom fixture is a synchronous DOM subtree the harness wraps around a `document.body` attach / detach cycle so axe-core sees an attached element regardless of what the caller supplied (fixes the "No elements found for include in page Context" that bit the v1.30-2 review). Playwright fixture is the `page.evaluate(() => axe.run(...))` result the caller has already computed. SSR-hydration fixture is a `ssrHtml` string plus an optional `hydrated` Element — violations are unioned by rule id with provenance recorded per layer.

### `@kiwa-lab/quality-metrics` v0.4 — 4-tier a11y threshold

Install the package.

```bash
pnpm add -D @kiwa-lab/quality-metrics@^0.4
```

Import the tier helpers.

```ts
import {
  a11yFromBaseline,
  assertA11yTier,
  resolveA11yTier,
  DEFAULT_A11Y_TIER_THRESHOLDS,
  evaluateReleaseGate,
  type A11yMetric,
  type A11yTier,
} from '@kiwa-lab/quality-metrics';
```

Use them in your own release gate.

```ts
const metric = a11yFromBaseline({
  totals: { critical: 0, serious: 0, moderate: 0, minor: 2 },
});
assertA11yTier({ metric, tier: resolveA11yTier('SaaS') });
```

The 4-tier default is `Core 0/0/3` / `Framework 0/3/10` / `SaaS 0/0/0` / `Test type 0/3/10` — mirrors the SSOT table in `docs/quality/a11y-thresholds.md` verbatim. `critical: 0` is a `A11yThreshold` TypeScript literal — no override can raise it above 0.

### 13th release-gate axis — opt-in `a11yTier` context field

`evaluateReleaseGate(report, thresholdOverrides, context)` grows a new optional context field.

```ts
const verdict = evaluateReleaseGate(report, {}, {
  mutationTier: 'saas',    // v1.27 opt-in (12th axis)
  a11yTier: 'saas',        // v1.30 opt-in (13th axis)
});
```

The verdict `axesEvaluated` count grows by 1 per opt-in — a report with both `mutationTier` and `a11yTier` set on a non-AI-LLM provider evaluates 9 axes total (7 legacy + 1 mutation.tier + 1 a11y.tier). Missing `report.a11y` when `a11yTier` is set yields a `Number.POSITIVE_INFINITY` fallback so the gate fails safe — a silent "no a11y data" pass is impossible by construction.

### `scripts/check-a11y-gates.mjs` — 34-row PACKAGE_TIER map

Landed in v1.30-4. Enumerates the tier + optional override for every publishable package. `scripts/run-axe-baseline.mjs` reads `.axe-config.mjs`, executes the 3-layer harness, and writes `.a11y-baseline/{pkg}.json`; `scripts/check-a11y-gates.mjs` reads the baseline totals + the `PACKAGE_TIER` row and asserts the ceiling. Both scripts are Node-only pure functions with no vitest / kiwa dependency at runtime — downstream monorepos can copy them verbatim.

## Publishing your own a11y baseline

The 4-tier ceiling is the SSOT for kiwa, but the pattern generalises. A downstream monorepo can wrap the `runLayerHarness` + `a11yFromBaseline` + `assertA11yTier` helpers with its own `PACKAGE_TIER` source (e.g. Turborepo, Nx, Lerna) and get the same fail-fast semantics.

- **Source the tier per package** — a static map in a script, or a `.axe-config.mjs` header comment the runner parses.
- **Source the fixtures** — jsdom fixture is any Element / Document / selector; Playwright fixture is any pre-computed `axe.run()` result; SSR-hydration fixture is any SSR HTML string.
- **Source the baseline path** — `.a11y-baseline/{pkg}.json` is the convention; commit the file to lock the a11y envelope into the repo.
- **Assert** — pass the tier + the baseline totals to `assertA11yTier` and expect no throw.

## FAQ

- **Do I need to migrate existing test suites?** No. v1.30 is opt-in. Existing suites keep working with zero changes.
- **What about `@kiwa-lab/quality-metrics` v0.3 consumers?** Backward compat. The 12-axis path (`{ mutationTier }`) still works. The 13-axis path adds a new context field without touching the existing one.
- **Can I use the a11y baseline outside kiwa?** Yes. `runLayerHarness` + `a11yFromBaseline` + `assertA11yTier` are pure functions with no kiwa-specific dependency at runtime. Any pnpm monorepo can call them.
- **What if my package has DOM output but no browser?** Use the jsdom fixture only. `.axe-config.mjs` records `playwright.applicable: false` and the tier gate reads the jsdom violations verbatim. This is the common case for SSR-only packages.
- **What if `critical > 0` on a package I need to ship?** The `A11yThreshold` type literal enforces `critical: 0` — the release gate refuses to pass. Fix the violation before shipping; there is no override path. The whole tier system is set up so that critical is never negotiable.
