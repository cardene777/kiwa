# Migration guide — v2.18 → v2.19

`@kiwa-lab/spec-kit` has been renamed to `@kiwa-lab/kaname`.

## Why

`github/spec-kit` is a widely known toolkit for spec-driven development with over 118,000 stars. Publishing a package with the same name in the same problem space guarantees confusion: search results collide, and every mention needs a disclaimer.

The old package was published on 2026-07-09 and had no downstream users, so the rename happens before anyone depends on it.

## The new name

`kaname` (要) is the pivot rivet of a folding fan. Every rib of the fan is fastened to that single point.

The package binds three modules into one flow: `spec` classifies specification items, `tracker` connects to issue trackers, and `flow` records and checks each step. The pivot metaphor matches the structure exactly. The English word is `keystone`.

## What changes

```diff
- pnpm add -D @kiwa-lab/spec-kit
+ pnpm add -D @kiwa-lab/kaname
```

```diff
- import { classify, splitSpec } from '@kiwa-lab/spec-kit';
+ import { classify, splitSpec } from '@kiwa-lab/kaname';
```

The Claude Code skill is renamed from `/spec-kit` to `/kaname`.

Every exported symbol keeps its name. `classify`, `splitSpec`, `SpecLayer`, `SpecItem`, `SpecDoc`, `SplitResult`, `ClassifyIssue`, and `ClassifyReport` are unchanged. Only the package specifier moves.

## What stays

The three-layer specification model is untouched. Items are still classified as `formal`, `runtime`, or `human`, and the five static rules still reject a specification that lets the same verification target straddle two layers.

## Deprecation

`@kiwa-lab/spec-kit@0.1.0` is deprecated on the npm registry with a pointer to `@kiwa-lab/kaname`. It will not receive further releases.
