# Migration guide — v1.23 → v1.24

v1.24 is **additive** — every `@kiwa/*` package public API that existed in v1.23 keeps its surface. Existing tests keep passing without touching a single line.

The 5 things v1.24 adds are.

- `@kiwa/edge` v0.2 layers **8 axes of advanced edge semantics** on top of the v0.1 `fetch` handler + KV / R2 / D1 / DurableObject minimal mocks (Durable Object / WebSocket edge / edge KV / geo-replicated / Cron trigger / subrequest limit / CPU time limit / streaming Response). Platform-neutral state machines + strict transition guards land in `packages/edge/src/semantics/*`.
- 3 dogfood edge apps — `dogfood-cloudflare-workers-durable-object-app` (realtime chat + Hibernation API + storage transactional + WebSocket edge broadcast), `dogfood-vercel-edge-function-app` (Next.js 15 middleware + edge runtime + Vercel KV + SSE streaming), `dogfood-deno-deploy-geo-app` (Fresh + Deno KV geo-replicated + Deno Deploy Cron + queue trigger). All three share the same `KIWA_MODE=mock|real-optional|real` switch v1.22 established.
- 3 new tutorials (42 Cloudflare Durable Object + 43 Vercel Edge streaming + 44 Deno Deploy geo), 1 concept doc SSOT (`edge-runtime-testing.md` — 8-axis reference), 1 migration guide (this file). All wired through the sidebar.
- 1 tutorial snippet validation test (`packages/edge/tests/docs-tutorial-v1.24.test.ts`) that re-runs every code snippet in tutorials 42-44 against the real `@kiwa/edge` API — same pattern as `docs-tutorial-v1.21.test.ts` / `docs-tutorial-v1.22.test.ts` / `docs-tutorial-v1.23.test.ts`.
- Sidebar navigation (`docs/.vitepress/config.mts`) — new "Edge/Serverless 深化 (v1.24)" section under Tutorials, `edge-runtime-testing.md` under Concepts, `v1.23 → v1.24` under Migrations.

## What breaks (nothing)

Nothing. The v1.24 changes are pure additions.

- `@kiwa/edge` v0.1 surface (`invokeEdgeHandler` / `createKvNamespace` / `EdgeFetchHandler` / `EdgeEnvBindings` / `InvokeEdgeHandlerOptions` / `InvokeEdgeHandlerResult` / `SimulatedExecutionContext`) — unchanged. v0.2 adds the `semantics/*` module tree alongside the existing surface. Every prior signature keeps its shape.
- Every prior `@kiwa/*` package (auth / streaming / solidjs / fresh / hono / observability v2 / component / realtime / ai-llm / mcp / agent / perf-harness / quality-metrics / search / dapp / payment) — untouched.
- `evaluateReleaseGate` — same 11-axis contract as v1.17-v1.23. v1.24 introduces no new release-gate axes.
- Every prior tutorial 01-41, migration guide v1.9→v1.23, concept doc — unchanged. v1.24 only appends tutorial 42-44 + concept `edge-runtime-testing.md` + migration `v1.23-to-v1.24.md`.
- Every prior dogfood app (v1.23 payment apps, v1.22 auth apps, v1.20 streaming apps, v1.19 framework apps, etc.) — untouched. v1.24 adds 3 new dogfood edge apps alongside; nothing is removed or renamed.

## What's new (opt in)

### `@kiwa/edge` v0.2 — 8-axis advanced edge semantics

The v0.1 `fetch` handler + KV / R2 / D1 mocks stay the first-line contract. v0.2 layers 8 axes of edge state on top so tests exercise the full envelope real platforms converge on. Every axis operates on the same neutral `EdgePlatform` union (`'cloudflare' | 'vercel' | 'deno'`) — swap the platform and the tests re-run against a different runtime without touching the axis bodies.

The 8 axes are.

- **Durable Object** — Cloudflare Durable Objects (and their session-affine analogues). State machine `initialized` → `active` (loops on request / alarm / storage-write) with a transactional storage guarantee. Default fires 4 neutral events (`durable-object.created` / `durable-object.requested` / `durable-object.alarm-fired` / `durable-object.storage-written`).
- **WebSocket edge** — edge WebSocket lifecycle. `pending` → `open` → `closed`, 4 neutral events (`websocket.upgrade-requested` / `websocket.accepted` / `websocket.message` / `websocket.closed`).
- **Edge KV** — read-through per-POP cache. 4 neutral events (`kv.read` / `kv.write` / `kv.cache-hit` / `kv.cache-miss`). Consistency states = `consistent` (Deno KV primary) / `eventually-consistent` (Cloudflare KV, Vercel Edge Config, Deno KV replicas).
- **Geo-replicated** — primary + N replicas that catch up asynchronously. `in-sync` → `lagging` → `in-sync` (only when every replica lag returns to 0) / `conflict-detected` → `in-sync`. 4 neutral events (`geo.primary-write` / `geo.replica-lagged` / `geo.replica-synced` / `geo.conflict-resolved`).
- **Cron trigger** — scheduled invocation lifecycle. `scheduled` → `running` → `completed` / `failed` (with retry back to `scheduled` until `maxRetries` exhausted). `triggerType` = `scheduled` / `queue` / `email`. Default `maxRetries: 3`. 4 neutral events (`cron.scheduled` / `cron.started` / `cron.completed` / `cron.failed`).
- **Subrequest limit** — per-invocation outbound fetch budget. `ok` → `approaching-limit` → `limited`. Default `limit: 50` (Workers free plan) + `warningThreshold: 40`. 4 neutral events (`subrequest.started` / `subrequest.counted` / `subrequest.limited` / `subrequest.completed`).
- **CPU time limit** — per-invocation compute budget. `idle` → `running` → `warning` → `throttled` / `completed`. Default `budgetMs: 50` + `warningAtMs: 40`. 4 neutral events (`cpu.started` / `cpu.budget-warning` / `cpu.limited` / `cpu.completed`).
- **Streaming Response** — chunked / SSE / websocket body delivery with backpressure. `open` → `backpressure` (when `bytesSent > highWaterMark`) → `open` (on `resumeStream`) → `closed`. Default `kind: chunked`, `highWaterMark: 65536`. 4 neutral events (`stream.opened` / `stream.chunk-sent` / `stream.backpressure` / `stream.closed`).

Concrete usage.

```ts
// v0.2 durable-object axis — Cloudflare Durable Objects envelope
import {
  createDurableObject,
  requestDurableObject,
  fireAlarm,
  writeStorage,
} from '@kiwa/edge';

const room = createDurableObject({ id: 'room-1', platform: 'cloudflare' });
requestDurableObject(room, { url: 'https://edge/room-1/join' });
writeStorage(room, { key: 'last-message', value: 'hello' });
fireAlarm(room);
// room.history has 4 AxisStep entries with neutralEvent + platformEvent + state.
```

The full 8-axis catalogue lives in [`docs/concepts/edge-runtime-testing.md`](../concepts/edge-runtime-testing).

- **`examples/dogfood-deno-deploy-geo-app`** (Deno Fresh) — multi-region write + read-your-writes + Deno Deploy Cron + queue trigger. 8-op surface (3 `geo-replicated` + 2 `edge-kv` + 3 `cron-trigger`), fidelity harness diffs mock-vs-real traces, `KIWA_MODE=real` swaps to real Deno Deploy sandbox with `DENO_DEPLOY_KEY=1`.

## Upgrade path

Bump the dependency and start using the axes.

```bash
pnpm add -D @kiwa/edge@^0.2
```

Existing v0.1 tests keep passing. New tests can import the 8-axis semantics from the same package.

```ts
// v0.1 — still works
import { invokeEdgeHandler, createKvNamespace } from '@kiwa/edge';

// v0.2 — new axes
import {
  createDurableObject, requestDurableObject, fireAlarm, writeStorage,
  requestWebSocketUpgrade, acceptWebSocket, sendMessage, closeWebSocket,
  createEdgeKvSession, kvRead, kvWrite, kvRangeQuery,
  createGeoReplicatedSession, geoPrimaryWrite, markReplicaLagged, syncReplica, resolveConflict,
  scheduleCron, startCron, completeCron, failCron,
  startSubrequestBudget, startSubrequest, countSubrequest, completeSubrequest, remainingBudget,
  startCpuBudget, startCpu, tickCpu, completeCpu,
  openStream, sendChunk, resumeStream, closeStream,
} from '@kiwa/edge';
```
