## What's new (opt in)

### `@kiwa-test/security` v0.1.0 — 8 axis + 4 provider fidelity harness

Install the package.

```bash
pnpm add -D @kiwa-test/security@^0.1
```

Import the axis you need directly through the top-level barrel — every v0.1 function is re-exported through the package root.

```ts
import {
  buildCspHeader,
  createRbacPolicy,
  evaluateAbac,
  evaluateCombined,
  evaluateLicense,
  isKiwaModeReal,
  lookupAdvisories,
  rbacAllows,
  resolveRealtimeDriver,
  runSecurityFidelityCheck,
  scanSecrets,
  scoreDread,
  SECURITY_FIDELITY_GRID,
  skipUnlessReal,
  toCycloneDx,
  toSpdx,
  validateNonce,
  validateSbom,
} from '@kiwa-test/security';
```

The v0.1 functions cover every axis (CSP / Rate limit / Authorization / WAF / Threat model / Secrets scan / SBOM / Security headers advanced) plus the fidelity harness (`runSecurityFidelityCheck` + `SECURITY_FIDELITY_GRID`).

Use it in your own test.

```ts
import { describe, expect, it } from 'vitest';
import {
  buildCspHeader,
  createRbacPolicy,
  rbacAllows,
} from '@kiwa-test/security';

describe('my api — csp regression', () => {
  it('csp emits strict-dynamic when a nonce is present', () => {
    const out = buildCspHeader({
      directives: { 'script-src': ["'self'"] },
      nonces: [{ nonce: 'AAAAAAAAAAAAAAAAAAAAAA' }],
      strictDynamic: true,
    });
    expect(out.headerValue).toContain("'strict-dynamic'");
  });

  it('rbac denies a permission the subject does not hold', () => {
    const policy = createRbacPolicy([
      { name: 'viewer', permissions: ['read:articles'] },
    ]);
    expect(
      rbacAllows(
        policy,
        { id: 'guest', roles: ['viewer'] },
        'delete:articles',
      ),
    ).toBe(false);
  });
});
```

The full API surface — 5-7 functions per axis × 8 axes ≈ 50 new state-machine transitions — is spelled out in tutorials 76 (CSP + nonce + hash + strict-dynamic + trusted-types + report-only), 77 (RBAC + role hierarchy + ABAC combining + combined RBAC + ABAC), 78 (CycloneDX + SPDX + advisory lookup + license policy + secrets scan + rotation SLA). The 4 target adapters (helmet / express-rate-limit / casbin / coraza) all cover all 8 axes.

### `SECURITY_FIDELITY_GRID` — 4 provider × 8 axis grid

The fidelity harness describes which provider covers which axis and what neutral event + provider dialect each axis emits.

```ts
import { SECURITY_FIDELITY_GRID } from '@kiwa-test/security';

console.log(SECURITY_FIDELITY_GRID.length); // 32 (4 provider × 8 axis)

const helmetCsp = SECURITY_FIDELITY_GRID.find(
  (r) => r.provider === 'helmet' && r.axis === 'csp',
);
console.log(helmetCsp);
// { provider: 'helmet', axis: 'csp' }
```

Every one of the 32 rows names a provider + axis pair. Tests iterating the grid pick the pair they cover and run the fidelity harness on it (`runSecurityFidelityCheck({ provider, axis, realDriver, mockDriver, scenarios })`) — the harness returns a per-scenario accuracy score that ties the real driver output back to the mock output.

### `KIWA_MODE=real` — env-gated real driver run

The mock path stays the default. When `KIWA_MODE=real` is set, the harness assertions also try to run against the real driver, gated by the required env for that provider.

- **helmet** → `KIWA_MODE` only (helmet is Node-in-process, no external service needed)
- **express-rate-limit** → `KIWA_MODE` + `KIWA_REDIS_URL` (real Redis-backed distributed rate limiter)
- **casbin** → `KIWA_MODE` + `KIWA_CASBIN_POLICY_PATH` (real casbin policy file path)
- **coraza** → `KIWA_MODE` + `KIWA_CORAZA_RULES_PATH` (real coraza / OWASP CRS rule file path)

Absent env means silently fall back to mock mode. This is the same env-gate contract the v1.22 real-driver testing tutorial (auth adapters + Keycloak), the v1.31 streaming real-driver concept doc, the v1.32 database real-driver concept doc, the v1.33 payment real-driver concept doc, the v1.34 frontend real-driver concept doc, the v1.35 observability real-driver concept doc, and the v1.36 search real-driver concept doc all use — v1.37 layers 3 more `_URL` / `_PATH` env-gates onto the same pattern.

## Snippet validation — 15 milestone streak

`packages/security/tests/docs-tutorial-v1.37.test.ts` — every code snippet in tutorials 76-78 is behavior-tested. If the security API surface drifts, the snippet test fails before the tutorial hits a reader.

The streak is now 15 milestones (v1.23 → v1.37) — each milestone lands a `docs-tutorial-v{version}.test.ts` in its package of record with `describe('tutorial N — {topic}')` blocks that mirror the tutorial code. This is the pattern kiwa uses to keep the docs from drifting silently; 15 consecutive milestones with the pattern makes it the default rather than the exception.

## No release-gate axis change

v1.37 does not add a 14th release-gate axis. The 8 security axes gate the security package's own tests (via `pnpm --filter @kiwa-test/security test`) but do not surface as a per-package `quality-metrics` axis. The reason is that the fidelity harness is provider-shape-specific — a package that does not export to helmet / express-rate-limit / casbin / coraza has nothing to assert on. When a future milestone adds a `security.fidelity` axis that describes "which security providers this package's tests hit," it will slot into the 13-axis release gate as the 14th; v1.37 keeps things simple.
