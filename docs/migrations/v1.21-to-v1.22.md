# Migration guide — v1.21 → v1.22

v1.22 is **additive** — every `@kiwa-lab/*` package public API that existed in v1.21 keeps its surface. Existing tests keep passing without touching a single line.

The 4 things v1.22 adds are.

- `@kiwa-lab/auth` v0.5 layers **real driver adapters** on top of the v1.21 4 protocol mocks — Keycloak testcontainers wiring for OIDC + Federation, oauth2-mock-server testcontainers for OAuth 2.1, Chrome caBLE hybrid transport for Passkey. Mocks stay the first-line contract; real drivers become the second-line fidelity check.
- 3 dogfood app upgrades (`dogfood-oidc-federation` full Nuxt 3 RP flow + a11y axe-core gate; `dogfood-oauth21-provider` oauth2-mock-server real driver + /authorize §4.1.2.1 redirect fix; `dogfood-webauthn-passkey-app` caBLE hybrid transport 5-axis harness) landing the real driver + a11y + caBLE surfaces.
- 2 new tutorials (37 real driver testing + 38 Passkey caBLE flow), 1 concept doc SSOT (`real-driver-testing.md`), 1 migration guide (this file). All covering the 3 execution modes (`mock only` / `real-optional` / `real-required`) end-to-end.

## What's new (opt in)

### `@kiwa-lab/auth` v0.5 — real driver adapters

The v1.21 4 protocol mocks stay the first-line contract. v1.22 layers testcontainers-backed real drivers on top so tests can dual-run mock + real and record a **fidelity report** — the release gate flags drift.

The 3 execution modes are.

- `mock only` (default, `KIWA_MODE` unset) — pure `@kiwa-lab/auth` mock, 0 network, ~1 ms per test. This is what every PR runs. Zero regression to the v1.21 latency budget.
- `real-optional` (`KIWA_MODE=real-optional`) — try the real driver; fall back to mock with a warning when the container URL is missing. Laptop-friendly.
- `real-required` (`KIWA_MODE=real` + protocol-specific env) — fail hard if the driver is missing; run only against the live container. Nightly CI + pre-release smoke.

Concrete usage.

```ts
// Real driver — Keycloak testcontainer (from tests/setup-keycloak.ts)
import { GenericContainer } from 'testcontainers';
import { setupOidcEnv } from '@kiwa-lab/auth';

const container = await new GenericContainer('quay.io/keycloak/keycloak:26.0')
  .withCommand(['start-dev', '--http-port=8080'])
  .withExposedPorts(8080)
  .start();

const url = `http://${container.getHost()}:${container.getMappedPort(8080)}`;

// Same setupOidcEnv API as v1.21, plus a `realDriver` option pointing at the Keycloak URL.
const env = await setupOidcEnv({
  issuer: `${url}/realms/kiwa-test`,
  clients: [{ clientId: 'rp-A', redirectUris: ['https://rp.example.test/cb'], scopes: ['openid'] }],
  users: [{ subject: 'user-1', scopes: ['openid'] }],
  realDriver: { keycloakUrl: url, realm: 'kiwa-test' },
});
```

The `realDriver` option is new in v0.5. When present + `KIWA_MODE=real`, the env drives the real Keycloak REST API. When absent OR `KIWA_MODE` unset, the env falls back to the pure mock — the exact v1.21 behaviour.

### Passkey caBLE hybrid transport (v1.22-4)

v1.22 ships 6 top-level caBLE helpers alongside `setupPasskeyEnv` for CTAP 2.2 hybrid transport.

```ts
import {
  establishWebSocketTunnel,
  generateCaBLEQRCode,
  migrateCredential,
  performBLEHandshake,
  performSignatureRoundtrip,
  runCaBLESession,
  setupPasskeyEnv,
} from '@kiwa-lab/auth';

const env = await setupPasskeyEnv({
  devices: [
    { deviceId: 'phone-A', platform: { biometric: 'touch-id' } },
    { deviceId: 'laptop-A', roaming: { transport: 'hybrid' } },
  ],
});
const credential = await env.createPasskey('phone-A', 'user-1', { rp, user, challenge });

// v1.22 new helpers — 5 step ceremony
const qr = generateCaBLEQRCode({
  initiatorDeviceId: 'laptop-A',
  responderDeviceId: 'phone-A',
  credential,
  tunnelServerHint: 'wss://cable.example.test/tunnel/xyz',
  nonce: 'nonce-1',
});
const handshake = performBLEHandshake(qr);
const tunnel = establishWebSocketTunnel(qr, handshake);
const migration = migrateCredential(tunnel, credential);
const roundtrip = performSignatureRoundtrip(tunnel, credential, 'rp-challenge-1');

// composite — chain the 5 steps in one call
const session = runCaBLESession(
  {
    initiatorDeviceId: 'laptop-A',
    responderDeviceId: 'phone-A',
    credential,
    tunnelServerHint: 'wss://cable.example.test/tunnel/xyz',
    nonce: 'nonce-2',
  },
  'rp-challenge-2',
);
```

Each helper is pure — no browser, no BLE stack, no real WebSocket. The 5-axis fidelity harness (tutorial 38) verifies the mock matches Chrome's real caBLE behaviour axis by axis.
