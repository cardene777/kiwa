# Migration guide — v1.24 → v1.25

v1.25 is **additive** — every `@kiwa-test/*` package public API that existed in v1.24 keeps its surface. Existing tests keep passing without touching a single line. The v1.25 changes are pure additions on the perf-harness axis.

The 5 things v1.25 adds are.

- `@kiwa-test/perf-harness` v0.2 stays API-compatible with v0.1 (`measure` / `saveBaseline` / `loadBaseline` / `detectRegression` / `evaluatePerfGate` / `runPerf3Layer` unchanged). v0.2 is a **coverage extension**, not a surface extension — every one of the 33 kiwa packages now ships a `tests/perf/{package}.perf.ts` suite + a `test:perf` script + a `.perf-baseline/{package}.json`.
- 4 sub-milestone perf sweeps (v1.25-1 core layer 9 package / v1.25-2 framework adapter 11 package / v1.25-3 test type 3 package / v1.25-4 SaaS layer 10 package). Every sweep uses the same `runPerf3Layer` primitive from v1.14-post, the same 3 warmup + 100 iteration + 20 % threshold SSOT (`docs/concepts/perf-testing-ssot.md`).
- 2 new tutorials (45 perf-harness baseline walkthrough + 46 perf baseline migration methodology), 1 concept doc SSOT (`perf-testing-ssot.md` — p50 / p95 / p99 + baseline persistence + regression detection + 3-layer harness reference), 1 migration guide (this file). All wired through the sidebar.
- 1 tutorial snippet validation test (`packages/perf-harness/tests/docs-tutorial-v1.25.test.ts`) that re-runs every code snippet in tutorials 45-46 against the real `@kiwa-test/perf-harness` API — same pattern as `docs-tutorial-v1.21.test.ts` through `docs-tutorial-v1.24.test.ts`.
- Sidebar navigation (`docs/.vitepress/config.mts`) — new "Perf-harness sweep (v1.25)" section under Tutorials, `perf-testing-ssot.md` under Concepts, `v1.24 → v1.25` under Migrations.

## What's new (opt in)

### `@kiwa-test/perf-harness` v0.2 — 33 package perf coverage

The v0.1 `measure` + `saveBaseline` + `detectRegression` primitives stay the first-line contract. v0.2 is a **rollout** — every kiwa package now has a `tests/perf/{package}.perf.ts` suite. The suites use `runPerf3Layer` (v1.14-post) to gate three axes in one call.

- **serial** — `measure` at concurrency 1, 200 iterations, 5 warmup. Baseline latency floor.
- **concurrent** — `measureConcurrent` at concurrency 10, 50 iterations per worker (500 total). Contention detector.
- **memory** — `measureMemory` at 200 iterations, gate on `arrayBuffersDelta`. Leak detector.

The 33 package sweep breaks down by layer.

- **core (9)** — `@kiwa-test/{core, dapp, api, ui, data, cli-test, observability, e2e, cli}`
- **framework adapter (11)** — `@kiwa-test/{nextjs, nuxt, sveltekit, remix, astro, solidstart, qwikcity, edge, fresh, hono, solidjs}`
- **test type (3)** — `@kiwa-test/{a11y, visual, component}`
- **SaaS layer (10)** — `@kiwa-test/{auth, queue, cache, orm, payment, streaming, search, mcp, agent}` + provider-specific baselines (auth 6+4, queue 5, cache 3, payment 3+9, streaming 3×5, etc.)

Concrete usage — the pattern every package follows.

```ts
// packages/my-package/tests/perf/my-package.perf.ts
import { describe, expect, it } from 'vitest';
import path from 'node:path';
import { resolveKiwaRepoRoot, runPerf3Layer } from '@kiwa-test/perf-harness';
import { primaryApi } from '../../src/index.js';

const MODULE = 'my-package';
const REPORT_PATH = path.join(
  resolveKiwaRepoRoot(process.cwd()),
  'docs/quality-reports/perf',
  `${MODULE}.md`,
);

describe(MODULE, () => {
  it('3-layer perf: primaryApi', async () => {
    const result = await runPerf3Layer({
      moduleName: MODULE,
      reportPath: REPORT_PATH,
      ops: [
        { name: 'primaryApi', serialP95CapMs: 5, fn: () => primaryApi() },
      ],
    });
    expect(result.allPassed).toBe(true);
  }, 120_000);
});
```

## Upgrade path

If you consume `@kiwa-test/perf-harness` directly.

```bash
pnpm add -D @kiwa-test/perf-harness@^0.2
```

Existing v0.1 imports keep passing. No new exports to import; the v0.2 upgrade is a coverage rollout, not a surface expansion.

```ts
// v0.1 — still works, no changes required
import {
  measure,
  saveBaseline,
  loadBaseline,
  detectRegression,
  evaluatePerfGate,
  runPerf3Layer,
} from '@kiwa-test/perf-harness';
```

If you fork the kiwa monorepo and want to add a perf suite for a new package, follow the 6-step recipe in [Tutorial 46 — Perf baseline migration](../tutorials/46-perf-baseline-migration).

## Release gate

`evaluateReleaseGate` axis surface is unchanged at v1.25 — same 11 axes as v1.17-v1.24. What v1.25 changes is **coverage**, not surface — the `perf.p95Ms` axis now gets collected on 33 packages instead of 3. No new axis is added, no threshold is changed.
