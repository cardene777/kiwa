# Migration guide — v1.16 → v1.17

v1.17 is **additive** — every `@kiwa/*` package that existed in v1.16 keeps its public API. Existing tests keep passing.

The 4 things v1.17 adds are.

- `@kiwa/observability` v2.0 (4 new axes on top of v1.1 telemetry mocks — `DashboardMock` + `AlertRouter` + `buildSpanTree` / `renderFlameGraph` / `drillDown` + `LogCorrelationIndex`)
- 3 dogfood apps (`dogfood-observability-dashboard` + `dogfood-alert-orchestrator` + `dogfood-trace-flame-graph`) that measure the mock against real Prometheus / AlertManager / Jaeger surfaces
- 3 tutorials, 1 concept doc, 1 migration guide (this file) covering the 4 axes end-to-end
- Fixture builders (3 panel + 3 rule + 3 trace + 1 route + 1 escalation + 1 silence + 1 log-set) so one-call scenario bootstrapping stays realistic

## What breaks (nothing)

Nothing. The v1.17 changes are pure additions.

- `@kiwa/observability` v1.1 exports (`TelemetryCollector` + `createOtelMock` + `createDatadogMock` + `createSentryMock`) — unchanged.
- `@kiwa/component` / `@kiwa/ai-llm` / `@kiwa/mcp` / `@kiwa/agent` / `@kiwa/realtime` / `@kiwa/perf-harness` / `@kiwa/quality-metrics` — unchanged.
- `evaluateReleaseGate` — same 11-axis contract as v1.16. Observability v2 providers (`@kiwa/observability/*` prefix) roll into the common 7-axis branch (coverage / test count / fidelity / perf p95 / mutation). The AI-LLM 4 axes (cost / latency / token / accuracy) do not apply to a metrics / alert / trace surface — there is no token pricing to measure.
- Everything else (auth / queue / cache / realtime / payment / search / polyglot Rust + Go / dApp / framework adapters / docs skills) — untouched.

## What's new (opt in)

### `@kiwa/observability` v2.0 — 4 new axes over the v1.1 collector

The v1.1 `TelemetryCollector` is the SSOT for span / metric / log emission. v2 adds 4 readers over that same collector.

```ts
import {
  AlertRouter,
  DashboardMock,
  LogCorrelationIndex,
  TelemetryCollector,
  buildSpanTree,
  createOtelMock,
  renderFlameGraph,
} from '@kiwa/observability';

const otel = createOtelMock();
const collector = otel.collector;
// SUT emits into `collector` through `otel.tracer` / `otel.meter` / `otel.logger`

// Axis 1 — dashboard render lifecycle
const dashboard = new DashboardMock({ id: 'sre', title: 'SRE', panels: [/* … */] }, collector);
dashboard.refresh();

// Axis 2 — alert lifecycle state machine
const router = new AlertRouter(collector);
router.registerRule({ /* … */ });
router.evaluate();

// Axis 3 — trace aggregation + drill-down
const roots = buildSpanTree(collector.spans);
const flame = renderFlameGraph(roots);

// Axis 4 — log ↔ span bidirectional correlation
const index = new LogCorrelationIndex({ logs: collector.logs, spans: collector.spans });
```

v1.1 provider mocks are the writers; v2 abstractions are the readers. A test that already emits through v1.1 gets v2 assertions for free — the same collector instance passes through.

### Fixture builders — one-call scenario bootstrapping

`fixtures.ts` ships named builders for every v2 axis so realistic scenarios are one import away.

- **Dashboard panels** — `panel_httpErrorRate()`, `panel_p99Latency()`, `panel_queueDepth(id, queue)`
- **Alert rules** — `rule_errorRateCritical()`, `rule_latencyDegraded()`, `rule_queueBackpressure(id, queue)`
- **Routing tree** — `defaultRoute()` (3-level: severity → team → channel)
- **Escalation ladder** — `escalation_pagerDutyTwoStep()` (L1 5 min → L2 15 min)
- **Silence** — `silence_maintenanceWindow(id, minutesFromNow, now)`
- **Trace shapes** — `trace_httpHandler(startAt)`, `trace_fanoutParallel(startAt)`, `trace_nestedRetry(startAt)`
- **Log set** — `logs_forHttpTrace(startAt)` matches the http-handler trace via `trace_id` + `span_id`

Every builder is pure — no side effects, no collector coupling. Callers control when the collector receives data and when the v2 readers evaluate.

### Dogfood apps (3 new, all opt in)

Three examples ship under `examples/`, each producing a real vs mock fidelity report that feeds the 7-axis release gate.

- `dogfood-observability-dashboard` — 5 panels (line / bar / gauge / stat / table) driven through the `DashboardMock`. Real adapter env-gates on `PROMETHEUS_URL`; falls back to `PROMETHEUS_ENV_MISSING` traces without it.
- `dogfood-alert-orchestrator` — 10 rules × 3-level routing × silence × escalation walking the `AlertRouter` state machine. Real adapter env-gates on `ALERTMANAGER_URL`.
- `dogfood-trace-flame-graph` — 10 canonical traces with 100+ total spans, span-tree + flame render + drill-down + log correlation. Real adapter env-gates on `JAEGER_URL`.

Every dogfood app writes its fidelity report to `quality-report/fidelity-latest.md` (git-ignored) and to `docs/quality-reports/observability/<name>.md` (git-tracked snapshot promoted per release).

## Release gate

The 11-axis contract is unchanged. Observability v2 providers keep their `@kiwa/observability/*` prefix routed to the 7-axis common branch (coverage 3 / fidelity / perf p95 / mutation / behavior tests). The AI-LLM 4 axes (cost / latency / token / accuracy) route only through providers whose name starts with `@kiwa/ai-` (see `isAiLlmProvider` in `packages/quality-metrics/src/types.ts`) — metrics / alert / trace surfaces are excluded because there is no token pricing to measure.

The observability v2 thresholds match the common 7-axis defaults documented in v1.16 — line coverage ≥ 85%, branch ≥ 80%, function ≥ 90%, fidelity ratio ≥ 70%, perf p95 ≤ 100 ms for panel refresh / rule evaluate / span-tree build round-trip, mutation kill rate ≥ 60%, behavior test count ≥ 10.

## Upgrade checklist

- [ ] `pnpm add -D @kiwa/observability` at each package that wants dashboard / alert / trace / correlation assertions (already installed if you use v1.1 telemetry mocks — the v2 additions ride the same package version bump)
- [ ] Reuse the collector from `createOtelMock()` / `createDatadogMock()` / `createSentryMock()` (accessible via `mock.collector`) so the v2 readers see the same data your v1.1 emitters wrote
- [ ] Bind a `DashboardMock` per test when asserting on panel refreshes; call `refresh()` after every collector state change you want reflected
- [ ] Register rules on an `AlertRouter` in `beforeEach`; use a deterministic `{ now: () => clock }` when asserting on `forSamples`, silence expiry, or escalation ladders
- [ ] Wire `runFidelityCheck` in your test setup to emit a report for the release gate when you add a new dogfood app under `examples/`
- [ ] Set `PROMETHEUS_URL` / `ALERTMANAGER_URL` / `JAEGER_URL` in CI when you want the dogfood fidelity report to reflect real drift instead of `ENV_MISSING`

## Migrating from v1.1 telemetry-only tests

Tests that only asserted on the v1.1 collector (`otel.collector.spanByName(...)`, `dd.collector.metricSum(...)`) do not need to change. v2 is additive — the v1.1 API surface is untouched.

To adopt v2 in an existing v1.1 test, extend the assertion phase instead of replacing it.

```ts
// v1.16 (v1.1 collector-only)
const otel = createOtelMock();
sut.handleRequest();
expect(otel.collector.spanByName('http.request')).toBeDefined();

// v1.17 (v1.1 + v2 flame graph)
const otel = createOtelMock();
sut.handleRequest();
expect(otel.collector.spanByName('http.request')).toBeDefined();

// New — build the flame graph on top of the same emitted spans
const flame = renderFlameGraph(buildSpanTree(otel.collector.spans));
const handler = flame.find((n) => n.name === 'http.request');
expect(handler?.selfMs).toBeLessThan(50);
```

The v2 readers are pure functions over `collector.spans` / `collector.metrics` / `collector.logs`. They add no state, no side effects, and no runtime overhead — the test grows one function call and gains three tree-shape assertions.
