### 16-axis combined fidelity harness

The v2.2 package extends the existing `collectFidelityCoverage()` grid to cover the full 4 provider × 16 axis = 64-row grid in one call.

```ts
import { collectFidelityCoverage } from '@kiwa/observability';

const cov = collectFidelityCoverage();
console.log(cov.rows.length); // 64
console.log(cov.rows.every((r) => r.providerEvents.length === r.neutralEvents.length)); // true
```

The rows are ordered by provider first (`grafana-oss` / `prometheus` / `loki` / `otel-collector`) then by axis (v2.1 axes 1-8 first, v2.2 axes 9-16 second). A CI job can pin the row count as a regression guard so a mis-configured axis registration is caught before the release cuts.

## Recommended migration path

1. Bump `@kiwa/observability` from `^2.1` to `^2.2` in your `package.json`.
2. Existing v2.1 imports keep working — no code change required.
3. Opt-in to a v2.2 axis by importing the new function (e.g. `startIacSession` for IaC observability) and adding a corresponding test.
4. Wire the real-driver path by setting `KIWA_MODE=real` + the axis-specific backend URL (`KIWA_TERRAFORM_URL` / `KIWA_ANTHROPIC_API_KEY` / `KIWA_CHAOSMESH_URL` / etc.) in the CI job that runs the dogfood app.
5. Optionally add `collectFidelityCoverage()` as a regression guard on the 4 × 16 = 64 grid so a mis-configured axis registration is caught before the next release cuts.

The 16-axis grid is a strict superset of the 8-axis v2.1 grid — a downstream consumer that was already asserting `rows.every(r => r.providerEvents.length === r.neutralEvents.length)` on 32 rows now asserts on 64 rows without changing the assertion shape.
