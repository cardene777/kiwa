# v1.9 → v1.10 migration

## Scope

v1.10 (issue [#666](https://github.com/cardene777/kiwa/issues/666)) added three parallel expansions:

- Supabase Auth core + advanced adapters (`@kiwa-test/auth` v0.3)
- RabbitMQ basic + advanced adapters (`@kiwa-test/queue` v0.3)
- Rust contract layer — `kiwa::contract::foundry` + `kiwa::contract::alloy` (`kiwa-test-rs` v0.4.2)

**No breaking changes** — every v1.9 test file compiles + passes unchanged. The migration below is only needed if you want to adopt v1.10 features.

## Update TypeScript deps

Bump both packages in your `package.json`:

```diff
 {
   "devDependencies": {
-    "@kiwa-test/auth": "0.2.0",
-    "@kiwa-test/queue": "0.2.0"
+    "@kiwa-test/auth": "0.3.0",
+    "@kiwa-test/queue": "0.3.0"
   }
 }
```

Then `pnpm install`.

## Adopt Supabase Auth (optional)

The core adapter covers the daily flow (email/password, OAuth PKCE, magic link, JWT session):

```ts
import { setupSupabaseAuthEnv } from '@kiwa-test/auth';

const env = await setupSupabaseAuthEnv({
  users: [{ email: 'alice@example.test', password: 'x', emailConfirmed: true }],
});
```

The advanced adapter layers RLS policy simulation + MFA + SSO SAML + Web3 SIWE:

```ts
import { setupSupabaseAdvancedEnv } from '@kiwa-test/auth';

const advanced = await setupSupabaseAdvancedEnv({
  policies: [
    {
      name: 'docs_owner_select',
      table: 'documents',
      command: 'select',
      roles: ['authenticated'],
      using: (row, ctx) => row.ownerId === ctx.userId,
    },
  ],
});
```

Both envs stop with `await env.stop()` in `afterEach`.

## Adopt RabbitMQ (optional)

The basic adapter covers AMQP 0.9.1 semantics (4 exchange types + consumer + ack/nack + prefetch):

```ts
import { setupRabbitMQEnv } from '@kiwa-test/queue';

const env = await setupRabbitMQEnv({
  exchanges: [{ name: 'orders', type: 'topic' }],
  queues: [{ name: 'orders.us' }],
  bindings: [{ exchange: 'orders', queue: 'orders.us', routingKey: 'us.*' }],
});
```

The advanced adapter adds DLX + delayed message plugin + cluster mode + federation + auto-reconnect:

```ts
import { setupRabbitMQAdvancedEnv } from '@kiwa-test/queue';

const env = await setupRabbitMQAdvancedEnv({
  delayedExchanges: [{ name: 'sms.delayed', type: 'x-delayed-message', delayedType: 'direct' }],
  queues: [{ name: 'work.main', deadLetterExchange: 'dlx.work', kind: 'quorum' }],
  cluster: {
    nodes: [
      { id: 'rabbit@n1', role: 'primary', active: true },
      { id: 'rabbit@n2', role: 'replica', active: true },
      { id: 'rabbit@n3', role: 'replica', active: true },
    ],
  },
});
```

## Adopt the Rust contract layer (optional)

Add the Foundry + alloy feature flags:

```diff
 [dev-dependencies]
-kiwa-test-rs = { version = "0.4" }
+kiwa-test-rs = { version = "0.4.2", features = ["contract-foundry", "contract-alloy"] }
```

Then any Rust integration test can use:

```rust
use kiwa::contract::foundry::{Anvil, FoundryEnv};
use kiwa::contract::alloy::{ContractCall, Provider, Signer, SolAbi};

let env = FoundryEnv::detect();
if env.all_available() {
    let anvil = Anvil::spawn_deterministic(8545)?;
    let out = env.forge_test(std::path::Path::new("."))?;
    assert!(out.success);
    drop(anvil);
}

let abi = SolAbi::parse_foundry_out("Counter", &std::fs::read_to_string("out/Counter.json")?)?;
let selector = abi.selector_of("increment").unwrap();
```
