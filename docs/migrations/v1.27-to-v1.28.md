# Migration guide — v1.27 → v1.28

v1.28 is **additive** — every `@kiwa/*` package public API that existed in v1.27 keeps its surface. Existing tests keep passing without touching a single line. The v1.28 changes are pure additions on the advanced realtime transport axis (WebRTC / WebTransport / HTTP/3 + QUIC).

The 5 things v1.28 adds are.

- `@kiwa/realtime` v0.2 keeps every v0.1 export (`RealtimeEngine` + `createSupabaseRealtimeMock` + `createAblyMock` + `createPusherMock` + `createSocketioMock` + `runRealtimeFidelityCheck` + `buildRealtimeReport` + every v1.13 `*Metric` type alias). v0.2 is a **surface extension** — 3 protocol × 8 axis low-layer transport mocks (`createWebRtcSignalingMock` + `createWebRtcIceMock` + `createWebRtcTrackMock` + `createWebRtcDataChannelMock` + `createWebTransportUniMock` + `createWebTransportBiMock` + `createHttp3PushMock` + `createQuicMultiplexMock`) + `measureSemanticsAxis` / `measureSemanticsGrid` / `SEMANTICS_GRID` (24-row fidelity grid) + `resolveRealtimeDriver` / `resolveRealtimeDriverByProvider` / `REAL_DRIVER_REQUIRED_KEYS` (env-gate for real driver opt-in across the v1.13 4 providers).
- 3 dogfood apps that exercise the 8 axes end-to-end across 3 realistic frameworks — `dogfood-nextjs-webrtc-video-app` (Next.js 15 + mediasoup SFU + coturn TURN + WebRTC video/audio, 36 tests) / `dogfood-nuxt-webtransport-stream-app` (Nuxt 3 + aioquic + WebTransport uni/bi + Datagram + connection migration + 0-RTT, 30 tests) / `dogfood-sveltekit-http3-multiplex-app` (SvelteKit + nginx-quic + HTTP/3 stream priority + HPACK dynamic table + 0-RTT anti-replay, 32 tests + 4 follow-up findings from adversarial review).
- 8-axis SSOT — `docs/concepts/webrtc-webtransport-testing.md` pins the 3 protocol × 8 axis grid (WebRTC signaling / ICE / track / data channel + WebTransport uni / bi + HTTP/3 push + QUIC multiplex) with the `SemanticsProtocol × SemanticsAxis` matrix as the runtime SSOT that mirrors the doc.
- 24-row fidelity grid + protocol × framework fidelity table — `SEMANTICS_GRID` in `@kiwa/realtime` enumerates every applicable / non-applicable (protocol, axis) pair so the visual matrix and the runtime measurement agree; the concept doc adds a protocol × framework matrix so a reader can pick which framework hosts which axis.
- 3 new tutorials (52 webrtc-video-signaling / 53 webtransport-stream / 54 http3-multiplex), 1 concept doc SSOT (`webrtc-webtransport-testing.md` — 8-axis catalog + P2P vs SFU selection guide + WebRTC ICE trickle vs half-trickle + WebTransport vs WebSocket differences), 1 migration guide (this file), 1 tutorial snippet validation test (`packages/realtime/tests/docs-tutorial-v1.28.test.ts`). All wired through the sidebar (`docs/.vitepress/config.mts`).

## What breaks (nothing)

Nothing. The v1.28 changes are pure additions.

- `@kiwa/realtime` v0.1 surface (`RealtimeEngine` + 4 provider mocks + `runRealtimeFidelityCheck` + `buildRealtimeReport` + 5 v1.13 semantics types) — unchanged. v0.2 layers 3 protocol × 8 axis low-layer transport mocks + 24-row fidelity grid + real driver env-gate without touching the v0.1 export names.
- `evaluateReleaseGate` signature — no change. The v1.27 opt-in 12-axis path (`{ mutationTier }`) stays as-is. v1.28 does not add a new axis; the 3 dogfood apps opt into the 12-axis path via `runFidelityHarness({ mutationTier: 'saas' })` on top of the v1.27 SaaS-tier baseline.
- Every prior `@kiwa/*` package (core / api / data / cli-test / observability / cli / nextjs / nuxt / sveltekit / remix / astro / solidstart / qwikcity / edge / solidjs / fresh / hono / auth / ai-llm / payment / queue / cache / streaming / mcp / agent / search / orm / dapp / ui / a11y / visual / component / e2e / perf-harness / quality-metrics) — public API surface untouched. Existing tests keep passing.
- Every prior tutorial 01-51, migration guide v1.9→v1.27, concept doc — unchanged. v1.28 only appends tutorial 52-54 + concept `webrtc-webtransport-testing.md` + migration `v1.27-to-v1.28.md`.
- Every prior dogfood app (v1.27 mutation sweep, v1.26 db-advanced apps, v1.25 perf-sweep suites, v1.24 edge apps, v1.23 payment apps, v1.22 auth apps, v1.20 streaming apps, v1.19 framework apps, etc.) — untouched. The 3 v1.28 dogfood apps opt into the 12-axis release-gate path via `runFidelityHarness({ mutationTier: 'saas' })` (SaaS tier default 65 %) but every mock-only suite still passes without the opt-in.

## What's new (opt in)

### `@kiwa/realtime` v0.2 — 3 protocol × 8 axis low-layer transport mocks

The v0.1 `RealtimeEngine` + 4 provider mocks + `runRealtimeFidelityCheck` stay the first-line contract for the 5 v1.13 chat / CDC semantics. v0.2 layers 8 new axis mocks + a 24-row fidelity grid + a real driver env-gate, all under `packages/realtime/src/semantics/` + `packages/realtime/src/semantics-fidelity.ts` + `packages/realtime/src/real-driver.ts`.

The 8 axis mocks.

- **`createWebRtcSignalingMock`** — SDP offer / answer negotiation + trickle ICE candidate emission + renegotiation for track changes. Emits `offer` / `answer` / `ice-candidate` / `renegotiation` events with deterministic seed.
- **`createWebRtcIceMock`** — ICE gathering + connectivity check + TURN relay fallback + trickle ICE. Emits `ice-gathering` / `ice-checking` / `ice-connected` / `ice-relay-used` events + exposes `IceStats` (`candidatesGathered` / `candidatesRemote` / `activeCandidatePairs` / `relayUsedCount`).
- **`createWebRtcTrackMock`** — `getUserMedia` + `MediaStream` + `addTrack` / `removeTrack` + simulcast layer (`rid: low / med / high` with `maxBitrate: 100k / 300k / 900k` defaults). Emits `track-add` / `track-remove` / `track-mute` / `track-unmute` events.
- **`createWebRtcDataChannelMock`** — `ordered` / `unordered` + `maxRetransmits` + `binaryType` DataChannel with deterministic drop simulation on unreliable channels. Emits `data-open` / `data-message` / `data-close` events.
- **`createWebTransportUniMock`** — unidirectional stream + Datagram + stream reset (writer.abort). Emits `uni-stream-open` / `uni-stream-write` / `uni-stream-reset` / `datagram-recv` events.
- **`createWebTransportBiMock`** — bidirectional stream + flow-control window (default 16 kB) + backpressure emission when writes exceed remaining window. Emits `bi-stream-open` / `bi-stream-write` / `bi-stream-close` / `bi-backpressure` events.
- **`createHttp3PushMock`** — server push_promise + priority (urgency 0-7 + incremental flag per RFC 9218) + cancellation. Emits `push-promise` / `push-headers` / `push-body` / `push-cancelled` events.
- **`createQuicMultiplexMock`** — QUIC stream multiplex + priority (0-255, low = high) + HPACK dynamic table + 0-RTT resumption. Emits `stream-open` / `stream-close` / `hpack-insert` / `zero-rtt-used` events.

The 24-row fidelity grid.

- **`SEMANTICS_GRID`** — 3 protocol × 8 axis = 24 row grid. Each row is `{ protocol: SemanticsProtocol, axis: SemanticsAxis, applicable: boolean }`. Cross-protocol rows are `applicable: false` (WebRTC does not have `webtransport-uni`), same-protocol rows are `applicable: true`. The grid keeps the visual matrix and the runtime measurement in sync — a caller cannot add an axis to the doc without updating the enum + grid at the same time.
- **`measureSemanticsAxis({ mock, scenario, timeoutMs })`** — single-axis fidelity measurement. Registers an event handler on the mock, runs the scenario, collects the event stream, returns `{ protocol, axis, applicable, eventsEmitted, streamsOpened, streamsClosed, streamsReset, backpressureCount, events }`. Rejects on timeout (default 3 s).
- **`measureSemanticsGrid({ scenarios })`** — 24-row grid measurement. Iterates `SEMANTICS_GRID`, calls `measureSemanticsAxis` on `applicable: true` rows with matching scenarios, emits placeholder rows for `applicable: false`. The return array has exactly 24 entries so downstream matrix rendering does not need to fill gaps.

The 4-provider real driver env-gate.

- **`REAL_DRIVER_REQUIRED_KEYS`** — provider-name → required env variable keys map. Supabase: `SUPABASE_URL` + `SUPABASE_ANON_KEY`. Ably: `ABLY_API_KEY`. Pusher: `PUSHER_APP_ID` + `PUSHER_KEY` + `PUSHER_SECRET` + `PUSHER_CLUSTER`. Socket.io: `SOCKETIO_URL`.
- **`resolveRealtimeDriver({ provider, requiredKeys, createReal, createMock, envSource? })`** — returns `{ driver, isReal, reason, missingKeys }`. Real driver returned only when `KIWA_MODE=real` + every required key present.
- **`resolveRealtimeDriverByProvider(provider, createReal, createMock, envSource?)`** — shorthand that looks up `REAL_DRIVER_REQUIRED_KEYS[provider]` for the default key set.

Concrete usage — the pattern every WebRTC / WebTransport / HTTP/3 caller follows (paste-ready).

```ts
import {
  createHttp3PushMock,
  createQuicMultiplexMock,
  createWebRtcDataChannelMock,
  createWebRtcIceMock,
  createWebRtcSignalingMock,
  createWebRtcTrackMock,
  createWebTransportBiMock,
  createWebTransportUniMock,
  measureSemanticsGrid,
  resolveRealtimeDriverByProvider,
  SEMANTICS_GRID,
} from '@kiwa/realtime';

// One shot — measure every applicable axis in one call.
const signaling = createWebRtcSignalingMock({ seed: 1 });
const ice = createWebRtcIceMock({ seed: 2 });
const track = createWebRtcTrackMock({ seed: 3 });
const data = createWebRtcDataChannelMock({ seed: 4 });
const uni = createWebTransportUniMock({ seed: 5 });
const bi = createWebTransportBiMock({ seed: 6 });
const push = createHttp3PushMock({ seed: 7 });
const quic = createQuicMultiplexMock({ seed: 8, enable0RTT: true });

const rows = await measureSemanticsGrid({
  scenarios: new Map([
    ['webrtc-signaling', { mock: signaling, scenario: async () => { await signaling.createOffer(); } }],
    ['webrtc-ice', { mock: ice, scenario: async () => { await ice.startGathering(3); await ice.startConnectivityCheck(); } }],
    ['webrtc-track', {
      mock: track,
      scenario: async () => {
        // getUserMedia only bumps the stream counter — the `track-add` event
        // is what the fidelity axis measures. Publishing a track exercises it.
        const s = await track.getUserMedia({ audio: true, video: true });
        for (const t of s.tracks) await track.addTrack(t, s);
      },
    }],
    ['webrtc-data-channel', {
      mock: data,
      scenario: async () => {
        // createDataChannel schedules `data-open` via a microtask — wait
        // briefly so the fidelity axis observes the emission before returning.
        data.createDataChannel({ ordered: true });
        await new Promise((r) => setTimeout(r, 5));
      },
    }],
    ['webtransport-uni', { mock: uni, scenario: async () => { await uni.createUniStream(); } }],
    ['webtransport-bi', { mock: bi, scenario: async () => { await bi.createBiStream({ windowSize: 1024 }); } }],
    ['http3-push', { mock: push, scenario: async () => { await push.pushStream('/a.css', { urgency: 3 }); } }],
    ['quic-multiplex', { mock: quic, scenario: async () => { await quic.openStream({ priority: 128 }); } }],
  ]),
});
// rows.length === 24, applicable rows have eventsEmitted > 0
```

## Upgrade path

If you consume `@kiwa/realtime` directly.

```bash
pnpm add -D @kiwa/realtime@^0.2
```

Existing v0.1 imports keep passing. The v0.2 upgrade adds new exports (8 axis mocks + `SEMANTICS_GRID` + `measureSemanticsAxis` + `measureSemanticsGrid` + `resolveRealtimeDriver` + `resolveRealtimeDriverByProvider` + `REAL_DRIVER_REQUIRED_KEYS`); no prior export renames or removals.

## Release gate

`evaluateReleaseGate` axis surface stays at **12 axes** in v1.28 — v1.27 introduced the 12th `mutation.tier` axis, and v1.28 does not add another. The 3 dogfood apps opt into the 12-axis path via `{ mutationTier: 'saas' }` (SaaS tier default 65 %) so their baseline JSONs live under `.mutation-baseline/{app}.json` alongside the 33 core packages.

| Axis | Kind | Introduced | Enabled by |
|---|---|---|---|
| coverage — line / branch / function (3 axes) | floor | v1.11 | always |
| test count — behavior | floor | v1.11 | always |
| fidelity — ratio | floor | v1.11 | always |
| perf — p95 ms | ceiling | v1.11 | always |
| mutation — killRate (legacy) | floor | v1.11 | always |
| cost / latency / token / accuracy (4 axes) | mixed | v1.12 | `provider` starts `@kiwa/ai-*` |
| mutation — tier | floor | v1.27-4 | `context.mutationTier` opt-in |
