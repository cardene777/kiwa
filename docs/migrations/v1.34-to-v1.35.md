# Migration guide — v1.34 → v1.35

v1.35 is **additive** — every `@kiwa-test/*` package public API that existed in v1.34 keeps its surface. Existing tests keep passing without touching a single line. The v1.35 changes are pure additions on the observability 深化 axis (SLO burn rate + RED/USE + exemplar + OTel-advanced + log-correlation-advanced + alert-routing-advanced + profiling + cardinality).

The 5 things v1.35 adds are.

## What's new (opt in)

### `@kiwa-test/observability` v2.1 — 8 advanced-semantics axes

Install (or bump) the package.

```bash
pnpm add -D @kiwa-test/observability@^2.1
```

Import the axis you need through the namespaced `semantics/` barrel — the whole advanced surface is one namespace away.

```ts
import { semantics } from '@kiwa-test/observability';

const {
  attachTraceToMetric,
  buildFlameGraph,
  collectFidelityCoverage,
  computeErrorBudget,
  computeFourGoldenSignals,
  evaluateBurnRate,
  fireMultiWindowMultiBurnRateAlert,
  openSLOWindow,
  recordRequests,
  sampleCpu,
  startProfiling,
  startSLO,
} = semantics;
```

The `semantics` namespace holds every v2.1 advanced function (SLO / RED-USE / exemplar / OTel-advanced / log-correlation-advanced / alert-routing-advanced / profiling / cardinality) plus the fidelity harness (`collectFidelityCoverage`). The v2.0 flat exports (`renderDashboard` / `AlertRouter` / `LogCorrelationIndex` / `buildSpanTree` / etc.) stay on the root import path unchanged.

Use it in your own test.

```ts
import { describe, expect, it } from 'vitest';
import { semantics } from '@kiwa-test/observability';

const {
  computeErrorBudget,
  evaluateBurnRate,
  fireMultiWindowMultiBurnRateAlert,
  openSLOWindow,
  recordRequests,
  startSLO,
} = semantics;

describe('my api — SLO burn rate', () => {
  it('fires the MWMB alert when the burn rate exceeds 14.4×', () => {
    const session = startSLO({
      target: 'prometheus',
      sloId: 'api-availability',
      targetObjective: 0.999,
      windowDays: 28,
    });
    openSLOWindow(session);
    recordRequests(session, { requests: 100_000, errors: 1_500 });
    computeErrorBudget(session);
    evaluateBurnRate(session, {
      shortWindowMinutes: 5,
      longWindowMinutes: 60,
      burnRate: 14.4,
    });

    const alert = fireMultiWindowMultiBurnRateAlert(session, {
      thresholds: [
        { shortWindowMinutes: 5, longWindowMinutes: 60, burnRate: 14.4 },
        { shortWindowMinutes: 30, longWindowMinutes: 360, burnRate: 6 },
      ],
      page: true,
    });

    expect(alert.state).toBe('alert-fired');
    expect(alert.metadata.fired).toBe(true);
  });
});
```

The full API surface — 5-7 functions per axis × 8 axes ≈ 45 new state-machine transitions — is spelled out in tutorials 70 (SLO burn rate + MWMB), 71 (OpenTelemetry exemplar + batch + W3C context), 72 (Continuous profiling + flame graph). The 4 target mocks (Grafana OSS / Prometheus / Loki / OpenTelemetry Collector) all cover all 8 axes.

### `collectFidelityCoverage()` — 4 provider × 8 axis grid

The fidelity harness describes which provider covers which axis and what neutral event + provider dialect each axis emits.

```ts
import { semantics } from '@kiwa-test/observability';

const coverage = semantics.collectFidelityCoverage([
  'grafana-oss',
  'prometheus',
  'loki',
  'otel-collector',
]);

console.log(coverage.rows.length); // 32 (4 provider × 8 axis)
console.log(coverage.axes.length); // 8

const promSlo = coverage.rows.find(
  (r) => r.provider === 'prometheus' && r.axis === 'slo',
);
console.log(promSlo?.neutralEvents);
// [ 'slo.window_opened', 'slo.error_budget_computed',
//   'slo.burn_rate_evaluated', 'slo.multi_window_alert_fired' ]
console.log(promSlo?.providerEvents);
// [ 'prom.slo.window.open', 'prom.slo.budget.compute',
//   'prom.slo.burn.eval', 'prom.slo.alert.mwmb' ]
```

Every one of the 32 rows has a `neutralEvents` list (portable) and a `providerEvents` list (provider-specific dialect). Tests iterating the grid assert on the neutral name for portability; tests wired to a real provider output can assert on the provider-specific dialect. This is the data structure the release-gate report reads to render "the fidelity matrix" in the CI summary.

### `KIWA_MODE=real` — env-gated real driver run

The mock path stays the default. When `KIWA_MODE=real` is set, the harness assertions also try to run against the real driver, gated by the required env for that axis.

- **SLO dogfood** axes → `PROMETHEUS_URL` + `GRAFANA_URL` (real Prometheus + Grafana OSS reachable for recording rule + panel query)
- **RED/USE dogfood** axes → `PROMETHEUS_URL` + `GRAFANA_URL` (same pair, different recording rules)
- **OTel exemplar dogfood** axes → `OTEL_COLLECTOR_URL` + `TEMPO_URL` (real OpenTelemetry Collector + Grafana Tempo reachable for OTLP + trace query)
- **OTel-advanced dogfood** axes → `OTEL_COLLECTOR_URL` (real Collector reachable for batch + resource + baggage propagation)
- **Log-correlation-advanced dogfood** axes → `LOKI_URL` + `PROMETHEUS_URL` (real Loki + Prometheus reachable for LogQL + PromQL join)
- **Alert-routing-advanced dogfood** axes → `GRAFANA_URL` + `ALERTMANAGER_URL` (real Grafana + Alertmanager reachable for silence + inhibit + route)
- **Profiling dogfood** axes → `PYROSCOPE_URL` (real Grafana Pyroscope reachable for flame graph fetch)
- **Cardinality dogfood** axes → `PROMETHEUS_URL` (real Prometheus reachable for series count + label-value query)

Absent env means silently fall back to mock mode. This is the same env-gate contract the v1.22 real-driver testing tutorial (auth adapters + Keycloak), the v1.31 streaming real-driver concept doc, the v1.32 database real-driver concept doc, the v1.33 payment real-driver concept doc, and the v1.34 frontend real-driver concept doc all use — v1.35 layers 6 more `_URL` env-gates onto the same pattern.

## Snippet validation — 13 milestone streak

`packages/observability/tests/docs-tutorial-v1.35.test.ts` — every code snippet in tutorials 70-72 is behavior-tested. If the observability API surface drifts, the snippet test fails before the tutorial hits a reader.

The streak is now 13 milestones (v1.23 → v1.35) — each milestone lands a `docs-tutorial-v{version}.test.ts` in its package of record with `describe('tutorial N — {topic}')` blocks that mirror the tutorial code. This is the pattern kiwa uses to keep the docs from drifting silently; 13 consecutive milestones with the pattern makes it the default rather than the exception.

## No release-gate axis change

v1.35 does not add a 14th release-gate axis. The 8 observability advanced axes gate the observability package's own tests (via `pnpm --filter @kiwa-test/observability test`) but do not surface as a per-package `quality-metrics` axis. The reason is that the fidelity harness is provider-shape-specific — a package that does not export to Grafana OSS / Prometheus / Loki / OpenTelemetry Collector has nothing to assert on. When a future milestone adds an `observability.fidelity` axis that describes "which observability providers this package's tests hit," it will slot into the 13-axis release gate as the 14th; v1.35 keeps things simple.
