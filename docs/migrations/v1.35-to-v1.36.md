# Migration guide — v1.35 → v1.36

v1.36 is **additive** — every `@kiwa/*` package public API that existed in v1.35 keeps its surface. Existing tests keep passing without touching a single line. The v1.36 changes are pure additions on the search 深化 axis (Vector + Semantic + Faceted advanced + Geo + Relevance + Synonym advanced + Index management + Query DSL).

## What's new (opt in)

### `@kiwa/search` v0.3 — 8 advanced-semantics axes

Install (or bump) the package.

```bash
pnpm add -D @kiwa/search@^0.3
```

Import the axis you need directly through the top-level barrel — every v0.3 advanced function is re-exported through the package root.

```ts
import {
  buildVectorIndex,
  collectFidelityCoverage,
  computeNestedFacets,
  filterBoundingBox,
  fuseHybrid,
  queryKnn,
  recallAnn,
  scoreBm25,
  seedFacetedDocuments,
  seedGeoDocuments,
  seedRelevanceDocuments,
  startFacetedSession,
  startGeoSession,
  startRelevanceSession,
  startVectorSession,
} from '@kiwa/search';
```

The v0.3 advanced functions cover every axis (Vector / Semantic / Faceted advanced / Geo / Relevance / Synonym advanced / Index management / Query DSL) plus the fidelity harness (`collectFidelityCoverage`). The v0.2 flat exports (`mockSearchQuery` / `mockSearchIndex` / `mockSearchFacet` / etc.) stay on the root import path unchanged.

Use it in your own test.

```ts
import { describe, expect, it } from 'vitest';
import {
  buildVectorIndex,
  fuseHybrid,
  queryKnn,
  recallAnn,
  startVectorSession,
} from '@kiwa/search';

describe('my api — vector recall regression', () => {
  it('recall@10 stays above 0.9 when HNSW efConstruction changes from 200 to 100', () => {
    const session = startVectorSession({
      target: 'meilisearch',
      indexId: 'articles',
      dimensions: 3,
    });
    buildVectorIndex(session, [
      { id: 'a', vector: [1, 0, 0] },
      { id: 'b', vector: [0, 1, 0] },
      { id: 'c', vector: [1, 1, 0] },
      { id: 'd', vector: [0, 0, 1] },
    ]);
    const knn = queryKnn(session, [1, 0, 0], 4);
    fuseHybrid(session, {
      vectorHits: knn.hits,
      keywordHits: [{ id: 'a', score: 1 }],
      vectorWeight: 0.7,
      keywordWeight: 0.3,
    });
    const { recall } = recallAnn(session, {
      groundTruth: ['a'],
      retrieved: knn.hits.map((h) => h.id),
    });
    expect(recall).toBeGreaterThanOrEqual(0.9);
  });
});
```

The full API surface — 5-7 functions per axis × 8 axes ≈ 45 new state-machine transitions — is spelled out in tutorials 73 (Vector search + HNSW + hybrid + recall), 74 (Faceted advanced + Geo), 75 (Relevance + Synonym advanced + Index management). The 4 target mocks (Meilisearch / Typesense / Algolia / OpenSearch OSS) all cover all 8 axes.

### `collectFidelityCoverage()` — 4 provider × 8 axis grid

The fidelity harness describes which provider covers which axis and what neutral event + provider dialect each axis emits.

```ts
import { collectFidelityCoverage } from '@kiwa/search';

const coverage = collectFidelityCoverage([
  'meilisearch',
  'typesense',
  'algolia',
  'opensearch-oss',
]);

console.log(coverage.rows.length); // 32 (4 provider × 8 axis)
console.log(coverage.axes.length); // 8

const meiliVector = coverage.rows.find(
  (r) => r.provider === 'meilisearch' && r.axis === 'vector',
);
console.log(meiliVector?.neutralEvents);
// [ 'vector.index_built', 'vector.knn_queried',
//   'vector.hybrid_fused', 'vector.ann_recalled' ]
console.log(meiliVector?.providerEvents);
// [ 'meili.vector.index.build', 'meili.vector.knn.query',
//   'meili.hybrid.fuse', 'meili.vector.ann.recall' ]
```

Every one of the 32 rows has a `neutralEvents` list (portable) and a `providerEvents` list (provider-specific dialect). Tests iterating the grid assert on the neutral name for portability; tests wired to a real provider output can assert on the provider-specific dialect. This is the data structure the release-gate report reads to render "the search fidelity matrix" in the CI summary.

### `KIWA_MODE=real` — env-gated real driver run

The mock path stays the default. When `KIWA_MODE=real` is set, the harness assertions also try to run against the real driver, gated by the required env for that axis.

- **Vector + Semantic dogfood** axes → `KIWA_MEILI_URL` + `KIWA_TYPESENSE_URL` (real Meilisearch v1 + Typesense v27 reachable for hybrid + kNN query)
- **Faceted + Geo dogfood** axes → `KIWA_ALGOLIA_URL` + `ALGOLIA_KEY` (real Algolia sandbox reachable for nested facet + bounding box query)
- **Relevance + Synonym + Index mgmt dogfood** axes → `KIWA_OPENSEARCH_URL` + `OPENSEARCH_KEY` (real OpenSearch OSS 2.x testcontainer reachable for BM25 + synonym file + alias swap)
- **Query DSL** → provider-agnostic (mock-only in v1.36, no dogfood app)

Absent env means silently fall back to mock mode. This is the same env-gate contract the v1.22 real-driver testing tutorial (auth adapters + Keycloak), the v1.31 streaming real-driver concept doc, the v1.32 database real-driver concept doc, the v1.33 payment real-driver concept doc, the v1.34 frontend real-driver concept doc, and the v1.35 observability real-driver concept doc all use — v1.36 layers 6 more `_URL` / `_KEY` env-gates onto the same pattern.

## Snippet validation — 14 milestone streak

## No release-gate axis change

v1.36 does not add a 14th release-gate axis. The 8 search advanced axes gate the search package's own tests (via `pnpm --filter @kiwa/search test`) but do not surface as a per-package `quality-metrics` axis. The reason is that the fidelity harness is provider-shape-specific — a package that does not export to Meilisearch / Typesense / Algolia / OpenSearch OSS has nothing to assert on. When a future milestone adds a `search.fidelity` axis that describes "which search providers this package's tests hit," it will slot into the 13-axis release gate as the 14th; v1.36 keeps things simple.
