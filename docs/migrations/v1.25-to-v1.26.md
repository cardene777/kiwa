# Migration guide — v1.25 → v1.26

v1.26 is **additive** — every `@kiwa/*` package public API that existed in v1.25 keeps its surface. Existing tests keep passing without touching a single line. The v1.26 changes are pure additions on the orm advanced-semantics axis.

The 5 things v1.26 adds are.

- `@kiwa/orm` v0.9 keeps every v0.8 export (`setupOrmEnv` / `expectQuery` / `expectRowCount` / the `Orm*` / `OrmTestEnv*` type aliases). v0.9 is a **surface extension** — 8 new axis session ctors + 32 step functions + `collectFidelityCoverage` + `backendEventName` + `AXIS_TO_EVENTS`, all under `packages/orm/src/semantics/`.
- 3 dogfood apps under `examples/dogfood-{postgres-cdc-outbox,mysql-rls-tenant,vector-search}-app/`. Each pairs one provider with one backend and exercises 1-3 axes as first-class flows (Next.js 15 + drizzle + Postgres CDC, Nuxt 3 + Prisma + MySQL RLS, SvelteKit + kysely + pgvector).
- 3 new tutorials (47 postgres-cdc-outbox walkthrough / 48 mysql-rls-tenant walkthrough / 49 vector-search-pgvector walkthrough), 1 concept doc SSOT (`db-advanced-testing.md` — 8 axis catalogue + provider × backend fidelity table + 3 × 3 × 8 = 72 row grid rule), 1 migration guide (this file). All wired through the sidebar.
- 1 tutorial snippet validation test (`packages/orm/tests/docs-tutorial-v1.26.test.ts`) that re-runs every code snippet in tutorials 47-49 against the real `@kiwa/orm` v0.9 API — same pattern as `docs-tutorial-v1.21.test.ts` through `docs-tutorial-v1.25.test.ts`.
- Sidebar navigation (`docs/.vitepress/config.mts`) — new "Database 深化 (v1.26)" section under Tutorials, `db-advanced-testing.md` under Concepts, `v1.25 → v1.26` under Migrations.

## What's new (opt in)

### `@kiwa/orm` v0.9 — 8 axis advanced db semantics

The v0.8 `setupOrmEnv` + `expectQuery` + `expectRowCount` stay the first-line contract. v0.9 layers 8 axis session ctors + 32 step functions + a fidelity coverage collector, all under `packages/orm/src/semantics/`.

Every axis follows the same 5-part shape.

- **Session ctor** — `create{Axis}Session({ provider, backend, ... })` returns a plain object with a `state` field, a `history` array, and axis-specific bookkeeping.
- **Step functions** — 4 exports per axis (e.g. `decodeEvent` / `appendOutbox` / `markEventOrdered` / `confirmDelivery` for `cdc`). Each returns an `AxisStep<TState>` envelope with `neutralEvent` + `backendEvent` + `state` + `metadata`.
- **State-machine guards** — every step function throws on illegal transitions. There is no silent fall-through.
- **Neutral event + backend dialect** — Postgres / MySQL / SQLite dialect strings resolve through `backendEventName(backend, neutral, provider?)`.
- **Fidelity coverage** — `collectFidelityCoverage({ providers, backends })` returns a deterministic 3 × 3 × 8 = 72-row grid.

The 8 axes.

- **replication** — `createReplicationSession` + `primaryWrite` / `markReplicaLagged` / `startFailover` / `promoteReplica` (streaming replication + failover flow).
- **cdc** — `createCdcSession` + `decodeEvent` / `appendOutbox` / `markEventOrdered` / `confirmDelivery` (Debezium-style outbox + LSN ordering + at-least-once delivery).
- **logical-replication** — `createLogicalRepSession` + `createPublication` / `syncSubscription` / `resolveConflict` / `heartbeat` (Postgres `pg_publication` + subscription conflict resolution).
- **mvcc** — `createMvccSession` + `takeSnapshot` / `abortSerializable` / `blockPhantom` / `detectDeadlock` (snapshot isolation + serializable abort + phantom / deadlock detection).
- **rls** — `createRlsSession` + `installPolicy` / `filterTenant` / `bypassRls` / `logAudit` (row-level security + tenant isolation + audit log).
- **connection-pool** — `createPoolSession` + `acquire` / `waitInQueue` / `idleTimeout` / `statementTimeout` (pool cap + idle eviction + statement cancel).
- **partitioning** — `createPartitioningSession` + `declarePartition` / `prunePartitions` / `partitionWiseJoin` / `routeInsert` (RANGE / LIST / HASH partitioning + pruning + partition-wise join).
- **vector-store** — `createVectorStoreSession` + `buildIndex` / `knnSearch` / `hybridSearch` / `computeDistance` (pgvector IVFFlat / HNSW + hybrid + cosine / L2 / inner-product distances).

Concrete usage — the pattern every axis follows.

```ts
// packages/my-package/tests/cdc.test.ts
import { describe, expect, it } from 'vitest';
import {
  appendOutbox,
  confirmDelivery,
  createCdcSession,
  decodeEvent,
  markEventOrdered,
} from '@kiwa/orm';

describe('cdc outbox — Postgres', () => {
  it('walks decoded -> buffered -> ordered -> delivered', () => {
    const session = createCdcSession({
      slotName: 'my_slot',
      provider: 'drizzle',
      backend: 'postgres',
    });

    for (const lsn of [101, 102, 103]) {
      decodeEvent(session, {
        event: { lsn, kind: 'insert', table: 'orders', payload: {} },
      });
      appendOutbox(session, {});
    }
    markEventOrdered(session);
    const final = confirmDelivery(session, { upToLsn: 103 });

    expect(final.state).toBe('delivered');
    expect(session.confirmedLsn).toBe(103);
  });
});
```

The full 8-axis catalogue lives in [`docs/concepts/db-advanced-testing.md`](../concepts/db-advanced-testing).

## Upgrade path

If you consume `@kiwa/orm` directly.

```bash
pnpm add -D @kiwa/orm@^0.9
```

Existing v0.8 imports keep passing. The v0.9 upgrade adds new exports (8 axis session ctors + 32 step functions + `collectFidelityCoverage` + `backendEventName` + `AXIS_TO_EVENTS` + type aliases); no prior export renames or removals.

```ts
// v0.8 — still works, no changes required
import {
  setupOrmEnv,
  expectQuery,
  expectRowCount,
} from '@kiwa/orm';

// v0.9 — new axis-scoped imports (opt-in)
import {
  createCdcSession,
  createRlsSession,
  createVectorStoreSession,
  collectFidelityCoverage,
  backendEventName,
} from '@kiwa/orm';
```

If you fork the kiwa monorepo and want to add a new dogfood app for another provider × backend combination, follow the tutorial 47-49 pattern.

## Release gate

`evaluateReleaseGate` axis surface is unchanged at v1.26 — same 11 axes as v1.17-v1.25. What v1.26 changes is **fidelity depth**, not surface — the `fidelity.ratio` axis now folds 8 advanced orm axes into the same metric. No new axis is added, no threshold is changed.
