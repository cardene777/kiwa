# Migration guide — v1.15 → v1.16

v1.16 is **additive** — every `@kiwa-lab/*` package that existed in v1.15 keeps its public API. Existing tests keep passing.

The 3 things v1.16 adds are:

- `@kiwa-lab/component` v0.1 (new package, unified Storybook 8 + Playwright Component Testing + Chromatic mock harness)
- 3 dogfood apps (`dogfood-storybook-design-system` + `dogfood-form-ct` + `dogfood-visual-regression`) that measure the mock against real Storybook / Playwright CT / Chromatic surfaces
- 3 tutorials, 1 concept doc, 1 migration guide (this file) covering component test setup

## What breaks (nothing)

Nothing. The v1.16 changes are pure additions.

- `@kiwa-lab/ai-llm` / `@kiwa-lab/mcp` / `@kiwa-lab/agent` / `@kiwa-lab/realtime` / `@kiwa-lab/perf-harness` / `@kiwa-lab/quality-metrics` — unchanged.
- `evaluateReleaseGate` — same 11-axis contract as v1.15. Component providers (`@kiwa-lab/component/*` prefix) roll into the common 7-axis branch (coverage / test count / fidelity / perf p95 / mutation). The AI-LLM 4 axes (cost / latency / token / accuracy) do not apply to a rendering surface.
- Everything else (auth / queue / cache / realtime / payment / search / observability / polyglot Rust + Go / dApp / framework adapters / docs skills) — untouched.

## What's new (opt in)

### `@kiwa-lab/component` v0.1 — 3 integration unified mock

New dependency:

```bash
pnpm add -D @kiwa-lab/component
```

Three factories, one shared DOM primitive layer, framework agnostic (React / Vue / Svelte / Solid render as `(args) => MockNode`).

```ts
import {
  createChromaticVisualMock,
  createPlaywrightCTMock,
  createStoryRegistry,
} from '@kiwa-lab/component';

const registry = createStoryRegistry();
const ct = createPlaywrightCTMock();
const chromatic = createChromaticVisualMock({ defaultDiffThreshold: 0 });
```

The 3 mocks share the same underlying `MockNode` tree so the same `render(args)` function feeds all 3 surfaces without adapters in between.

- `createStoryRegistry()` — Storybook 8 CSF3 compatible in-memory registry with `register` + `list` + `mount` + `play` + `runA11y`
- `createPlaywrightCTMock()` — Playwright Component Testing shaped `mount(render, args) → locator` with `getByRole` + `getByText` + `click` + `fill`
- `createChromaticVisualMock(config)` — baseline / current / diff / accept / reject workflow keyed on SHA-256 markup hashes

Config knobs (all optional; safe defaults keep the primary code paths passing).

- `ChromaticConfig.defaultViewport` — default `'default'`, used when a story does not set `parameters.chromatic.viewports`
- `ChromaticConfig.defaultDiffThreshold` — default `0` (hash-exact matching)
- `ChromaticConfig.now` — deterministic time source for `capturedAt` / `reviewedAt`, used to make test outputs stable

The 5 built-in fixtures (`buildButton` / `buildInput` / `buildForm` / `buildModal` / `buildCard`) are opt-in — production code registers its own `render` functions and never has to import from `fixture.js`.

### Dogfood apps (3 new, all opt in)

Three examples ship under `examples/`, each producing a real vs mock fidelity report that feeds the 7-axis release gate.

- `dogfood-storybook-design-system` — 12 React primitives (Button / Input / Card / Modal / Dropdown / Tabs / Toast / Table / Tooltip / Badge / Avatar / Icon) registered as `StoryObj` with `args` + `play` + a11y checks. Real adapter env-gates on `STORYBOOK_URL`.
- `dogfood-form-ct` — 5 form patterns (login / signup / checkout / profile / search) driven through the Playwright CT mock with 4 assertions each (mount / validation / submit / a11y). Real adapter env-gates on `PW_CT_ENDPOINT`.
- `dogfood-visual-regression` — 10 UI scenes (5 primitives × light / dark) covering the 4 AC axes (baseline seed / capture / diff-on-intent-change / accept-restores-baseline). Real adapter env-gates on `CHROMATIC_PROJECT_TOKEN`.

Every dogfood app writes its fidelity report to `quality-report/fidelity-latest.md` (git-ignored) and to `docs/quality-reports/component/<name>.md` (git-tracked snapshot promoted per release).

## Release gate

The 11-axis contract is unchanged. Component providers keep their prefix routed to the 7-axis common branch (coverage 3 / fidelity / perf p95 / mutation / behavior tests). The AI-LLM 4 axes (cost / latency / token / accuracy) route only through providers whose name starts with `@kiwa-lab/ai-` (see `isAiLlmProvider` in `packages/quality-metrics/src/types.ts`) — component surfaces are excluded because there is no token pricing to measure.

The component thresholds match the common 7-axis defaults documented in v1.15 — line coverage ≥ 85%, branch ≥ 80%, function ≥ 90%, fidelity ratio ≥ 70%, perf p95 ≤ 100 ms for mount + play + a11y, mutation kill rate ≥ 60%, behavior test count ≥ 10.

## Upgrade checklist

- [ ] `pnpm add -D @kiwa-lab/component` at each package that wants Storybook / CT / Chromatic mocks
- [ ] Copy the fixture pattern from `examples/dogfood-storybook-design-system/src/components/design-system.ts` for framework-agnostic renderers
- [ ] Wire `runFidelityCheck` in your test setup to emit a report for the release gate
- [ ] Register your Storybook `.stories.ts` files with `registry.register(meta)` — CSF3 `meta.args` + `story.args` merge automatically
- [ ] Set `parameters.chromatic.viewports` when a story needs multiple viewports (mobile / desktop) captured
