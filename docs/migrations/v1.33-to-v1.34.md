# Migration guide — v1.33 → v1.34

v1.34 is **additive** — every `@kiwa/*` package public API that existed in v1.33 keeps its surface. Existing tests keep passing without touching a single line. The v1.34 changes are pure additions on the component + Next.js 縦深化 axis (RSC harness + streaming SSR + view transitions + form action advanced + server action advanced + partial prerendering + interception routes + parallel routes advanced).

The 5 things v1.34 adds are.

- `@kiwa/component` v0.3 — 4 advanced-semantics axes on top of the v0.2 6-semantics base (`startRscHarness` + `beginRscRender` + `enterSuspenseBoundary` + `streamHtmlChunk` + `completeRscRender` + `failRscRender` + `startStreamingSsr` + `markSuspensePending` + `captureErrorBoundary` + `startProgressiveHydration` + `completeSelectiveHydration` + `startViewTransitionSession` + `startElementTransition` + `finishElementTransition` + `startDocumentTransition` + `assertAnimation` + `startFormActionSession` + `markFormStatusPending` + `applyOptimisticUpdate` + `enableProgressiveEnhancement` + `resolveFormAction` + `rejectFormAction`) + a `collectFidelityCoverage()` describing the 3 target × 4 axis grid (12 rows) + a `KIWA_MODE=real` env-gate that lets the same assertions run against real Storybook 8 + Playwright CT + Chromatic under `KIWA_MODE=real`.
- `@kiwa/nextjs` v1.2 — 4 advanced-semantics axes on top of the v1.1 5-semantics base (`startServerActionAdvanced` + `submitFormAction` + `revalidateActionPath` + `revalidateActionTag` + `redirectAction` + `startPartialPrerendering` + `renderStaticShell` + `openDynamicHole` + `flushStreamingBoundary` + `completePartialPrerendering` + `startInterceptionRoutes` + `interceptCurrentSegment` + `interceptParentSegment` + `interceptRootCatchall` + `openInterceptedModal` + `startParallelRoutesAdvanced` + `renderDefaultSlot` + `renderLoadingState` + `captureParallelError` + `navigateSlot`) + a `collectFidelityCoverage()` describing the 3 target × 4 axis grid (12 rows).
- 3 dogfood app new (`examples/dogfood-nextjs-rsc-streaming-app` + `examples/dogfood-nextjs-server-action-app` + `examples/dogfood-storybook-8-mdx-app`) — each pins to real Next.js 15.4 + React 19.1 + Playwright + Chromium under `KIWA_MODE=real`, routes the fidelity-harness assertions through Playwright e2e, and keeps the mock-only path green for the fast inner loop. The v1.29 3-layer defensive structure (release-invariants + docs-e2e + release-smoke) auto-fires on merge.
- 3 new tutorials (67 RSC streaming SSR + 68 Server Action + optimistic + 69 Storybook 8 MDX) + 1 concept doc SSOT (`frontend-real-driver-testing.md` — 8 axis SSOT + 24 cell grid + browser-shaped env-gate pattern + browser-ready env-gate + target-specific `_BROWSER_READY` envs) + 1 migration guide (this file) + 1 snippet validation test (`packages/component/tests/docs-tutorial-v1.34.test.ts`) — **12-milestone snippet validation streak** (v1.23 → v1.34). All wired through the sidebar (`docs/.vitepress/config.mts`).
- No new release-gate axis — v1.34 stays at the v1.30 13-axis lineup (`a11y.tier` was the 13th). The 8 frontend axes are surface-level (they gate the component + nextjs package's own tests) but do not surface as a per-package release-gate axis, because the fidelity harness lives inside `@kiwa/component` + `@kiwa/nextjs` rather than at `@kiwa/quality-metrics`.

Use it in your own test.

```ts
import { describe, expect, it } from 'vitest';
import {
  beginRscRender,
  completeRscRender,
  enterSuspenseBoundary,
  startRscHarness,
  streamHtmlChunk,
} from '@kiwa/component';

describe('my article page — RSC streaming', () => {
  it('advances idle → rendering → suspended → streaming → completed', () => {
    const session = startRscHarness({
      target: 'playwright-ct',
      componentId: 'ArticlePage',
    });
    beginRscRender(session);
    enterSuspenseBoundary(session, '<div data-suspense="pending">loading</div>');
    streamHtmlChunk(session, '<article>Hello</article>');
    const done = completeRscRender(session);

    expect(done.state).toBe('completed');
    expect(done.neutralEvent).toBe('rsc.render_completed');
  });
});
```

The 3 target mocks (Storybook 8 / Playwright CT / Chromatic) all cover all 4 axes.

### `collectFidelityCoverage()` — 3 target × 4 axis grid (both packages)

The fidelity harness describes which target covers which axis and what neutral event + target dialect each axis emits, for both packages.

```ts
import { collectFidelityCoverage as componentCoverage } from '@kiwa/component';
import { collectFidelityCoverage as nextCoverage } from '@kiwa/nextjs';

const cComp = componentCoverage(['storybook8', 'playwright-ct', 'chromatic']);
console.log(cComp.rows.length); // 12 (3 target × 4 axis)
console.log(cComp.axes.length); // 4 (rsc-harness / streaming-ssr / view-transitions / form-action-advanced)

const cNext = nextCoverage(['app-router', 'pages-router', 'edge-runtime']);
console.log(cNext.rows.length); // 12 (3 target × 4 axis)
console.log(cNext.axes.length); // 4 (server-action-advanced / partial-prerendering / interception-routes / parallel-routes-advanced)

const appRouterAction = cNext.rows.find(
  (r) => r.provider === 'app-router' && r.axis === 'server-action-advanced',
);
console.log(appRouterAction?.neutralEvents);
// [ 'action.form_submitted', 'action.revalidate_path',
//   'action.revalidate_tag', 'action.redirected' ]
```

Every one of the 24 rows across both packages has a `neutralEvents` list (portable) and a `providerEvents` list (target-specific dialect). Tests iterating the grid assert on the neutral name for portability; tests wired to real target output can assert on the target-specific dialect. This is the data structure the release-gate report reads to render "the fidelity matrix" in the CI summary.

### `KIWA_MODE=real` — env-gated real driver run

The mock path stays the default. When `KIWA_MODE=real` is set, the harness assertions also try to run against the real driver, gated by the required env for that target.

- **RSC streaming dogfood** axes → `RSC_STREAMING_BROWSER_READY=1` (Playwright + Chromium browser session ready)
- **Server Action dogfood** axes → `SERVER_ACTION_BROWSER_READY=1` (Playwright + Chromium browser session ready)
- **Storybook 8 MDX dogfood** axes → `STORYBOOK_URL` + `STORYBOOK_MDX_READY=1` + `STORYBOOK_TEST_READY=1` (Storybook 8 server + MDX doc + interaction runner all ready)

Absent env means silently fall back to mock mode with a target-specific `_ENV_MISSING` reason (`KIWA_RSC_STREAMING_ENV_MISSING` / `KIWA_SERVER_ACTION_ENV_MISSING` / `STORYBOOK_MDX_REAL_ENV_MISSING`). This is the same env-gate contract the v1.22 real-driver testing tutorial (auth adapters + Keycloak), the v1.31 streaming real-driver concept doc, the v1.32 database real-driver concept doc, and the v1.33 payment real-driver concept doc all use.

## Snippet validation — 12 milestone streak

`packages/component/tests/docs-tutorial-v1.34.test.ts` — every code snippet in tutorials 67-69 is behavior-tested. If the component or nextjs API surface drifts, the snippet test fails before the tutorial hits a reader.

The streak is now 12 milestones (v1.23 → v1.34) — each milestone lands a `docs-tutorial-v{version}.test.ts` in its package of record with `describe('tutorial N — {topic}')` blocks that mirror the tutorial code. This is the pattern kiwa uses to keep the docs from drifting silently; 12 consecutive milestones with the pattern makes it the default rather than the exception.

## No release-gate axis change

v1.34 does not add a 14th release-gate axis. The 8 frontend axes gate the component + nextjs package's own tests (via `pnpm --filter @kiwa/component test` + `pnpm --filter @kiwa/nextjs test`) but do not surface as a per-package `quality-metrics` axis. The reason is that the fidelity harness is target-shape-specific — a package that does not use Storybook 8 / Playwright CT / Chromatic or App Router / Pages Router / Edge Runtime has nothing to assert on. When a future milestone adds a `frontend.fidelity` axis that describes "which frontend targets this package's tests hit," it will slot into the 13-axis release gate as the 14th; v1.34 keeps things simple.
