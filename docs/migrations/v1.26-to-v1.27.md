# Migration guide — v1.26 → v1.27

v1.27 is **additive** — every `@kiwa/*` package public API that existed in v1.26 keeps its surface. Existing tests keep passing without touching a single line. The v1.27 changes are pure additions on the mutation testing quality-gate axis.

The 5 things v1.27 adds are.

- `@kiwa/quality-metrics` v0.3 keeps every v0.2 export (`assembleReport` / `evaluateReleaseGate` / `mutationFromCounts` / `emitMarkdown` / every `*Metric` type alias). v0.3 is a **surface extension** — `DEFAULT_MUTATION_TIER_THRESHOLDS` + `resolveMutationTier` + `assertMutationTier` + `MutationTier` type + `ReleaseGateContext` type, all under `packages/quality-metrics/src/gate.ts`.
- Stryker rollout across **all 33 kiwa packages** — 22 packages already had a `stryker.config.mjs` from earlier milestones, 11 new packages were added in v1.27-1 through v1.27-3 (`@kiwa/nextjs` / `nuxt` / `sveltekit` / `remix` / `astro` / `solidstart` / `qwikcity` / `edge` / `solidjs` / `fresh` / `hono` — the framework layer that previously had no mutation baseline).
- 4-tier threshold SSOT — `docs/quality/mutation-thresholds.md` pins every package to Core 80 / Framework 70 / SaaS 65 / Test type 60 (kill-rate `high` column). Per-package baselines under `.mutation-baseline/*.json` record the actual kill-rate + surviving mutant list, and `scripts/check-mutation-gates.mjs` `PACKAGE_TIER` map is the runtime SSOT that mirrors the doc.
- 12-axis release gate — `evaluateReleaseGate(report, thresholdOverrides, { mutationTier })` opts a report into a 12th axis (`mutation.tier`) that fails when kill-rate drops below the tier floor. The legacy 7 / 11 axis paths stay unchanged when `mutationTier` is omitted.
- 2 new tutorials (50 mutation testing baseline walkthrough / 51 mutation baseline migration methodology), 1 concept doc SSOT (`mutation-testing-ssot.md` — kill rate SSOT + 4-tier threshold rationale + baseline persistence + regression detection + 3-layer harness), 1 migration guide (this file), 1 tutorial snippet validation test (`packages/quality-metrics/tests/docs-tutorial-v1.27.test.ts`). All wired through the sidebar (`docs/.vitepress/config.mts`).

## What breaks (nothing)

Nothing. The v1.27 changes are pure additions.

- `@kiwa/quality-metrics` v0.2 surface (`assembleReport` + `evaluateReleaseGate` + every `*Metric` type alias + `emitMarkdown` + `diffReports`) — unchanged. v0.3 layers `DEFAULT_MUTATION_TIER_THRESHOLDS` + `resolveMutationTier` + `assertMutationTier` + `MutationTier` type + `ReleaseGateContext` type without touching the v0.2 export names.
- `evaluateReleaseGate` signature — the third argument (`context`) is optional. Calls that pass only the report (or the report + overrides) continue to run the legacy 7-axis (non-AI-LLM) or 11-axis (AI-LLM) path. The 12th axis is opt-in.
- Every prior `@kiwa/*` package (core / api / data / cli-test / observability / cli / nextjs / nuxt / sveltekit / remix / astro / solidstart / qwikcity / edge / solidjs / fresh / hono / auth / ai-llm / payment / queue / cache / streaming / realtime / mcp / agent / search / orm / dapp / ui / a11y / visual / component / e2e / perf-harness / quality-metrics) — public API surface untouched. Existing tests keep passing.
- Every prior tutorial 01-49, migration guide v1.9→v1.26, concept doc — unchanged. v1.27 only appends tutorial 50-51 + concept `mutation-testing-ssot.md` + migration `v1.26-to-v1.27.md`.
- Every prior dogfood app (v1.26 db-advanced apps, v1.25 perf-sweep suites, v1.24 edge apps, v1.23 payment apps, v1.22 auth apps, v1.20 streaming apps, v1.19 framework apps, etc.) — untouched. The 3 v1.26 dogfood apps (`dogfood-postgres-cdc-outbox-app`, `dogfood-mysql-rls-tenant-app`, `dogfood-vector-search-app`) opt into the 12-axis path via `runFidelityHarness({ mutationTier: 'saas' })` but the mock-only test suites still pass without the opt-in.

## What's new (opt in)

### `@kiwa/quality-metrics` v0.3 — 4-tier mutation SSOT + 12th release-gate axis

The v0.2 `assembleReport` + `evaluateReleaseGate` + `mutationFromCounts` + every `*Metric` type alias stay the first-line contract. v0.3 layers 3 new runtime helpers + 2 new type aliases + 1 optional `context` parameter on `evaluateReleaseGate`, all under `packages/quality-metrics/src/gate.ts`.

The 3 new runtime helpers.

- **`DEFAULT_MUTATION_TIER_THRESHOLDS`** — the 4-tier SSOT table (`core: 80 / framework: 70 / saas: 65 / test-type: 60`), a `Readonly<Record<MutationTier, number>>` that mirrors the tier `high` column of `docs/quality/mutation-thresholds.md`.
- **`resolveMutationTier(label)`** — normalises the verbal tier label (`Core` / `Framework` / `SaaS` / `Test type`) written in `.mutation-baseline/*.json` into the machine `MutationTier` enum (`core` / `framework` / `saas` / `test-type`). Case-insensitive, trim-tolerant, throws on unknown labels.
- **`assertMutationTier({ metric, tier, threshold? })`** — asserts `metric.killRate >= threshold ?? DEFAULT_MUTATION_TIER_THRESHOLDS[tier]`. Zero-mutation metrics throw (`no mutation signal`) so an empty test suite never silently passes.

The 2 new type aliases.

- **`MutationTier`** — `'core' | 'framework' | 'saas' | 'test-type'`. The machine enum resolved by `resolveMutationTier`.
- **`ReleaseGateContext`** — `{ mutationTier?: MutationTier; mutationTierThreshold?: number }`. Passed as the optional third argument of `evaluateReleaseGate`.

`evaluateReleaseGate` gains an optional third parameter:

```ts
evaluateReleaseGate(report, thresholdOverrides, {
  mutationTier: 'saas',          // required to enable the 12th axis
  mutationTierThreshold: 60,     // optional looser override
});
```

When `mutationTier` is omitted the verdict stays at 7 (non-AI-LLM) or 11 (AI-LLM) axes for backward compatibility. When present the verdict count grows by 1 (`axesEvaluated` becomes 8 or 12) and any threshold miss surfaces as a `mutation.tier` blocker alongside the legacy `mutation.killRate` axis (both axes coexist so v1.11 consumers keep the old shape).

Concrete usage — the pattern every 12-axis caller follows.

```ts
import {
  assembleReport,
  coverageFromV8Summary,
  evaluateReleaseGate,
  fidelityFromMethodCounts,
  mutationFromCounts,
  perfFromSamples,
  resolveMutationTier,
  testCountFromCategories,
} from '@kiwa/quality-metrics';

const report = assembleReport({
  provider: '@kiwa/auth',
  version: '0.5.0',
  coverage: coverageFromV8Summary(covSummary.total),
  testCount: testCountFromCategories({ behavior: 236, integration: 8, e2e: 0 }),
  fidelity: fidelityFromMethodCounts({ mockCoveredMethods: 42, realTotalMethods: 60 }),
  perf: perfFromSamples(latencyMs),
  mutation: mutationFromCounts({ mutations: 167, killed: 115 }),
});

const verdict = evaluateReleaseGate(report, {}, {
  mutationTier: resolveMutationTier('Framework'),
  mutationTierThreshold: 65, // .mutation-baseline/auth.json override
});
if (!verdict.passed) {
  console.error('blockers:', verdict.blockers);
  process.exit(1);
}
```

The full 4-tier catalogue + package-by-package assignment lives in [`docs/quality/mutation-thresholds.md`](../quality/mutation-thresholds). The SSOT and the runtime helpers agree by construction — the same table drives Stryker configs, baseline JSON, `PACKAGE_TIER` in `scripts/check-mutation-gates.mjs`, and `DEFAULT_MUTATION_TIER_THRESHOLDS` in `@kiwa/quality-metrics`.

## Upgrade path

If you consume `@kiwa/quality-metrics` directly.

```bash
pnpm add -D @kiwa/quality-metrics@^0.3
```

Existing v0.2 imports keep passing. The v0.3 upgrade adds new exports (`DEFAULT_MUTATION_TIER_THRESHOLDS` + `resolveMutationTier` + `assertMutationTier` + `MutationTier` + `ReleaseGateContext`); no prior export renames or removals.

```ts
// v0.2 — still works, no changes required
import {
  assembleReport,
  evaluateReleaseGate,
  mutationFromCounts,
} from '@kiwa/quality-metrics';

// v0.3 — new mutation-tier helpers (opt-in)
import {
  DEFAULT_MUTATION_TIER_THRESHOLDS,
  assertMutationTier,
  resolveMutationTier,
  type MutationTier,
  type ReleaseGateContext,
} from '@kiwa/quality-metrics';
```

If you fork the kiwa monorepo and want to onboard a new package into the mutation sweep, follow the tutorial 50-51 walkthrough.

## Release gate

`evaluateReleaseGate` axis surface grows from 11 to **12 axes** in v1.27, but the 12th axis is **opt-in** via the third `context.mutationTier` argument. Consumers that pass no `mutationTier` continue to run the legacy 7 / 11 axis path — the SSOT stays backward compatible with every v1.11 – v1.26 consumer.

| Axis | Kind | Introduced | Enabled by |
|---|---|---|---|
| coverage — line / branch / function (3 axes) | floor | v1.11 | always |
| test count — behavior | floor | v1.11 | always |
| fidelity — ratio | floor | v1.11 | always |
| perf — p95 ms | ceiling | v1.11 | always |
| mutation — killRate (legacy) | floor | v1.11 | always |
| cost / latency / token / accuracy (4 axes) | mixed | v1.12 | `provider` starts `@kiwa/ai-*` |
| mutation — tier | floor | v1.27-4 | `context.mutationTier` opt-in |

The `mutation.tier` axis surfaces **alongside** the legacy `mutation.killRate` axis when both fail — v1.11 consumers keep the old blocker shape, and 12-axis consumers additionally see the tier-aware bar.
