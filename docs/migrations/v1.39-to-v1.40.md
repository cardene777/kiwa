### 16-axis combined fidelity harness

`collectFidelityCoverage()` walks the full 4 provider × 16 axis = 64-row grid in one call.

```ts
import { collectFidelityCoverage } from '@kiwa-lab/ai-llm';

const cov = collectFidelityCoverage();
console.log(cov.rows.length); // 64
console.log(cov.rows.every((r) => r.implemented)); // true
```

The rows are ordered by axis first (v0.4 axes 1-8 first, v0.5 axes 9-16 second) then by provider (`anthropic` / `openai` / `vercel-ai` / `langchain`). A CI job can pin the row count as a regression guard so a mis-configured axis registration is caught before the release cuts.

## Recommended migration path

1. Bump `@kiwa-lab/ai-llm` from `^0.4` to `^0.5` in your `package.json`.
2. Existing v0.4 imports keep working — no code change required.
3. Opt-in to a v0.5 axis by importing the new function (e.g. `startMaoSession`) and adding a corresponding test.
4. Wire the real-driver path by setting `KIWA_MODE=real` + the axis-specific backend URL (`KIWA_LANGGRAPH_URL` / `KIWA_CI_SANDBOX_URL` / `KIWA_OPS_REGISTRY_URL`) in the CI job that runs the dogfood app.
5. Optionally add `collectFidelityCoverage()` as a regression guard on the 4 × 16 = 64 grid so a mis-configured axis registration is caught before the next release cuts.

The 16-axis grid is a strict superset of the 8-axis v0.4 grid — a downstream consumer that was already asserting `rows.every(r => r.implemented)` on 32 rows now asserts on 64 rows without changing the assertion shape.
