### 25-axis combined fidelity harness

The v0.5 package extends the existing `collectFidelityCoverage()` grid to cover the full 3 provider × 25 axis = 75-row grid in one call.

```ts
import { collectFidelityCoverage } from '@kiwa/payment';

const cov = collectFidelityCoverage();
console.log(cov.rows.length); // 75
console.log(cov.rows.every((r) => r.implemented)); // true
```

The rows are ordered by axis first (v0.3 axes 1-9 first, v0.4 axes 10-17 second, v0.5 axes 18-25 third) then by provider (`stripe` / `paddle` / `lemonsqueezy`). A CI job can pin the row count as a regression guard so a mis-configured axis registration is caught before the release cuts.

## Recommended migration path

1. Bump `@kiwa/payment` from `^0.4` to `^0.5` in your `package.json`.
2. Existing v0.4 imports keep working — no code change required.
3. Opt-in to a v0.5 axis by importing the new function (e.g. `openAccount` for embedded-finance) and adding a corresponding test.
4. Wire the real-driver path by setting `KIWA_MODE=real` + the axis-specific backend URL (`KIWA_STRIPE_TREASURY_URL` / `KIWA_KLARNA_URL` / `KIWA_CRYPTO_URL` / `KIWA_FX_URL`) in the CI job that runs the dogfood app.
5. Optionally add `collectFidelityCoverage()` as a regression guard on the 3 × 25 = 75 grid so a mis-configured axis registration is caught before the next release cuts.

The 25-axis grid is a strict superset of the 17-axis v0.4 grid — a downstream consumer that was already asserting `rows.every(r => r.implemented)` on 51 rows now asserts on 75 rows without changing the assertion shape.
