Migration guide — v1.22 → v1.23 ​

v1.23 is additive — every @kiwa-test/* package public API that existed in v1.22 keeps its surface. Existing tests keep passing without touching a single line.

The 5 things v1.23 adds are.

  • @kiwa-test/payment v0.3 layers 9 axes of advanced billing semantics on top of the v0.2 webhook mock (dunning / retry / 3DS v2 / SCA / PSD2 mandate / subscription lifecycle / invoice lifecycle / VAT-GST-sales-tax / chargeback dispute). Provider-neutral state machines + strict transition guards land in packages/payment/src/semantics/*.
  • 3 dogfood merchant apps — dogfood-stripe-billing-app (Next.js 15 + checkout + webhook + subscription + invoice + 3DS + dunning, 35 vitest), dogfood-paddle-merchant-app (Nuxt 3 + Paddle Billing v2 + inline checkout + subscription tier + VAT/GST auto-calc, 40 vitest), dogfood-lemon-squeezy-app (SvelteKit + hosted checkout + license key issue+activate+revoke + refund + chargeback, 74 vitest). All three share the same KIWA_MODE=mock|real-optional|real switch v1.22 established.
  • 3 new tutorials (39 Stripe advanced billing + 40 Paddle merchant-of-record + 41 Lemon Squeezy license flow), 1 concept doc SSOT (billing-semantics.md — 9-axis reference), 1 migration guide (this file). All wired through the sidebar.
  • 1 tutorial snippet validation test (packages/payment/tests/docs-tutorial-v1.23.test.ts) that re-runs every code snippet in tutorials 39-41 against the real @kiwa-test/payment API — same pattern as docs-tutorial-v1.21.test.ts and docs-tutorial-v1.22.test.ts.
  • Sidebar navigation (docs/.vitepress/config.mts) — new "Payment 深化 (v1.23)" section under Tutorials, billing-semantics.md under Concepts, v1.22 → v1.23 under Migrations.

What breaks (nothing) ​

Nothing. The v1.23 changes are pure additions.

  • @kiwa-test/payment v0.2 surface (createStripeMock / createPaddleMock / createLemonSqueezyMock / signWebhook / emit / verify / checkoutCompleted / subscriptionCreated / paymentFailed / refunded) — unchanged. v0.3 adds the semantics/* module tree alongside the existing surface. Every prior signature keeps its shape.
  • Every prior @kiwa-test/* package (auth / streaming / solidjs / fresh / hono / observability v2 / component / realtime / ai-llm / mcp / agent / perf-harness / quality-metrics / search / dapp) — untouched.
  • evaluateReleaseGate — same 11-axis contract as v1.17-v1.22. v1.23 introduces no new release-gate axes.
  • Every prior tutorial 01-38, migration guide v1.9→v1.22, concept doc — unchanged. v1.23 only appends tutorial 39-41 + concept billing-semantics.md + migration v1.22-to-v1.23.md.
  • Every prior dogfood app (v1.22 auth apps, v1.20 streaming apps, v1.19 framework apps, etc.) — untouched. v1.23 adds 3 new dogfood merchant apps alongside; nothing is removed or renamed.

What's new (opt in) ​

@kiwa-test/payment v0.3 — 9-axis advanced billing semantics ​

The v0.2 webhook mock stays the first-line contract. v0.3 layers 9 axes of billing state on top so tests exercise the full envelope real providers converge on. Every axis operates on the same PaymentAdapter interface createStripeMock / createPaddleMock / createLemonSqueezyMock return — swap the adapter and the tests re-run against a different provider without touching the axis bodies.

The 9 axes are.

  • Dunning — payment retry sequence for failed invoices. State machine active → in-grace-period → recovered or exhausted. Default maxAttempts: 4, retryIntervalMs: 3 days, gracePeriodMs: 1 day matches Stripe Smart Retries.
  • Retry — general-purpose exponential-backoff retry independent of dunning. Default maxAttempts: 5 with jitter. Used for webhook delivery, idempotent API retries, 3DS polling.
  • 3D Secure v2 — EMVCo 3DS 2.2 challenge flow. fingerprint → challenge-pending → completed, or fingerprint → frictionless. Accepts all 6 transStatus codes (Y / N / A / C / U / R).
  • SCA (PSD2) — Strong Customer Authentication with 6 exemption categories (low-value, low-risk, trusted beneficiary, secure corporate payment, recurring, MIT).
  • PSD2 mandate — SEPA direct debit / Bacs / ACH mandate lifecycle. pending → active → revoked with consent-timestamp recording.
  • Subscription lifecycle — 5-state envelope (active → upgraded / downgraded / paused / canceled, paused → resumed, canceled → reactivated) with strict transition guards.
  • Invoice lifecycle — draft → open → (paid | void | uncollectible) + credit-note support.
  • Tax (VAT / GST / sales tax) — merchant-of-record auto-calc across ~180 jurisdictions with reverse charge for B2B EU customers with a valid VAT ID.
  • Chargeback dispute — card-network dispute lifecycle opened → evidence-submitted → won or lost with provider-specific fee assessment.

Concrete usage.

ts
// v0.3 dunning axis — Stripe Smart Retries envelope
import { createStripeMock, startDunning, dunningAttempt, finalizeDunning } from '@kiwa-test/payment';

const adapter = createStripeMock({ webhookSecret: 'whsec_test', apiKey: 'sk_test_123' });
const session = startDunning({
  invoiceId: 'in_1',
  amountCents: 1999,
  customerId: 'cus_1',
  currency: 'usd',
});

for (let i = 0; i < 4; i++) {
  await dunningAttempt(adapter, session);
}
// session.state === 'in-grace-period' after 4 attempts.

const { session: final } = await finalizeDunning(adapter, session, { succeed: false });
// final.state === 'exhausted', 'invoice.marked_uncollectible' emitted.

The full 9-axis catalogue lives in docs/concepts/billing-semantics.md.

3 dogfood merchant apps ​

  • examples/dogfood-stripe-billing-app (Next.js 15 App Router) — checkout / webhook / subscription / invoice route handlers wired through the 9-axis semantics. 35 vitest cases spanning checkout-e2e.spec.ts (19 tests), dunning-e2e.spec.ts (8), 3ds-e2e.spec.ts (8). KIWA_MODE=real swaps to real Stripe API with STRIPE_KEY + STRIPE_WEBHOOK_SECRET + KIWA_STRIPE_REAL_READY=1.
  • examples/dogfood-paddle-merchant-app (Nuxt 3) — Paddle Billing v2 merchant-of-record. Inline checkout + subscription tier upgrade + VAT/GST/sales-tax auto-calc. 40 vitest cases across checkout-tier-e2e.spec.ts (23) + tax-vat-e2e.spec.ts (17). KIWA_MODE=real requires PADDLE_KEY + PADDLE_NOTIFICATION_SECRET + KIWA_PADDLE_REAL_READY=1.
  • examples/dogfood-lemon-squeezy-app (SvelteKit) — hosted checkout + license key issue+activate+revoke + refund full+partial + chargeback dispute lifecycle. 74 vitest cases across checkout-license-e2e.spec.ts + refund-chargeback-e2e.spec.ts. KIWA_MODE=real requires LEMONSQUEEZY_KEY + LEMONSQUEEZY_SIGNING_SECRET + KIWA_LEMONSQUEEZY_REAL_READY=1.

All three follow the v1.22-established KIWA_MODE=mock (default) / KIWA_MODE=real-optional (try real, fall back) / KIWA_MODE=real (fail hard) contract.

Tutorial snippet validation ​

packages/payment/tests/docs-tutorial-v1.23.test.ts re-runs every code snippet in tutorials 39-41 against the real @kiwa-test/payment API. If a tutorial snippet drifts from the shipped API (rename, signature change, deleted export), the vitest run fails — same guard v1.17 / v1.19 / v1.20 / v1.21 / v1.22 established for their tutorials.

Upgrade path ​

Bump the dependency and start using the axes.

bash
pnpm add -D @kiwa-test/payment@^0.3

Existing v0.2 tests keep passing. New tests can import the 9-axis semantics from the same package.

ts
// v0.2 — still works
import { createStripeMock, checkoutCompleted } from '@kiwa-test/payment';

// v0.3 — new axes
import {
  startDunning, dunningAttempt, finalizeDunning,
  createSubscription, changePlan,
  startThreeDs, threeDsRequestChallenge, threeDsFrictionless,
  calculateTax,
  openChargeback, submitEvidence, resolveChargeback,
} from '@kiwa-test/payment';

Release gate ​

evaluateReleaseGate axis surface is unchanged at v1.23 — same 11 axes as v1.17-v1.22. The 3 new dogfood merchant apps emit fidelity-report payloads that feed the existing gate; no new axis is added.
