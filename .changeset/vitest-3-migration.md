`peerDependencies.vitest` の対応範囲を `^2` から `^3.2.6` に上げる。

vitest に CRITICAL の勧告 (`GHSA-5xrq-8626-4rwp`、Vitest UI サーバー経由の任意ファイル読み取りと実行) があり、修正版は `>=3.2.6` である。
2.1.9 は 2 系の最終版なので、2 系のままでは解消できない。

下限を `^3` ではなく `^3.2.6` にしているのは、`^3` が脆弱な 3.0.0 から 3.2.5 も許容するためである。
公開している範囲なので、利用者が 3.1 系を使っていても適合と判定されてしまう。

**利用者への影響。**
`@kiwa-lab/auth` を vitest 2 系または 3.2.5 以前のプロジェクトで使っている場合、peer の解決が外れる。
3.2.6 以上へ上げてから追随してほしい。

repo 内の 226 個の package.json も同時に上げた。

**確認した範囲。**
`packages/*` の 71 package で通常テストの通過数を移行前後で突き合わせ、差が無いことを確認している (11,731 件)。
これに加えて、今回上げた網羅率プロバイダを読み込む経路 (`test:cov`) と、別 API を使う変異試験の経路 (`stryker run --dryRunOnly`) も代表 package で実際に走らせて通ることを確認した。

通常テストで使う API には非互換箇所が無かった。
この repo は `vitest run` の素の使い方しかしておらず、2 系から 3 系の破壊的変更 (環境指定の解決経路、モック API、設定の再編、既定値) に触れていない。
