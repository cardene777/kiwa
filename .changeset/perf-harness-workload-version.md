op が測っている作業内容の版を宣言できるようにする。

`PerfOpSpec.workloadVersion` に数を書くと、版が違う記録どうしは比較せず入れ替える。
`MeasureReference.implVersion` が基準 op に対して持っている契約と同じ形。

**なぜ必要か。**

回帰判定は「実装が遅くなった」 を見るためのものだが、op が測っている作業内容そのものを変えた場合も同じ形で現れる。
どちらも「anchor から一方向に大きくずれ続ける」 になり、harness からは区別が付かない。

`hasSameMeasurementConfig` は `iterations` と `warmup` を比べるが、作業内容は `fn` の中にあってどちらも動かさない。
記録に痕跡が残らないため、宣言しない限り検知できない。

実測 = `vector` の `queryNearestTop5` は #1730 で母集団を 20 → 200 件に変えた。
`queryNearest` は全件走査 + sort なので作業量が 10 倍になり、比が anchor の 6.2 倍に跳ねる。
5 パス測って +464% 〜 +546% の一方向、判定は毎回 `regressed`、履歴は 1 件も積まれない状態だった。

版を宣言すると anchor が 0.045 → 0.260 に入れ替わり、4 パスとも判定が付かず履歴が 1→2→3→4 と積み上がる。

**判定の規則。**

「無い」 も 1 つの値として単純に等しいかを見る。

| 組 | 挙動 |
|---|---|
| 両方とも宣言なし | 比較する (既存の op はここ) |
| 両方とも同じ版 | 比較する |
| 版が違う | 比較せず記録を入れ替える |
| 片方だけが宣言 | 比較せず記録を入れ替える (宣言し始めた実行で 1 度だけ) |

「片方に無ければ同じとみなす」 は成立しない。
既存の記録は全て版を持たないので、そう書くと宣言しても記録が入れ替わらず、入れ替わらないので版が baseline に載らず、載らないので次も比較が成立する = 宣言が永久に効かない。
実装して実測で確認した。

**版として受理する値。**

1 以上の安全な整数だけ。宣言の時点で検証し、成立しない値は測る前に例外にする。

`NaN` は自分自身と等しくならないので記録が毎回入れ替わり、その op は永久に比較されない。
読み取り側で弾いても次の実行で同じ値が書かれるため seed し直しが続く。
小数は `1.0` と `1` の区別が付かず、0 と負は「宣言していない」 との区別が付かず、`2^53` を超えると 1 上げても同値になる。

読み取り側の検証は緩いまま残す。
`isResultMap` が `every` で判定するため、読み取り側を同じ厳しさにすると 1 record の不正で baseline file 全体が破棄され、無関係な全 op の履歴と anchor が消える。

**適用範囲。**

serial と concurrent の両方の記録に載り、mock (`runPerf3Layer`) と live (`runPerf3LayerLive`) の両経路で効く。

**既存の op への影響。**

版を宣言しない op の挙動は変わらない。
両側とも「無い」 ので比較が成立し、記録も入れ替わらない。
