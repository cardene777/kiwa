Fidelity — dogfood-vercel-ai-rag (v1.12-4) ​

Real-vs-mock behavioural fidelity for the Vercel AI SDK + LangChain + retriever + embedding + RAG pipeline dogfood, produced by examples/dogfood-vercel-ai-rag/tests/emit-fidelity-report.test.ts. Feeds @kiwa-test/quality-metrics 11-axis release gate.

Baseline (real mode skipped — no OPENAI_API_KEY + RAG_VECTOR_STORE_URL + RAG_VECTOR_STORE_API_KEY) ​

When the harness runs without full real-mode env, the real adapter emits RAG_ENV_MISSING for every op. Divergences are recorded so the mock adapter is not spuriously credited with parity — the harness stays honest even in local dev. Accuracy is the mean Jaccard similarity between the mock answers and the ground-truth strings in the 20-QA-pair set. In real-mode-skipped mode the ground truth is a short paraphrase per question (see RAG_QA_PAIRS in src/flows/rag-flows.ts) while the mock echoes the full seed doc — Jaccard token overlap is inherently low even though the answer is well-grounded, so the fail is by design and signals that fidelity is unverified without a live key. Wiring OPENAI_API_KEY + RAG_VECTOR_STORE_URL + RAG_VECTOR_STORE_API_KEY and running against gpt-4o-mini + text-embedding-3-small + Pinecone promotes the report to the real baseline.

Ops under measurement ​

Five provider-neutral ops on RagAdapter.

  • ingest — chunk + embed + upsert seed docs into the vector store (mock = in-memory, real = Pinecone)
  • embed — Task 3.1 — deterministic hashing (mock) or real OpenAI embeddings (text-embedding-3-small)
  • retrieve — Task 3.2 — top-k cosine search returns the retrieved chunks + doc ids
  • answer — Task 3.3 — full RAG turn (retrieval + LLM generation with context injection)
  • answerStream — RAG turn with streamed generation (Vercel AI SDK streamText-shape)

Per-question mock response bank (design SSOT) ​

The shared MockEngine inside @kiwa-test/ai-llm resolves prompts through a response bank keyed by the last role: 'user' message. RAG builds a new user prompt per question (context block + question), so the mock adapter constructs a fresh createVercelAiMock instance per answer whose response bank is seeded from the retrieved hits — the mock's answers stay grounded in the retrieved context (mirroring real LLM behaviour) without changes to the shared engine. Metric accumulation is hand-rolled across the fresh clients so the mock's cost / token / latency totals stay comparable with the real adapter's.

The createLangchainMock instance is exercised once during ingest() for surface coverage — a single langchainInvoke trace ensures the LangChain mock participates in the fidelity harness even though the primary answer path uses the Vercel mock. Because the test-real adapter does not touch the LangChain surface, langchainInvoke shows up as the sole BEHAVIORAL_DIVERGENCE in the baseline report — this is intentional and documents that the LangChain surface is a mock-only side channel by design.

Notes ​

Provider prefix @kiwa-test/ai-llm/ triggers the 11-axis branch of evaluateReleaseGate (packages/quality-metrics/src/gate.ts — the 4 AI-LLM axes cost / latency / token / accuracy are added on top of the shared 7). Task-specific fidelity metrics (embedding cosine similarity, retrieval F1, answer Jaccard) are attached to the report notes field so the AC targets from Issue #698 are inspectable directly without a bespoke schema change.
